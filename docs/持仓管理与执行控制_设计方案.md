# 持仓管理与执行控制设计方案

> 版本：v1（2026-09-15）　配套：`docs/统一交易栈_设计方案.md`（v3）
> 定位：策略输出"目标持仓"之后、订单进入撮合之前的一切。与风控分工——**风控管"不许做什么"（红线拦截），本模块管"怎么做"（仓位/退出/下单方式）**，两者独立可测、互不依赖。
> 对标：顶级量化机构（幻方/DeepSeek 母公司的工程标准）的持仓纪律与执行质量体系。

---

## 一、链上位置

```
策略（选股+目标组合）→ ┌ 持仓管理：仓位决策 + 退出规则 + 组合约束 ┐ → ┌ 执行控制：算法选择+拆单+追价+调度 ┐ → OrderRouter → 撮合
                       └ 产出：交易清单(买卖+数量+执行参数)        ┘    └ 产出：子单序列 + 执行报告          ┘
```

## 二、持仓控制

### 2.1 持仓生命周期状态机

```
候选 → 建仓中 → 持有 ─┬→ 加仓（信号增强/分批建仓后段）
                      ├→ 减仓（规则触发/风控降仓）
                      → 清仓（退出规则）→ 复盘归档
```

每个状态的动作、允许操作、超时处理（如"建仓中"超过 N 日未完成 → 放弃或转市价）在配置中声明。

### 2.2 仓位决策（怎么定大小）

| 方式 | 规则 | 用途 |
|---|---|---|
| 信号分档 | rank_pct 分位 → 目标仓位档（如 top1% 15%、top5% 10%、其余 5%） | 默认 |
| 波动率目标 | 仓位 ∝ 目标波动 / 个股波动 | 可选 |
| Kelly 分数 | (胜率×盈亏比−败率)/盈亏比 × 折扣系数（借鉴 KHunter，折扣防高估） | 可选，需有胜率统计 |
| 风险预算 | 按行业/因子暴露分配 | 进阶（接组合优化） |
| **regime 系数** | 全部仓位 × 市场状态系数（1.0/0.5/0.3/0） | 全局约束 |

单票/行业/总仓上限由风控 L1 执行，**参数由本模块提供**（一处配置，两处消费）。

### 2.3 退出规则引擎（规则目录，按优先级）

| 优先级 | 退出类型 | 触发 | 执行方式 |
|---|---|---|---|
| 1 | **风控强制** | HALT / 大盘破位 / 账户限额 | 全撤 + 清仓（紧急执行算法） |
| 2 | **事件退出** | 重大负面新闻/公告（veto 级） | 立即清仓（可配置"仅减半"） |
| 3 | 硬止损 | 亏损 ≥ X%（默认 -5%，跌停不可卖时排队） | 紧急 |
| 4 | 移动止损 | 从最高价回撤 ≥ Y%（止盈保护，替代固定止盈） | 正常 |
| 5 | **信号消失** | rank 掉出入场线 / 所属行业 Top1 跌破入场线（行业消失=清仓，既有口径） | 正常（可分批） |
| 6 | 时间止损 | 持有 ≥ max_hold_days（**与模型 horizon 对齐**） | 正常 |
| 7 | 定期再平衡 | 日/周调仓窗口 | 批量执行 |

规则实现为**独立小函数 + 配置**（每条可开关、可参数化、可单测）；触发时记录"触发依据快照"（当时价格/分数/事件），进复盘。

### 2.4 组合层面控制

- 集中度（前 N 持仓占比）、行业暴露、持仓相关性上限（防"一组高相关票等于单吊"）
- 现金管理（最低现金比例、打新/申购预留）
- 再平衡：目标 vs 实际漂移 > 阈值时生成调仓清单

### 2.5 持仓监控（交易台"持仓"面板）

每持仓一行：盈亏、**离每条退出线的距离**（离止损还有几个点）、信号变化（rank 趋势）、事件标记、所属规则状态——让"持仓怎么了"一眼可见（对治现状"持仓页只有数字没有判断"）。

## 三、撮合与执行控制

### 3.1 执行算法目录（按场景选择）

| 场景 | 算法 | 参数 | QMT 通道可行性 |
|---|---|---|---|
| 常规调仓建仓 | 盘口限价追价 / 短 TWAP 分批（如 3-5 笔，09:35–10:00） | 每笔参与率 ≤10% | ✅ 直接做 |
| 大额建仓/减仓 | POV（参与率跟随）拆单 | 参与率 5-10%、价格保护 | ✅ 拆单逻辑自建 |
| 紧急（止损/风控） | 市价 / 涨跌停价快速成交 | 逐笔立即、不拆分 | ✅（注意跌停流动性） |
| 集合竞价 | 开盘价委托（09:25 前）| 可撤单窗口管理 | ✅ |
| 涨跌停排队 | 排板策略（是否挂涨停价排队） | 策略级开关 | ✅ |
| 未来（L2/tick） | 盘口跟随/冰山单 | TickCore 阶段 | P7+ |

**诚实边界**：A 股散户通道无原生算法单（TWAP/VWAP 需自建拆单循环）；机构算法单（XTP/OES 那类）不适用我们的 QMT 桥——**执行算法 = 我们自己拆单 + 调度**，不要指望柜台。

### 3.2 撮合控制（系统侧）

- **OrderRouter 调度**：优先级队列（风控平仓 > 止损 > 策略调仓 > 普通）；单账户并发上限；撤补单节奏（追价次数与间隔上限，防"追不上反复撤"烧掉撤单率）
- **部分成交处理**：剩余量继续/放弃/降价 策略化；超时撤单（复用现有买单撤单观察窗 300s 口径）
- **失败路径**：拒单/废单原因分类（资金/持仓/涨跌停/风控/柜台），自动重试仅限幂等场景
- **三环境同构**：模拟/影子/实盘走同一调度器（模拟是执行算法的免费试验场）

### 3.3 执行质量度量（机构级标准）

| 指标 | 定义 | 用途 |
|---|---|---|
| **Implementation Shortfall** | 决策价（生成信号时价）→ 实际成交价 的差额 | 执行质量总分 |
| 到达价滑点 | 下单时刻价 → 成交价 | 剔除决策延迟后纯执行成本 |
| VWAP 基准滑点 | 成交价 vs 当日 VWAP | 与市场基准比较 |
| 成交率 / 参与率 | 成交量/委托量、占市场成交量比 | 容量与冲击监控 |
| 撤单率 | 撤单/委托 | 合规（接风控 L3） |
| **模拟-实盘成交偏差** | 同单模拟撮合价 vs 实盘成交价 | **"模拟接近实盘"的度量**（接评估体系） |

每日执行报告（每单下钻 + 汇总分布），并入评估打分体系的"执行"维度。

## 四、对标顶级量化机构的工程标准（幻方 / DeepSeek 母公司）

幻方的"专业"不在某个模型，而在**工业化**：研究流水线化、因子工厂、全自动交易闭环、算力调度、纪律化的风控。逐项映射到本方案：

| 幻方式的工业化能力 | 本方案的落点 | 现状差距 |
|---|---|---|
| 因子工厂（自动化挖掘→检验→入库） | RD-Agent + factor_quality + 特征注册表 | 🟡 已有雏形 |
| 全流程自动化（数据→信号→交易→复盘无人值守） | 每日闭环 + P4（自动化） | 🟡 半自动 |
| 算力调度（训练/回测弹性） | AutoDL 远程训练 + R1/R2/R3 分层 |  已有 |
| 严格风控与合规 | 七级风控体系 | 🔴 待建（P0 起） |
| 执行质量体系 | 本节 §3.3 |  缺 |
| 研究与生产同一套口径 | 粒度对齐五规则 | 🔴 违例待清 |

**能对标与不能对标**：算力规模与研究团队规模不对标（诚实）；**工程纪律、自动化程度、口径一致性、风控完备性**完全可对标——这四项恰是本方案的主体。
