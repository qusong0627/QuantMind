# LLM 与 Agent 接入设计方案

> 版本：v1（2026-09-15）　配套：`docs/统一交易栈_设计方案.md`（v3）
> 背景：后期引入大模型/Agent 能力。已有资产：TradingAgents（7 分析师+辩论）、RD-Agent 因子挖掘、AI-IDE 对话生成策略、FinBERT 中文金融情感、litellm 网关、QwenPaw。
> 立场：LLM/Agent 是**新的信号源与生产力工具**，不是新的交易链路——一切接入必须挂到既有契约上。

---

## 一、LLM 在量化栈中的四类角色

| # | 角色 | 位置 | 例子 | 现有资产 |
|---|---|---|---|---|
| 1 | **研究助手**（离线） | L1/L2/L4 | 因子挖掘、策略生成、报告 | RD-Agent ✅、AI-IDE ✅ |
| 2 | **信号贡献者**（在线） | L3 | 新闻事件分级、公告解读、投研观点 | FinBERT ✅、TradingAgents ✅ |
| 3 | **风控审查者** | L5 | 事件型 veto 建议、异常解释 | — |
| 4 | **运营 Agent** | L7/运维 | 交易台问答、日报、归因叙述 | — |

## 二、六条铁律

1. **LLM 永不直达下单**：产出只能是 Signal / 建议 / veto 建议，走同一契约 + 同一风控。LLM 没有执行权限，"agent 自动交易"= agent 产出信号，由既有 OrderRouter 执行。
2. **一切可回溯**：提示词版本 + 模型版本 + 输入快照（当时的数据/新闻原文）+ 结构化输出，全量留档。不可复现的 LLM 信号禁止进生产。
3. **数值必须来自工具调用**：价格/财务/持仓等数字一律经工具取数，禁止模型凭记忆生成（防幻觉；幻觉检测自动比对"文本中的数字 vs 工具返回值"）。
4. **LLM 信号必须量化评估**：同量化模型门槛（IC/覆盖率/稳定性/成本），评估通过才可进 ensemble，且**权重设上限**（初期 ≤10%）。
5. **成本与延迟预算**：盘中使用小模型/缓存/批量；离线用大模型；每 agent/每任务 token 预算上限 + 成本看板。
6. **Human-in-the-loop**：写操作（下单/改参数/停用/上线策略）必须人工审批；只读操作自由。

## 三、接入点地图（挂在哪张契约上）

| 层 | 接入方式 | 输入 | 输出（契约） | 阶段 |
|---|---|---|---|---|
| L1 特征 | 新闻情绪特征（分钟级） | Huntly/RSS 流 | 情绪分/事件数 → Feature | P6 |
| L3 信号 | **新闻事件分级**：FinBERT 初筛 → LLM 结构化分级（类型/标靶/严重度/方向） | 新闻原文（不可信输入，见 §四安全） | `Signal(source=llm_news)` | P6 |
| L3 信号 | **投研观点信号化**：TradingAgents 辩论结论 → 日频观点分 | 其一键分析产物 | `Signal(source=llm_research)`，低权重入 ensemble | P7 |
| L3 信号 | 公告/财报事件抽取（业绩预告/减持/立案…） | 公告文本 | 事件信号 + 风控 veto 候选 | P7 |
| L5 风控 | 事件 veto 建议（critical 事件）| 事件流 | veto 建议（规则确认后生效） | P7 |
| L5 风控 | 异常解释/复盘叙述 | 拦截记录/亏损单 | 文本（进失败案例库） | P7 |
| L7/运营 | 交易台问答、日报、归因叙述 | 系统状态/绩效 | 文本 + 建议 | P6 |

## 四、Agent 架构（agent 时代）

```
研究 Agent ──
交易 Agent ──┼─→ 结构化消息总线（与 Signal/事件同契约）→ 风控闸门 → OrderRouter
风控 Agent ──┤        ↑ 人工审批节点（写操作）
复盘 Agent ──┘
```

- **分工与工具集**：每个 agent 有明确工具白名单（取数/回测/查询/推送）；工具即 API，**agent 不直连数据库**。
- **通信纪律**：agent 之间传结构化消息（JSON schema），自由文本只能作为"人看的叙述"字段，不得作为决策依据。
- **记忆**：研究结论库 + 失败案例库（接模型细则 §九），由复盘 Agent 维护。
- **安全（关键）**：
  - **新闻/公告文本是不可信输入**——必须防提示词注入（清洗 + 隔离通道：文本进 LLM 前剥离指令型内容；LLM 输出经 schema 校验才可用）。
  - AI-IDE 沙箱的隔离经验（AST/容器）推广到所有执行型 agent。
  - Agent 的写操作白名单 + 审批 + 全量审计。
- **编排**：function calling 为主；长任务进任务队列（复用现有后台任务框架）；失败重试与超时降级（盘中断路 → 回退纯量化信号）。

## 五、评估与监控（LLM 专属）

| 项 | 方法 | 门槛 |
|---|---|---|
| 信号有效性 | IC/分层/覆盖率（同量化模型口径） | 与量化模型同表评估，权重按表现分配 |
| 幻觉 | 数字自动核对（文本 vs 工具返回） | 错误率 > 阈值 → 该 agent 降级/下线 |
| 成本 | 每 agent/任务 token 成本看板 | 预算超限告警 |
| 延迟 | 盘中链路 P99 | 超时 → 降级为纯量化 |
| 版本管理 | 提示词/模型版本化，变更 A/B + 可回滚 | 同代码变更管理 |
| 稳定性 | 输出 schema 校验通过率 | < 99% → 排查 |

## 六、演进路线

| 阶段 | 内容 | 验收 |
|---|---|---|
| P6 | 新闻事件分级（L3）+ 运营 agent（只读问答/日报） | 事件信号可评估；问答数值 100% 来自工具 |
| P7 | LLM 信号入 ensemble（≤10% 权重）+ 风控审查 agent | IC 评估通过；veto 建议经影子验证 |
| P8 | 多 agent 协同（研究/交易/风控/复盘）+ human-in-the-loop | 端到端演练：异常事件 → agent 建议 → 人工确认 → 风控执行 |

## 七、开放问题

1. 盘中使用模型选型（延迟/成本/效果三角）——小模型本地 vs API？
2. TradingAgents 结论"信号化"的口径（现有报告是宏观/个股观点，转成分数需要标定方案）。
3. Agent 写操作白名单的边界（哪些可以全自动，哪些必须审批）——建议初期全部审批。
4. 新闻注入防护的实现深度（清洗规则 vs 双模型交叉验证）。
