# 模型量化细则设计方案（Model Contract · 防未来函数 · 验证 · 监控）

> 版本：v1（2026-09-15）　配套：`docs/统一交易栈_设计方案.md`（v3）
> 定位：统一交易栈的"模型侧"细则。回答一个问题——**量化里什么最重要，以及落到每个接口上怎么做**。

---

## 一、量化第一性原理：什么最重要

按"做错的代价 × 发生的概率"排序（这也是本方案在所有取舍中的优先级）：

| 优先级 | 原则 | 为什么 | 判据（做到了什么样） |
|---|---|---|---|
| **1** | **数据与时点正确性** | 错误的输入比错误的模型致命 100 倍；未来函数极其隐蔽（前复权序列、财务报告期、行业分类版本） | 全部输入可回答"**在 T 日收盘时，这个值是否已经可知**" |
| **2** | **诚实的评估** | 大部分"高收益"死于样本外失效与多重检验；自己骗自己是最贵的错误 | 样本外+成本后+多重检验折扣后仍然有效 |
| **3** | **成本与容量** | 持有 2-4 天、每天换 3-5 只 = 年换手 20-50 倍，成本吃掉大半 alpha | 成本后净值曲线才是唯一有效曲线；容量可估算 |
| **4** | **全链一致性** | 研究/回测/模拟/实盘任何一环口径漂移，前面全部作废 | 同一策略五个环节的成交序列可 diff |
| **5** | **风险与生存** | 一次 2024-02 微盘股级别的崩盘可以抹掉两年收益 | 极端行情下有强制空仓/降仓机制且被回测验证 |
| **6** | **模型本身** | 模型从 XGBoost 换到 TFT 的边际收益，远小于上面任何一项做对 | 模型迭代是"锦上添花"，不是第一优先级 |

**推论（资源分配）**：口径治理 / 验证体系 / 监控告警的建设投入，应大于"换更强的模型"。本细则 70% 的篇幅在 1-4 项上。

## 二、模型契约（Model Contract）——模型量化的"身份证"

**问题**：模型 metadata 今天是"参考信息"，错误也没人拦。目标：**契约不符即拒**（推理/回测/策略绑定三个入口强制校验）。

### 2.1 契约 schema（metadata.json 必备字段）

```jsonc
{
  "model_id": "mdl_cn_train_20260906_...",
  "market": "CN",
  "version": 3,
  "label": {
    "type": "excess_return",          // raw_return | excess_return | rank
    "benchmark": "000905.SH",         // excess 时的基准
    "horizon_days": 5,                // 持有 H 日
    "execution_lag_days": 1,          // T+lag 执行（训推一致的关键）
    "limit_handling": "exclude",      // 一字板/跌停样本处理：exclude | clip | mark
    "price_basis": "hfq_close"        // 标签价格口径（前复权收盘）
  },
  "features": {
    "count": 151, "version": "feat_v12",
    "list_hash": "sha256:...",        // 特征清单哈希（训练=推理强校验）
    "missing_policy": "drop|zero|median"
  },
  "universe": { "pool": "cn_all_a", "exclude": ["ST","suspended","new_listing_60d","delisting"] },
  "adjust": "hfq",                    // 复权口径标记
  "neutralize": { "industry": true, "size": true, "method": "regression" },
  "cv": { "scheme": "purged_walk_forward", "purge_days": 5, "embargo_days": 2 },
  "train_window": ["2016-01-01", "2026-05-31"],
  "metrics": { "ic": 0.061, "icir": 0.52, "rank_ic": 0.058, "turnover": 0.35,
               "quantile_spread_ann": 0.18, "half_life_days": 6 },
  "status": "production",             // candidate | production | watch | retired
  "created_at": "...", "trainer": "autodl|local", "git_commit": "..."
}
```

### 2.2 三方对齐矩阵（**量化最容易翻车的地方**）

| 维度 | 训练时 | 策略/回测时 | 实盘/模拟时 | 不一致的后果 |
|---|---|---|---|---|
| 执行滞后 lag | `label.execution_lag_days` | 回测撮合时点必须相同 | 下单时点必须相同 | 回测虚高（T 日信号 T 日收盘成交=未来函数） |
| 持有期 horizon | `label.horizon_days` | `risk.max_hold_days` ≤ horizon | 同 | 拿超期衰减的信号做短打/反之 |
| 价格口径 | 标签价格 basis | 撮合价同口径 | 同 | 复权口径不一致 → 收益虚增 |
| 股票池 | `universe` | 回测池 = 训练池 | 实盘池 = 训练池 | 训练在主板、实盘买双创（**现有 19/27 双创板事故**） |
| 特征清单 | `list_hash` | 推理特征同 hash | 同 | 静默少喂/多喂特征（**曾发生过**） |
| 预处理 | NaN/极值/标准化 | 推理同实现 | 同 | 分布漂移假象 |

**实现**：`ModelContract.check(model_meta, strategy_spec, exec_context)` 在推理入口（`script_runner`）、回测入口（`backtest_service`）、策略绑定入口（`real_trading_lifecycle`）三处强制调用；不通过→ 拒绝运行 + 明确报错（不允许 warning 放行）。

## 三、防未来函数细则（Lookahead Checklist + 自动化验收）

### 3.1 分类清单（逐项对照，全部要有自动化测试）

| # | 类别 | 具体陷阱 | 正确做法 | 现状 |
|---|---|---|---|---|
| 1 | **复权价格** | 前复权序列会随新除权**整体重算**——今天看到的前复权价，在历史某天是不可知的 | 回测/训练用"当时可知"口径：**后复权**或"原始价 + 当日已生效复权因子" | ⚠️ `daily_forward` 曾损坏；分钟/日线双重缩放陷阱已记录 |
| 2 | 停牌 | 停牌期间无价格，前复权/插值会造假数据 | 停牌日特征保留、标签按规则处理（排除或特殊标记） | 部分处理 |
| 3 | 涨跌停 | 一字板买入的样本在实盘不可获得 → 训练集里的"涨停后收益"有幸存者偏差 | 标签层 `limit_handling`：一字板样本剔除/标记；回测撮合独立判定可成交性 | 选股侧有剔除，标签侧待查 |
| 4 | **财务数据** | 用报告期而非**公告日** = 未来函数；财报修正（restatement） | 一律按公告日（PIT）建特征；修正数据保留双版本 | ⚠️ 待审计（valuation TTM 曾出过中报季损坏） |
| 5 | 行业/指数成分 | 申万行业分类会改版；指数成分会调整 | 使用时点快照（分类生效日） | 待审计 |
| 6 | ST/退市标记 | 用"当前"ST 名单回填历史 = 未来函数 | ST 生效日时点标记 | 信号侧有 30 天窗口处理，需确认口径 |
| 7 | 特征计算 | rolling 窗口 shift 少一位；全样本标准化（用了未来均值/方差） | 严格 as-of；标准化只用截至当日数据 | 有测试（OOF purge 已修） |
| 8 | 交易日历 | 用自然日/错误日历导致窗口错位 | 统一交易日历服务 | 已修复（含美股假日别名） |
| 9 | 截面处理 | rank/zscore 用了全历史而非当日截面 | 截面统计仅当日 | 待审计 |
| 10 | 标签本身 | 标签窗口与验证集重叠（**OOF purge 已修**）；T+1 涨跌停无法执行的样本 | purge=horizon + embargo | ✅ 已修（`_generate_oof_predictions`） |

### 3.2 自动化验收（三类测试，进 CI）

1. **未来扰动测试**：把 T 日之后的所有行情/财务数据人为修改（±10%），断言 T 日的特征值与标签**逐位不变**。覆盖全部特征。
2. **复权一致性测试**：任取 N 个除权日前后样本，断言"后复权收益 = 原始价收益 + 复权因子演算收益"。
3. **PIT 抽检**：随机抽 100 条财务特征，人工核对公告日 ≤ 特征日期（抽检脚本输出对照表）。

> 这三个测试是"数据与时点正确性"（第一性原理 #1）的可执行化。不通过不许训练。

## 四、标签设计规范

| 项 | 规范 | 说明 |
|---|---|---|
| 收益定义 | `close(T+lag+H)/close(T+lag) - 1`，后复权口径（或等价的因子演算） | 与撮合口径一致 |
| 执行时点 | lag 默认 1（T 日信号 → T+1 执行）；若策略用开盘执行，标签也用开盘价 | **标签时点 = 策略执行时点**，不能想当然 |
| 涨跌停处理 | 买入不可得（一字板）→ exclude；跌停不可卖 → 收益 clip 或标记 | 样本偏差是隐性杀手 |
| 停牌/退市 | 长期停牌剔除；退市股保留至退市日（**避免幸存者偏差**） | 股票池必须含已退市标的的历史 |
| 样本权重 | 时间衰减（半衰期可配，默认 250 交易日），近期样本权重高 | 应对市场结构性变化 |
| 类别/截面 | 每截面样本数 < N（如 50）跳过该截面 | 防小样本截面噪声 |

## 五、验证协议（防自欺细则）

### 5.1 切分与评估
- **切分**：purged walk-forward（滚动）+ embargo；purge = horizon 天数，embargo = 1-2 天。禁止随机切分、禁止用测试集调参。
- **指标**（全部要，缺一不可）：
  - IC / RankIC / ICIR（日频截面，≥50 样本/日）
  - **分层组合收益**（Q1-Q5 单调性）——比 IC 更能说明"能不能赚钱"
  - 换手率与**信号衰减半衰期**（决定持有期与调仓频率）
  - 成本后组合净值（佣金+印花+滑点+冲击，按 §交易细则费用表）
  - 容量粗估（按日均成交额与目标仓位推算可承载资金）

### 5.2 稳健性（已有资产接线）
- 参数敏感性 / 扰动保真度 PFS（`factor_quality.py` 已有，训练默认开）→ 接线到模型卡
- 子样本：牛/熊/震荡、不同市值档、不同年份（至少 3 个子样本都无崩坏）
- **多重检验折扣**：记录搜索过的参数组数，最终指标做 deflated 折扣（防 p-hacking）；扫描越多的组合，晋级门槛越高

### 5.3 晋级门槛（示例值，可配置）

| 门槛 | 候选→production | production→策略绑定 |
|---|---|---|
| OOS RankIC | ≥ 0.03 | ≥ 0.03（近 3 月滚动） |
| ICIR | ≥ 0.3 | ≥ 0.3 |
| Q1-Q5 单调 | 是 | 滚动窗口保持 |
| 成本后年化（回测） | > 基准 + 5% | — |
| 最大回撤 | < 25% | — |
| 滚动 IC 衰减 | — | 近 20 日未触发降仓阈值 |

## 六、模型监控与退役（生产期）

| 监控项 | 频率 | 阈值示例 | 动作 |
|---|---|---|---|
| 滚动 IC（`model_ic_monitor.py` 已有） | 日 | 20 日均值 < 0.01 或 t < 0 | 告警 → **降仓建议**（人工确认） |
| 特征漂移 PSI | 日 | PSI > 0.25（单特征）/ 全局 > 0.1 | 告警 + 排查数据管线 |
| 预测分布 | 日 | 分数分布坍缩（std 掉 50%） | 告警 → 检查推理链路 |
| 分层组合 | 日 | 连续 5 日 Q5 跑输 Q1 | 告警 → 降仓/停用建议 |
| 契约漂移 | 每次推理 | list_hash 变化 | **拒绝运行** |

原则：监控产出**建议**，停用需人工确认（防止监控自身误报导致误停）；所有告警进"今日交易台"红点。

## 七、特征治理

1. **特征注册表**（每特征一行）：名称、定义、单位、更新频率、依赖数据版本、PIT 判定依据、负责人。放进 `docs/` 或 DB 表，与 `factor_quality` 打通。
2. **版本与哈希**：`feature_version` + `list_hash` 写入模型契约；训练与推理强校验（曾发生 SHAP 因列名市场差异静默 None、特征数不对齐类事故）。
3. **预处理一致性**：NaN/极值/标准化的**同一份实现**被训练与推理共用（抽成共享函数，禁止两处各写一份）；训练预处理配置入 metadata。
4. **新特征准入**：覆盖度 → 单因子 IC → 与存量相关性去重（已有去重管线）→ PFS/DH 质量闸门 → 小步进模型对比。

## 八、重训与模型生命周期

| 项 | 规则 |
|---|---|
| 重训节奏 | 定时（季度/月度）+ 触发式（滚动 IC 触发）；两者都产生 **candidate**，不自动替换 production |
| 窗口一致性 | 训练/推理/回测的起始窗口一致（如 DEFAULT_START=2016） |
| 版本保留 | production 保留最近 N 个版本可回滚；退役模型目录不删（审计） |
| 融合模型 | 融合权重确定要走 OOS（不能用全样本拟合权重）；子模型单独监控，单只失效可降权（**子模型失效检测**是本项头号任务） |
| 训练环境 | 远程训练产物回传后强制跑契约校验 + 契约一致性回归 |

## 九、归因与复盘（把"为什么赚/亏"说清楚）

- **收益分解**：基准收益 + 行业配置 + 选股 alpha + 择时 + 交互项（Brinson 类）
- **成本分解**：佣金 / 印花 / 过户 / 滑点 / 冲击（fills 已分项存）
- **换手分解**：调仓换手 vs 止损换手
- **失败案例库**：每笔大亏自动归档（信号→持仓→卖出全链路快照 + 当日市场状态 + 相关新闻），月度复盘
