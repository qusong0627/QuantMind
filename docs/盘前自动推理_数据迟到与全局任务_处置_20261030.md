# 盘前自动推理：数据迟到与全局任务失败 · 处置记录

- 日期：2026-10-30
- 现象时间：2026-10-29 08:00（北京）自动推理全部失败

## 1. 现象

2026-10-29 08:00 的 `auto_inference_if_needed` 对 5 个 CUSTOM 市场模型全部失败：

```
主模型维度门禁未通过: QuantDB l1_factors 最新可用 2026-10-27，请求 2026-10-28 超出数据范围
```

同日 08:00 全局任务（`model_id=None`）失败：

```
主模型推理脚本不存在: /app/models/production/inference.py
```

## 2. 根因

### 2.1 日K 本身迟到，补池链把「本地最新」当成了「已最新」

- 10-28 的 `daily_forward` 分区直到 **10-29 20:07（北京）** 才落盘（mtime 实证），
  10-29 08:00 时本地最新只有 10-27。
- `scripts/alpha_refresh_retry.sh` 的三档补跑（北京 04:30/05:30/06:30）以
  `kline` 本地最新分区为基准判断 alpha/custom 是否滞后。kline 自己滞后时，
  三者相等 → 日志「无事：已最新」→ 不触发任何同步。
- 08:00 自动推理按交易日历请求「最近一个已收盘交易日」10-28 → 数据不存在 → 门禁失败。

### 2.2 production 模型目录为空

`/app/models/production` 没有 `inference.py`，全局任务（不属于任何用户模型）每天仍会派发一次注定失败的 run。

## 3. 修复

### 3.1 补池链：用交易日历做期望基准

`scripts/alpha_refresh_retry.sh`：

- 新增 `expected_last_session()`：容器内 `exchange_calendars` 取「昨天及以前最后一个交易日」（北京时区）；
- `KLINE_DT < EXPECTED_DT` 视为日K 滞后，先触发容器内 `run_market_sync('A')`（超时 45 分钟），
  再重算 alpha/custom 滞后标记；
- 同步后日K 仍缺：末档推 🟠，不再空跑；
- 测试/演练：`QM_EXPECTED_DT_OVERRIDE=YYYYMMDD` 可注入期望日；`DOCKER_BIN` 非真 docker 时跳过日历调用（不影响替身测试）。

### 3.2 自动推理：09:05 补跑

`backend/services/engine/qlib_app/celery_config.py` 新增 beat：

```
auto-inference-retry-0905  周一至周五 09:05
```

- 08:00 成功时被 `ALREADY_DONE`/推理锁跳过（幂等）；
- 08:00 因数据迟到失败时，09:05 再试；约 6 分钟，早于 09:35 决策轮。

### 3.3 全局任务：未配置就跳过

`backend/services/engine/tasks/celery_tasks.py`：

- 新增 `_production_inference_available()`；
- 全局任务（`sid=global, model_id=None`）在无解析模型且 production 目录无 `inference.py` 时，
  记 `skipped / NO_PRODUCTION_MODEL`，不再记 failed。

## 4. 验收

- `bash -n scripts/alpha_refresh_retry.sh` 通过；
- `--dry-run` 正常日：`expected=20261029` 与 kline 一致 → 无事退出；
- `--dry-run` + `QM_EXPECTED_DT_OVERRIDE=20261030`：输出「日K 滞后 → 将执行 A 股同步」；
- `scripts/tests/test_alpha_refresh_retry.py`：33 passed；
- `backend/tests/test_auto_inference_production_guard.py`：2 passed。

## 5. 遗留

- 若上游 QuantDB release 当晚未发布，早晨同步也拉不到，只能等 09:05 补跑或人工确认；
  末档 🟠 会明确报「日K 仍缺 X」。
- A 股同步自身仍按用户在「数据管理 → 同步调度」里的配置（当前 20:55）执行；
  本修复只在盘前发现缺口时补一次，不改变用户调度。
