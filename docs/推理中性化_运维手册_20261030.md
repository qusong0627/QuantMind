# 推理中性化影子层 · 运维手册

配套设计：`docs/推理中性化处理前端_生产级设计_20261030.md`

## 1. 一分钟判断是否正常

```sql
-- 最近一次计算
SELECT model_id, data_trade_date, status, n_symbols, n_total,
       round(coverage::numeric, 4) AS coverage, round(r2_pass1::numeric, 3) AS r2,
       reason, config_version
FROM qm_neutral_runs
ORDER BY created_at DESC
LIMIT 5;
```

- `status=ok`：正常；
- `status=degraded`：看 `reason`（样本不足 / 覆盖率不足 / 控制变量缺失 / 矩阵病态 / 事后暴露残留）；
- `status=failed`：控制变量分区缺失或读取失败，修数据后重算。

## 2. 开启 / 修改 / 关闭

前端两个入口（同一份后端配置）：

- 推理中心 → 模型治理 → 「推理中性化」；
- 模型管理 → 选中模型 → 「中性化」Tab。

模式：

- `off`：不计算；
- `shadow`（默认）：只写影子表，不改原始排序与下单；
- `enforce`：允许消费方读取中性化分位，需要管理员权限；当前无消费方接入，等价于 shadow + 标记。

## 3. 批量推理与实时推理

- **批量推理**：每次 run 成功落库后自动计算（`script_runner` 收尾），失败只告警，不影响 run 成功状态；
- **实时推理**：`signal-ready` 后自动计算，`universe_scope=hot_set`；
- **enforce 不使用热集结果**（横截面样本偏差），只认全市场。

## 4. 历史回填

```bash
# 单个模型
python -m backend.scripts.neutralization_backfill \
  --model-id mdl_cn_train_xxx --from 2025-01-02 --to 2026-10-23

# 全部已开启（mode != off）的模型
python -m backend.scripts.neutralization_backfill --all-enabled \
  --from 2025-01-02 --to 2026-10-23
```

只写影子表；每天取该模型当天最近一次 completed 推理 run；缺口逐日记录并继续。

单日重算也可以走前端「重算当日」，或：

```bash
curl -X POST "$API/api/v1/models/$MID/neutralization/recompute" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"data_trade_date":"2026-10-29"}'
```

## 5. 控制变量缺失

控制变量来自 `6_ml_datasets/l1_factors/dt=YYYYMMDD/data.parquet` 的
`fun_float_mv` / `style_beta_60` / `mom_ret_20d`。分区缺失会写 `failed`，修好分区后回填该日即可。

## 6. 每日巡检 SQL

```sql
-- 覆盖率 < 95% 的日期
SELECT model_id, data_trade_date, coverage
FROM qm_neutral_runs
WHERE coverage < 0.95 AND data_trade_date >= CURRENT_DATE - 30
ORDER BY data_trade_date DESC;

-- 事后暴露残留 > 0.05
SELECT model_id, data_trade_date, exposure
FROM qm_neutral_runs
WHERE data_trade_date >= CURRENT_DATE - 30
  AND exposure::text LIKE '%0.0%'
ORDER BY data_trade_date DESC;
```

## 7. 回滚

- 单模型：前端切 `off`，或 `PUT .../neutralization {"mode":"off", ...}`；
- 全量：`UPDATE qm_neutralization_settings SET mode='off';`（需管理员评估，不在迁移脚本内）；
- 影子表独立，回滚不需要动 `engine_signal_scores` 与任何模型产物。

## 8. 审计

```sql
SELECT created_at, model_id, action, operator, from_value->>'mode' AS before_mode,
       to_value->>'mode' AS after_mode
FROM qm_neutralization_audit
ORDER BY created_at DESC
LIMIT 20;
```
