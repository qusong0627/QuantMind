# 模型训练机构级升级：规划、审查与落地（Phase 1）

> 日期：2026-11-27
> 范围：训练参数治理 + 模型结构护栏 + 训练/推理一致性；不改标签定义、不改切分口径、不改已上线模型产物。
> 原则：一次只动一轴；默认值变更必须可解释、可回滚、有测试；性能结论标注「待实测」。

---

## 一、目标与验收判据

### 目标

1. **参数治理**：前端训练页与训练容器对同一参数只保留一份「机构基准」，消除"前端默认覆盖后端机构起点"的漂移。
2. **结构适配**：模型默认结构与数据形态（20 步窗口、151–4700 列、8M 行）匹配，结构失配要在训练日志里可见。
3. **财务现实**：默认参数面向 A 股日频截面（厚尾、低信噪、强正则、按日分组排序），而不是通用 ML 教程默认值。
4. **训练/推理一致**：任何默认值的改动不得造成训练端与推理端口径分叉（尤其是序列模型的 `feat_norm` 与截面预处理）。

### 验收判据（kill criteria）

| 编号 | 判据 | 不通过即回滚 |
|---|---|---|
| K1 | 前后端同名参数取值一致，或差异有注释说明 | 任何无注释差异 |
| K2 | 排序目标早停由显式指标决定，不由多指标竞争决定 | 早停行为仍不确定 |
| K3 | TCN 默认结构感受野 ≥ `step_len` | 感受野 < 窗口 |
| K4 | 所有改动有单测/AST 测试覆盖 | 无测试的默认值变更 |
| K5 | 不改变已训练模型的推理行为 | 旧产物加载/预测变化 |
| K6 | 不在本轮启用任何会破坏实时链的默认值（见审查 R2） | 平铺模型默认开截面预处理 |

## 二、现状审计（代码事实）

1. **前端默认覆盖后端**：`electron/src/pages/training/trainingUtils.tsx` 的 `buildBackendTrainingPayload` 始终把 `lgb_params/xgb_params/catboost_params/dl_params` 全量写进载荷；后端 `DEFAULT_*` 仅在缺键时兜底。实际生效的是前端值。
2. **GRU/LSTM/ALSTM 学习率漂移**：前端 `MODEL_DL_DEFAULTS` 为 `1e-3`，后端 `trainers_dl.py:342` 为 `3e-4`，且后端注释记录了 2026-09-16「1e-3 大表第 1 轮冲过头被早停」的实证。
3. **MLP 无专属默认**：前端切到 MLP 时沿用全局 `dl_lr=1e-4`、`n_epochs=200`，后端 MLP 文档默认 `1e-3`、`500` 轮。
4. **XGBoost `min_child_weight=100`**：平方损失下 hessian≈1/样本，等价每叶 100 个样本；LGB 同口径 `min_data_in_leaf=500`，两者不一致，8M 行面板上 XGB 叶子过细。
5. **LGB 行业码未声明类别**：`industry_as_feature` 会把 `ind_code_l1` 加入特征（`train.py:1599`），但 LGB 训练器未传 `categorical_feature`，行业码被当数值序数。预处理已把 `ind_code_l1/l2` 排除在截面变换外（`data/splits.py:300`），编码本身安全。
6. **LGB 早停口径不确定**：`lgb.early_stopping(...)` 未设 `first_metric_only`，valid 同时含 `l2/ndcg` 与 feval `rank_ic`；LightGBM 4.x 默认对多指标做早停检查，与代码注释「以 l2 为准」不一致。
7. **TCN 感受野不足**：默认 `kernel_size=5, num_layers=2`，按 Qlib `dilations=2^i` 口径感受野 13 步，小于默认 `step_len=20`。
8. **Optuna 搜索空间与机构基线错位**：LGB `min_child_samples` 搜 20–500、`feature_fraction` 搜 0.4–0.9；XGB `min_child_weight` 搜 20–300。大表场景应覆盖更保守的区间。
9. **`mlp` 框架元数据不一致**：`capabilities.py` 为 `sklearn`，`model_algorithm_meta.ALGO_FRAMEWORKS` 为 `pytorch`。

## 三、方案 v1（初版）

1. 前端 GBDT/DL 默认值全面对齐后端机构起点；新增 MLP 默认块；GRU 系 lr 改 3e-4。
2. 后端 XGB `min_child_weight` 100→500；LGB 声明类别特征；LGB 早停 `first_metric_only=True`；Optuna 搜索区间扩到机构区间。
3. TCN 增加感受野检查，不足则告警并写元数据。
4. 序列模型默认开启截面预处理（rank）。
5. 修正 `mlp` framework 元数据。

## 四、审查意见（v1 → v2）

### R1：默认值变更影响历史可比性 —— 接受，但必须单一入口

前端默认值只影响**新建草稿**；已保存草稿（localStorage）保留旧值。后端默认值只影响**未显式传参**的 API 调用。两者都不会改写历史模型产物，K5 满足。为降低认知负担，前端集中在 `DEFAULT_PARAMS` / `MODEL_DL_DEFAULTS` 两个块，并加注释指向后端 `DEFAULT_*`。

### R2：序列模型默认开截面预处理 —— **驳回（关键）**

`backend/services/engine/inference/realtime_service.py:52` 明确记录：**平铺模型 + preprocessing.enabled 的模型在实时链无法复现截面变换**（实时链是单帧 fill 口径）。虽然序列模型实时链支持（`preprocessing=meta.get("preprocessing") if seq_len > 1 else None`），但：

- 批次推理模板与实时链都会读 metadata，行为尚可复现；
- 但训练端"默认开"意味着用户无法在 UI 上表达"我明确要关"（前端关闭时根本不发这个键）；
- 这属于改变训练语义的第二轴，必须在 Phase 2 用 A/B 单独验证。

**v2 改为**：保持默认关闭；在训练日志中对「序列模型 + 未启用截面预处理」给出一次显式告警（不阻断）。UI 默认值不动。

### R3：TCN 自动改结构 —— 驳回，改为告警

静默修改用户显式参数（如 `num_layers`）会让复现困难。v2 只计算感受野、不足时告警，并写进 `dl_metadata` 供审计；是否改结构由用户决定。

### R4：XGB `min_child_weight` 100→500 是否有依据

有，且是同口径一致性：LGB `min_data_in_leaf=500`、CatBoost `depth=5`。平方损失下 XGB 的 hessian 之和≈样本数，500 等价于 LGB 的 500。属于「同一机构基线的口径统一」，不是拍脑袋调参。仍标注为待横评项。

### R5：改后端默认值会不会影响训练容器外的调用方

会。`DEFAULT_XGB_PARAMS` 被训练容器、Optuna 包装、可能的脚本共用。改动是全局的，但所有调用方都能用显式参数覆盖；且这是"机构起点"而非"最优值"的修正。K1/K4 要求有测试锁定。

### R6：前端 TS 默认值如何防止再次漂移

引入 **AST/正则不敏感的静态校验测试**太脆弱。v2 采用折中：后端测试只锁定后端常量与纯函数；前端默认值用一条轻量源码断言测试（读取 `trainingUtils.tsx`，检查关键键值），失败信息直接给出「前后端默认值漂移」。该测试不解析 TS，只做受控正则匹配，键名变更时会显式失败而不是静默通过。

### R7：本轮不碰的项（Phase 2/3）

| 项 | 原因 |
|---|---|
| 序列模型默认截面预处理 | 需 A/B + 实时链验证（R2） |
| DL 按验证集 rank IC 选 checkpoint | 需要 loader 带日期，改造面大 |
| 多模型按净值/成本后收益选优 | 需要逐模型组合评估，超出参数治理范围 |
| GATs/HIST 图模型 | 新数据通道，研究先行 |
| 样本权重默认开启 | 加载器已做 ST 过滤与停牌剔除；PIT 权重默认开启会影响 OSS 部署的 fail-closed 行为 |

### R8：短段 embargo 从「告警跳过」改为「直接失败」——接受（本轮唯一变严项）

- **影响**：任何 train 或 valid 段长度 ≤ `target_horizon_days + 1` 个交易日的配置将无法训练。
- **依据**：该配置下段尾样本的标签必然跨入下一段，属于前视泄漏；旧实现只打一条
  `Embargo skipped` 警告后继续训练，等于静默放行。
- **缓解**：错误文案直接给出「扩大该段窗口或降低 `target_horizon_days`」；
  默认时间窗口（train 2016–2023 / valid 2024 / test 2025）远大于 embargo，日常训练不受影响。
- **代价**：极短窗口的演示/冒烟配置需要显式调整切分。这是有意的 fail-closed。

## 五、方案 v2（本轮落地）

### A. 前端参数治理（`electron/src/pages/training/trainingUtils.tsx`）

| 键 | 旧 | 新 | 依据 |
|---|---|---|---|
| `learning_rate` | 0.02 | **0.03** | 后端机构起点 |
| `max_depth` | -1 | **6** | 后端机构起点；`num_leaves` 仍是主要容量控制 |
| `min_data_in_leaf` | 300 | **500** | 8M 行下防过拟合 |
| `bagging_freq` | 5 | **1** | 后端机构起点 |
| `lambda_l2` | 1.0 | **5.0** | 后端机构起点 |
| `num_boost_round` | 2000 | **1000** | 后端机构起点；早停会先触发 |
| `xgb_max_depth` | 4 | **5** | 后端机构起点 |
| `xgb_subsample` | 0.7 | **0.8** | 后端机构起点 |
| `xgb_colsample_bytree` | 0.65 | **0.8** | 后端机构起点 |
| `xgb_reg_lambda` | 2.0 | **10.0** | 后端机构起点 |
| `xgb_min_child_weight` | 100 | **500** | 与 LGB `min_data_in_leaf` 同口径 |
| `cb_depth` | 6 | **5** | 后端机构起点 |
| `cb_l2_leaf_reg` | 3.0 | **10.0** | 后端机构起点 |

### C. 无未来函数 / 防过拟合专项（本轮硬要求）

| 护栏 | 位置 | 行为 |
|---|---|---|
| 特征名泄漏硬闸 | `request.py`（422）+ `data/integrity.py`（RuntimeError） | `label` 家族、`fwd/future/next` 收益一律拒绝；`return_{n}d` 只告警（语义随因子源不同，非直读源加载时剔除） |
| 时点完整性复核 | `data/integrity.py::time_integrity_report` | 三段顺序 + train→valid / valid→test 交易日间隔 ≥ `horizon + lag`，不足即中止 |
| 短段 embargo fail-closed | `data/splits.py::_take_segment` | 旧实现「段太短 → 告警并跳过裁剪」= 静默泄漏；现改为 RuntimeError，要求扩窗或降 horizon |
| 标签构建口径 | `data/loading.py`（既有） | 标签 = `shift(-(horizon + 1))`；节假日填充行先剔除；非直读源剔除 `return_*d` |
| 填充统计只看 train | `data/splits.py::_prepare_arrays`（既有） | median 取自 train；截面变换逐日独立；新增测试钉住 |
| 测试集不参与早停 | `data/splits.py`（既有） | valid/test 重叠直接 RuntimeError；test 段位于时间末端 |
| WFA 窗口 embargo | `data/wfa_windows.py`（新增） | 复核发现 WFA 诊断原先 train→val 不裁 embargo；现与主切分同口径，段太短跳过该窗口 |
| OOF 折 purge | `train.py::_generate_oof_predictions` | 复核发现只 purge `horizon`，漏了 T+1 执行滞后（最后一个训练日标签跨到验证首日）；现改为 `horizon + lag` |
| 过拟合诊断 | `data/integrity.py::overfit_diagnostics` | `no_val_signal` / `train_val_gap`（≥0.05）/ `stopped_immediately` / `rounds_exhausted`；写入 comparison 行并打日志 |
| Optuna 反过拟合 | `train.py` | LGB `min_child_samples` 200–2000、`feature_fraction` 0.15–0.9；XGB `min_child_weight` 100–2000；CatBoost `l2_leaf_reg` 1–50 |

**语义变更（需知会）**：`_take_segment` 从「短段告警跳过 embargo」改为「直接失败」。这是本轮唯一的训练行为变严项——任何 `valid`/`train` 段长度 ≤ `horizon + 1` 个交易日的配置将无法训练。理由：该配置下尾部标签必然跨段，属于前视泄漏，静默放行比失败更危险。

## 六、审计与回滚

- 所有默认值都是"起点"，用户可在训练页逐项覆盖；回滚只需回退本文件与参数块。
- 新增的告警不改变训练结果（仅日志/元数据），可安全保留。
- `dl_metadata` 新增键为追加式，不删除既有键；旧产物加载路径不变。
- 前端默认值不影响已训练模型与已保存草稿（localStorage 优先）。

## 七、Phase 2 备选（本轮不实施）

1. 序列模型截面预处理默认开启（先 A/B：同特征同标签，开/关各训一版，比较 residual IC / random batches）。
2. DL 训练循环按验证集 rank IC 保存 checkpoint（需 loader 携带日期）。
3. 多模型选优从 `val_rank_icir` 扩展为「成本后 top-decile 净值 + residual IC」双条件。
4. GATs/HIST 图模型研究线（行业/概念邻接，按预测日重建图）。
