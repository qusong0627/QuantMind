# 因子研究主库：2016-07 起 + 年分区 + 方向冻结（2026-11-10）

## 目标

把因子研究工作台从「2020-01 至今的单快照」扩到 **2016-07 至今**，并允许用户按
时间窗选择、按年增量续拉。机构级底线：**可复现、可对账、样本外不泄漏**。

## 口径

| 项 | 口径 |
|---|---|
| 主库窗口 | CN 默认 `2016-07-01` 至今；行情/估值/ST PIT 自 `2016-01-04` 起 |
| 2016 上半年 | 股票池要求近 120 日 60% 有效历史 → 2016-01~06 为空窗，首月 2016-07 |
| 财务因子 | 财务三表自 2016Q1 起；TTM 首个完整可用约 2017Q1/Q2，早月显示「—」 |
| 方向 sign | 只在校准窗 **2020-01-01 ~ 2024-12-31** 算一次，写 `direction.json`；评估窗口只读 |
| 退市覆盖 | `coverage.json` 逐月统计「行情有票但所有因子库都没值」的缺口；窗口内 >5% → `survivorship_bias=true` |
| 持有期收益 | 构建时多读 45 天；块末月（如 2019-12）的 fwd 用下一采样日价格，边界不断链 |
| 运行时 | 只读与请求区间相交的 `year=YYYY.parquet`；旧单文件快照自动回退 |

## 存储布局

```
factor_research[_private]/
  meta.json / factors.json / metrics.json
  direction.json                  # 冻结 sign + 校准窗 + 每因子来源（calibration/frozen/fallback/catalog）
  coverage.json                   # 逐月 + 逐因子覆盖；survivorship_bias
  factor_panel.parquet            # 兼容整份（运行时优先读年分区）
  factor_panel/year=YYYY.parquet
  monthly_scores.parquet          # classic 兼容整份；private 只写年分区
  monthly_scores/year=YYYY.parquet
  stock_snapshot.parquet          # 最新截面（兼容）
  stock_snapshot/year=YYYY.parquet# 历史窗口持仓画像用当年末截面
  ic.parquet / fwd_returns.parquet / benchmarks.parquet / nav.parquet
```

## 构建与增量

```bash
# 全量（classic 约 10–20 分钟；private 约 15–25 分钟，构建按年写分区）
python3 backend/scripts/build_factor_research.py --start 2016-07-01
python3 backend/scripts/build_factor_panel_private.py --start 2016-07-01 \
    --direction-out data/quantdb/factor_research_private/direction.json

# 增量续拉（保留旧年；必须复用冻结方向）
python3 backend/scripts/build_factor_panel_private.py --start 2026-11-01 \
    --append --direction-file data/quantdb/factor_research_private/direction.json

# API：POST /api/v1/factor-research/build?dataset=private&start=2026-11-01&append=true
```

`--out <dir>` 可先写 staging 再切换；`--no-partition` 仅用于冒烟/小数据。
classic 不支持 `append`（全量重建便宜；API 会明确拒绝）。

**私有分块顺序（必须）**：先 `2020-01~2024-12`（校准窗，写 direction.json）→
再 `2016-07~2019-12 --append` → 最后 `2025-01~今 --append`。
每块都带 `--direction-file`（已有方向优先），顺序反了会把 2016 块的本窗 IC
当成冻结方向。

## 运行时 / 前端

- `store.panel(dataset, market, start, end)`：读相交年份；缓存键含窗口与文件 mtime。
- `store.scores_for(..., start, end)`：private 宽表按列裁剪 + melt；classic 长表过滤。
- `store.stock_snapshot(market, as_of)`：按年截面，历史窗口不回看今天。
- API `range` 元信息新增 `window` / `lookback_start` / `direction_calibration` /
  `survivorship_bias`（**按当前窗口切片判定**，不拿全库 flag 盖所有年份）。
- 前端区间选择器：时代档 `2016–2019` / `2020–2024` / `2025–今` + 窗口内全部年份；
  主库窗口与「退市覆盖缺口」徽章。
- 因子在所选窗口无数据时返回空详情 + `unavailable_reason`（含首个有效日），不再 404。

### 2026-11-10 实测结果

- classic：73 因子 × 125 期（2016-07-29 ~ 2026-11-09），容器内 779 秒；
  `factor_panel/monthly_scores/stock_snapshot` 年分区 + `years.json` 齐。
- 旧快照（10-09 数据）vs 新 10 年库在 2020-01-23 对拍：持有期终点同为 2020-02-28；
  fwd 最大差 1.66%、IC 最大差 0.029；面板差异集中在 **EQGROWTH（旧值全 0 → 新值真实）**、
  PBPCTL、INTCOVER —— 属 11-06 财务数据刷新后的 vintage 修复，不是构建代码回归。
  非重叠的末月（2026-09-30）因新旧持有终点不同已剔除。
- 同数据/同代码的 host staging 与容器 full 在 2019-12-31 对拍：`fwd_returns` 全表逐值
  一致；score 差异仅 TURNVOL 一列（容器 pandas 2 的 rolling 行为，旧快照同样存在，
  与本轮改动无关，另案挂账）。
- 私有 2020–2024 预检：4585 因子 × 60 期，622 秒，峰值 RSS ~8G；direction 全部
  source=calibration。

## 已知缺口（不阻塞上线，但必须挂账）

1. **退市股因子值未补齐**：`factor_defs/alpha_library/factor1300/alpha360`
   只含当前股票池；2016–2019 每月缺 ~6–8% 行情池。coverage 已量化并标
   `survivorship_bias`，该窗口只能做研究、不得作为验收依据。修复需补齐退市股
   估值/行业上游后重物化。
2. **2016 上半年**无 120 日预热，未回补 2015；首月 2016-07。
3. **classic 不支持增量**（全量约 10–20 分钟，可接受）。
4. **构建中途**年分区是逐年原子写入，整套不是原子切换；重建前先备份
   （本次备份：`data/quantdb/_factor_research_backup_20261110/`）。
5. **产物属主**：容器内构建以 root 写盘，宿主机裸跑会 PermissionError；
   生产走 `POST /build`（容器内）或 `docker exec quantmind python …`，不要 sudo chown 后混跑。
6. **去重相关矩阵**：`cross_corr.npz` 仍是旧 2020–2026 窗口产物；跨时代去重
   需重跑 `build_factor_panel_corr.py`，否则 2016–2019 的去重带未来信息。
7. **TURNVOL 在容器 pandas 2 下个别票 raw=0**（如 002948.SZ 2019H2）：
   `turnover.rolling(60).std()` 的 DataFrame 行为与 pandas 3 不一致；旧快照
   同样存在，不属本轮改动，另案修复。
