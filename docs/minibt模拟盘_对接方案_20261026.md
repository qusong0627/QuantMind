# minibt 策略接入模拟盘：对接方案与验收（2026-10-26）

> 目标：AI-IDE / 回测中心能用的 minibt 策略，也能在**模拟盘**里按自身信号
> 驱动委托；撮合、T+1、涨跌停、台账、风控仍走模拟盘既有链路。
>
> 结论：**已实现**。minibt 策略不再进 on_tick 沙箱（那会静默零信号），
> 改为「侧车算目标股数 → 托管调度器在买入窗口执行」。

## 1. 为什么不能直接进沙箱

沙箱执行模型是 `exec(code)` 后找 `on_tick(context)`；minibt 策略只定义
`Strategy` 子类与 `if __name__ == "__main__": Bt().run()`。沙箱 globals 没有
`__name__`（解析成 `builtins`），`__main__` 块不执行，也没有 `on_tick`——
启动成功、零信号、无报错。因此：`sandbox_manager.submit_strategy` 现在对
minibt 代码**显式拒入**；`/real-trading/start` 按代码形态分流。

## 2. 架构

```
hosted 调度器（trade, py3.10）                minibt 侧车（runner 镜像, py3.12）
  └─买入窗口 14:50 (±90s)                        └─每 2s 轮询请求键
       │  ① 写请求键 qm:sim:minibt:req:...             │
       ├──────────────────────────────────────────────▶│
       │                                         ② 跑一次策略（spawn 子进程，超时即杀）
       │                                         ③ 写目标键 qm:sim:minibt:target:...
       │◀──────────────────────────────────────────────┤
       │  ④ 下一 tick 读目标（≤180s 新鲜）
       └─ SimulationEngine.run_cycle(signals_override, target_quantities)
            └─ 撮合/风控/T+1/台账（原链路，零改动）
```

- 侧车**不下单、不碰账户**；只读 QuantDB（ro）、行情快照（ro）与策略代码（ro）。
- 交易进程与侧车只通过 Redis 通信；键名唯一构造点
  `backend/shared/minibt_sim_keys.py`。
- 侧车容器由 `backend/services/trade/services/minibt_sim_launcher.py` 经
  docker.sock 起停（仅 OSS 单容器部署；无 docker 时显式 400）。

## 3. 关键语义

| 项 | 口径 |
|---|---|
| 决策时点 | 前端配置的 `buy_time`（默认 14:50）；只在买入窗口跑一轮 |
| 预计算 | 买入窗口前 `QM_MINIBT_SIM_PRECOMPUTE_LEAD`（默认 90s，约 14:48:30）先请求侧车算目标，14:50 第一拍直接执行；预计算失败则退化为 14:50 请求、下一拍（约 +30s）执行 |
| 决策频率 | **每日一次**；minibt 运行时会忽略 `rebalance_days`（模型组合用的节奏，套到信号策略会把信号推迟 N-1 天），日志显式记录 |
| 信号输入 | 日线历史（QuantDB `daily_forward`，截至昨日）+ **当日实时快照合成今天这根 K 线** |
| 目标输出 | 回测最后一根 K 线的 `positions`（股数）；负值（裸卖空）按 0 + `short_unsupported` |
| 执行 | `target_quantities={symbol: 股数}`，**只管理该标的**；账户里其它策略/历史持仓一律不碰（实测反例：不加作用域会把 78 只无关持仓全部清仓） |
| 目标 0 | 生成清仓卖单；跌停也生成，由撮合层拒绝并留痕，不在规划层静默丢弃 |
| 拒单/风控 | 全部走 `OrderRouter`→`risk_gate`→`ashare_matcher`；与模型信号路径同一套 |
| 费用/滑点 | 用模拟盘费率与撮合口径；minibt 自己的 `percent_commission` 不参与执行 |

## 4. 数据口径（易错点）

- **成交量**：快照/序列 `volume` 为**手**，QuantDB 日线为**股** → `×100`。
- **成交额**：QuantDB A 股日线 `amount` 实测为**万元**（600036 2026-10-23：
  516,087 万元）；TDX 桥序列同为万元，不换算。缺字段时按
  `close × volume股 ÷ 10000` 补。
- **快照读取**：Hash 四形（`600036.SH` / `600036.sh` / `sh600036` /
  `SH600036`）→ 都 miss 则回退 `market:series:*` ZSET 最新一条
  （收盘后 Hash TTL 300s 会消失，序列仍在）。
- **新鲜度**：快照年龄 > 180s / 缺时间戳 / 现价非法 → 目标写 error，
  调度器按 `minibt_target_error` 显式跳过；**绝不用旧价伪造 K 线**。

## 5. 生命周期

- **启动**：`/real-trading/start` 检测 `import minibt` → 校验 AST 闸门 →
  起侧车容器 → active_strategy 写 `runtime=minibt`、`minibt.container_id`。
  准备度门禁对 minibt **跳过**「默认模型 / 信号就绪 / 沙箱进程池」三项
  （策略自供信号），保留 Redis/DB/行情检查；docker 与 runner 镜像在启动时
  单独校验。REAL 模式显式 400（本批只接模拟盘）。
- **上传策略**：`runtime_strategy_id` 记录有效的策略标识（无库内 id 时用
  文件名），重启恢复/停止/调度都用它，不依赖被截断的 `code_str`。
- **首次建仓**：跳过模型信号的 bootstrap；等下一个买入窗口评估（响应里
  `bootstrap_skipped_reason=minibt_waits_for_decision_window`）。
- **状态**：心跳键（30s 续期/TTL 120s）优先，容器 inspect 兜底；返回
  `runtime` 字段。
- **停止**：停容器 + 删目标/请求/心跳键 + 删代码快照。
- **重启恢复**：`simulation_runtime_restorer` 读落盘代码快照重新起容器；
  快照缺失保留 active 键并显式 `not_running`（不静默丢绑定）。
- **09:35 模型调度**：识别 `runtime=minibt` 的账户并跳过，避免两套信号
  双重驱动。

## 6. 已知边界（MVP）

1. **仅 A 股、日线、单标的**：解析策略顶层 `SYMBOL = '...'`；多标的/分钟线
   策略暂不支持（侧车只补一根日线）。
2. **仅模拟盘**；实盘需另接真单链路（本批显式拒绝）。
3. 决策用 14:50 的现价当今日收盘，与回测「15:00 收盘价」有几分钟差异；
   成交价仍取执行时实时价。
4. 全量回测每次 2–4s（1.3.3 比 1.2.7 慢约 6 倍），在 90s 触发窗内。
5. 纯指标策略（无 `next`/无交易）目标恒 0，等于空跑；应在启动前拦截或提示。
