# 推理中心三市场统一 + 美股版（含个股预测）设计方案

> 目标：推理中心按市场区分 A 股 / 港股 / 美股，覆盖「市场截面推理」与「个股预测」两条链路；
> 沿用个股终端那次已验证的做法 —— **先抽共享层，再加市场**。

---

## 一、结论先行

1. **原状是二分支 fork**：`InferenceCenterPage`（A 股 1013 行）与 `InferenceCenterHkPage`（港股 1010 行）
   互相复制，diff 291 行（≈30%），且**双向漂移**；`App.tsx` 的 `InferenceCenterByMarket` 只判 HK，
   **切到美股渲染的是 A 股页**（默认 SH600519、货币 ¥、A 股联想表、SSE 日历）。
2. **收敛为一个共享实现 + 三份约 50 行的适配器**（`features/inference-center-shared/`），
   双向漂移的功能按**并集**在三个市场都有。
3. **美股个股预测原本必崩**：后端 `predict_single_stock(market='US')` 的第一步就查
   `stock_daily_latest_us`，而**这张表在库里根本不存在**（只有 CN 与 HK 两张）。
4. **交易日历对美股/港股一直是静默错的**：`get_market('NYSE')` 抛错被吞 → 交易日判断退化为
   「只看周末」→ 实测美国独立日（2026-07-03）被判为交易日。
5. **美股模型拆分有三处缺陷**：13 个算法只有 6 个能真正加载、13 份 `pred.parquet` 逐字节相同、
   xgboost 因 `best_iteration` 缺失必失败。

## 二、现状实测

### 2.1 前端双向漂移

| 功能 | A 股版 | 港股版 |
|---|---|---|
| 基准日回退后同步输入框 + 提示 | 有 | 无 |
| 个股 K 线含基准日之后的真实走势 | 有（窗口 `基准日-100天`） | 无（只拉 60 天） |
| `forecast_warning` 告警条 | 有 | 丢弃 |
| 多模型分数曲线 `ModelScoreCurveGrid` | 有 | 无 |
| 评级徽标 / SHAP 因子归因 / 共识矩阵 | 无 | 有 |

另有两处小 bug：港股页市场 Tag 带字面引号；两页的 `initialTopTab` 是死三元。

### 2.2 美股数据家底（实测）

- **模型**：14 条（13 个单算法子模型 + 1 个多模型父记录），全部 `ready`，各有 `pred.parquet`。
- **信号**：`engine_signal_scores` 有 **460 行 `universe_tag='US'`**，但只有 **2026-09-11 一天**
  （BUY 92 / SELL 92 / HOLD 276）。
- **pred 历史**：192,771 行 / 502 只 / 398 个交易日（2025-01-02 ~ 2026-08-05）——
  这是覆盖度与分数曲线的真实来源。
- **质量/批次**：`qm_model_inference_quality` 无 US 行、`qm_model_inference_batches` 无 US 批次、无 US 默认模型。

### 2.3 必须修的后端缺陷

| # | 问题 | 根因 | 后果 |
|---|---|---|---|
| 1 | 个股预测对美股必崩 | `_get_sdl_table('US')='stock_daily_latest_us'`，表不存在 | `UndefinedTableError` |
| 2 | 美股 K 线为 0 根 | `/research/kline` 只分 `is_hk` 与 A 股 | 静默空图 |
| 3 | pred 直读取错标的 | `re.sub('[^0-9]','',symbol)` 对 AAPL 得空串，SQL 对所有 ticker 成立 | 实测 AAPL 取到 -0.047（真值 +0.022） |
| 4 | 分数曲线读不到 pred | `_load_stock_pred_history` 的 `code6` 为空即提前返回 | 只剩 1 个点 |
| 5 | 交易日历认不出 NYSE/HKEX | `ALL_MARKETS` 只有 `XNYS` 等代号，前端传惯用名 | 静默退化为「只看周末」 |
| 6 | 模型拆分三缺陷 | 拆分时未重写 `model_class_name`/`best_iteration`；`pred.parquet` 被当共享产物复制 | 13 个算法只有 6 个能跑；曲线 13 条同线 |

**已知限制（不粉饰）**

- **预测扇形（P10/P50/P90）依赖模型的分位推理能力**，美股当前模型不产出完整分位 →
  `forecast_curve` 为空，个股预测只显示 K 线 + 分数 + 评级 + 共识 + 归因，不显示预测扇形。
  UI 已按空态降级并给出说明文案。
- **美股信号只有 1 天**（2026-09-11）→ 推理历史面板只有 1 条 run，分数曲线只有 1 个点。
  这是数据现状，页面如实展示，不伪造历史。
- 美股 `qm_model_inference_quality` 无记录 → 质量/IC 面板为空态。
- `nativetft` 子模型目录没有 `pred.parquet`（模型本身能跑，实测出分 0.048311），
  其分数曲线会回退到信号表。根因是 `DLAdapter.run_nativetft(single=True)` 的返回键与训练保存段
  读取的键不一致（`full_pred_df` vs `pred_df`）导致**静默跳过**；已修，但只对下次训练生效。

### 发现但未修（需要决策，不属本次范围）

**`score_direction` 反转是死代码** —— 训练把方向写进 `metrics.score_direction`，而推理模板读的是
**顶层** `meta["score_direction"]`（训练从不写顶层），于是模板里的 `scores = -scores` **永不执行**。

实测：所有模型产物顶层均为 absent；`metrics.score_direction` 为 `reversed` 的有 **5 个美股模型**
（random_forest / catboost / xgboost / mlp / lightgbm，CN/HK 均为 normal）。
这 5 个模型的验证 IC 为负、本应翻转符号，实际没有 → **它们给出的分数符号是反的**
（如 mlp 实测 -0.144，按设计翻转后应为 +0.144）。

修法是模板改读 `metrics.score_direction`（或训练补写顶层），但**会改变这些模型的输出语义与已落库信号**，
因此没有顺手改，留待单独立项决策。

## 六、为什么这样设计（可维护性）

1. **一处改动三市场生效**：顶栏、两个 Tab 的状态机、四个展示组件都只有一份。
2. **市场差异在适配器边界**：共享组件里不写 `if (market === 'US')`；后端返回字段不同也在适配器里翻译。
3. **取数不复用坏路径**：美股 K 线与联想走美股终端已交付的端点，而不是去改 A 股/港股共用的老接口 ——
   既有零回归的收益，也把「美股口径」集中在一个已经测过的地方。
4. **加第 N 个市场清单固定**：写一个适配器 → `App.tsx` 加一个分支 → E2E 的 `MARKETS` 加一项。
