# 推理中心三市场统一 + 美股版（含个股预测）设计方案

> 目标：推理中心按市场区分 A 股 / 港股 / 美股，覆盖「市场截面推理」与「个股预测」两条链路；
> 沿用个股终端那次已验证的做法 —— **先抽共享层，再加市场**。

---

## 一、结论先行

1. **原状是二分支 fork**：`InferenceCenterPage`（A 股 1013 行）与 `InferenceCenterHkPage`（港股 1010 行）
   互相复制，diff 291 行（≈30%），且**双向漂移**；`App.tsx` 的 `InferenceCenterByMarket` 只判 HK，
   **切到美股渲染的是 A 股页**（默认 SH600519、货币 ¥、A 股联想表、SSE 日历）。
2. **收敛为一个共享实现 + 三份约 50 行的适配器**（`features/inference-center-shared/`），
   双向漂移的功能按**并集**在三个市场都有。
3. **美股个股预测原本必崩**：后端 `predict_single_stock(market='US')` 的第一步就查
   `stock_daily_latest_us`，而**这张表在库里根本不存在**（只有 CN 与 HK 两张）。
4. **交易日历对美股/港股一直是静默错的**：`get_market('NYSE')` 抛错被吞 → 交易日判断退化为
   「只看周末」→ 实测美国独立日（2026-07-03）被判为交易日。
5. **美股模型拆分有三处缺陷**：13 个算法只有 6 个能真正加载、13 份 `pred.parquet` 逐字节相同、
   xgboost 因 `best_iteration` 缺失必失败。

## 二、现状实测

### 2.1 前端双向漂移

| 功能 | A 股版 | 港股版 |
|---|---|---|
| 基准日回退后同步输入框 + 提示 | 有 | 无 |
| 个股 K 线含基准日之后的真实走势 | 有（窗口 `基准日-100天`） | 无（只拉 60 天） |
| `forecast_warning` 告警条 | 有 | 丢弃 |
| 多模型分数曲线 `ModelScoreCurveGrid` | 有 | 无 |
| 评级徽标 / SHAP 因子归因 / 共识矩阵 | 无 | 有 |

另有两处小 bug：港股页市场 Tag 带字面引号；两页的 `initialTopTab` 是死三元。

### 2.2 美股数据家底（实测）

- **模型**：14 条（13 个单算法子模型 + 1 个多模型父记录），全部 `ready`，各有 `pred.parquet`。
- **信号**：`engine_signal_scores` 有 **460 行 `universe_tag='US'`**，但只有 **2026-09-11 一天**
  （BUY 92 / SELL 92 / HOLD 276）。
- **pred 历史**：192,771 行 / 502 只 / 398 个交易日（2025-01-02 ~ 2026-08-05）——
  这是覆盖度与分数曲线的真实来源。
- **质量/批次**：`qm_model_inference_quality` 无 US 行、`qm_model_inference_batches` 无 US 批次、无 US 默认模型。

### 2.3 必须修的后端缺陷

| # | 问题 | 根因 | 后果 |
|---|---|---|---|
| 1 | 个股预测对美股必崩 | `_get_sdl_table('US')='stock_daily_latest_us'`，表不存在 | `UndefinedTableError` |
| 2 | 美股 K 线为 0 根 | `/research/kline` 只分 `is_hk` 与 A 股 | 静默空图 |
| 3 | pred 直读取错标的 | `re.sub('[^0-9]','',symbol)` 对 AAPL 得空串，SQL 对所有 ticker 成立 | 实测 AAPL 取到 -0.047（真值 +0.022） |
| 4 | 分数曲线读不到 pred | `_load_stock_pred_history` 的 `code6` 为空即提前返回 | 只剩 1 个点 |
| 5 | 交易日历认不出 NYSE/HKEX | `ALL_MARKETS` 只有 `XNYS` 等代号，前端传惯用名 | 静默退化为「只看周末」 |
| 6 | 模型拆分三缺陷 | 拆分时未重写 `model_class_name`/`best_iteration`；`pred.parquet` 被当共享产物复制 | 13 个算法只有 6 个能跑；曲线 13 条同线 |

**已知限制（不粉饰）**

- **预测扇形（P10/P50/P90）依赖模型的分位推理能力**，美股当前模型不产出完整分位 →
  `forecast_curve` 为空，个股预测只显示 K 线 + 分数 + 评级 + 共识 + 归因，不显示预测扇形。
  UI 已按空态降级并给出说明文案。
- **美股信号只有 1 天**（2026-09-11）→ 推理历史面板只有 1 条 run，分数曲线只有 1 个点。
  这是数据现状，页面如实展示，不伪造历史。
- 美股 `qm_model_inference_quality` 无记录 → 质量/IC 面板为空态。
- `nativetft` 子模型目录没有 `pred.parquet`（模型本身能跑，实测出分 0.048311），
  其分数曲线会回退到信号表。根因是 `DLAdapter.run_nativetft(single=True)` 的返回键与训练保存段
  读取的键不一致（`full_pred_df` vs `pred_df`）导致**静默跳过**；已修，但只对下次训练生效。

### 已修：`score_direction` 反转曾是死代码（2026-09-13）

训练把方向写在 `metrics.score_direction`，而推理模板读的是**顶层** `meta["score_direction"]`
（训练从不写顶层）→ 模板里的 `scores = -scores` **从未执行**。实测 `metrics.score_direction='reversed'`
的有 **5 个美股模型**（xgboost / mlp / random_forest / lightgbm / catboost，其训练期验证集 IC 均为负），
它们的分数一直是反的，且**界面上完全看不出来**。

修法分三层（只改模板不够 —— 个股预测与分数曲线是直读 `pred.parquet` 的）：

| 层 | 改动 |
|---|---|
| 推理脚本 | 两个模板 + 训练端内嵌兜底脚本改读 `metrics.score_direction`（顶层为兼容） |
| 训练写入 | 反向模型的 `pred.parquet` / `pred.pkl` / `pred_{算法}.parquet` **写出时就取负**，与平台「正分=看涨」一致 |
| 存量产物 | 一次性迁移 `backend/scripts/fix_pred_score_direction.py`（幂等：写 `pred_direction_applied` 标记；同时处理训练任务工作区里的同名文件，避免重跑拆分又带回错符号） |

验证：5 个模型验证集 rank IC 由负转正（如 xgboost −0.0292 → **+0.0292**）；
实跑推理分数精确翻转（xgboost +0.000201 → −0.000201、mlp −0.144136 → **+0.144136**）；
`backend/tests/test_score_direction.py` 12 项通过（含真实产物断言与源码守卫）；
美股个股预测 E2E 仍 12/12。

> 注：这 5 个模型的验证集 IC 量级很小（0.001~0.03），**按验证集符号翻转本身是在拟合噪声** ——
> 本次改动只是让代码兑现既有设计，是否该对这类近零 IC 模型做方向翻转，值得另行讨论。

## 六、为什么这样设计（可维护性）

1. **一处改动三市场生效**：顶栏、两个 Tab 的状态机、四个展示组件都只有一份。
2. **市场差异在适配器边界**：共享组件里不写 `if (market === 'US')`；后端返回字段不同也在适配器里翻译。
3. **取数不复用坏路径**：美股 K 线与联想走美股终端已交付的端点，而不是去改 A 股/港股共用的老接口 ——
   既有零回归的收益，也把「美股口径」集中在一个已经测过的地方。
4. **加第 N 个市场清单固定**：写一个适配器 → `App.tsx` 加一个分支 → E2E 的 `MARKETS` 加一项。

## 七、机构级验收与改造（2026-09-20）

面向「生产环境里点下去就必须出结果」重新过了一遍：**活体验收 → 就绪体检 → 修复 → 探针回归**。

### 7.1 三种验收口径（都可复跑）

| 口径 | 回答什么问题 | 怎么跑 |
|---|---|---|
| 活体功能验收（50 项） | 每个按钮点下去真实发生什么 | 手工 + Playwright 探针 |
| UI ↔ API 对账探针 | 屏幕上的数字与接口真值是否一致 | `node electron/tests/probe_ic_*.mjs` |
| 全量就绪体检 | 77 个在册模型里，此刻有几个真能跑 | `python backend/scripts/diagnose/model_readiness_audit.py` |

就绪体检分两档，**必须一起看**：`[结构]` 不看日期（暴露资产/口径问题），
`[含时效]` 叠加日期范围（等价于用户点击那一刻）。差集就是「模型没问题、它依赖的数据没跟上」。

### 7.2 结论：此刻有几个模型能跑（2026-09-20 实测，77 个在册）

| 口径 | 就绪 | 模型目录不存在 | 因子库时效不足 |
|---|---|---|---|
| 结构 | **54** | 23 | — |
| 含时效 | **27** | 23 | 14 US + 13 HK |

- 23 个 `模型目录不存在`：注册行指向已被清走的目录，路径仍停在历史账号段
  （`/users/default/admin/` 13 个、`/users/default/00000001/` 10 个）——**注册表没跟上账号口径迁移**，
  应归档这批死行或重新注册实际产物。
- **所有 HK/US 模型被卡在因子库停更**（与代码无关）：`quanthk/6_ml_datasets/l1_factors`
  最新分区 `2026-09-16`（缺 09-17、09-18 两个交易日）、`quantus/.../l1_factors` 最新 `2026-09-17`
  （缺 09-18）；`quantdb`/`quantcustom` 已到 `2026-09-18`。**处置：重跑港股/美股同步**。
  注意同步标记只证明「派发过」，不证明「跑成了」——09-18 的 Redis
  `stop-writes-on-bgsave-error` 曾让派发失败且当天不再重试（已改为 send 成功后才写标记）。

### 7.3 本次修掉的「用不了」

| 现象 | 根因 | 落点 |
|---|---|---|
| 切市场后预检全红、「立即执行」置灰 | 预检 describe 缓存键只有 `source`，不含数据目录，CN 的 schema_hash 污染 HK/US | `script_runner`（键已含 `data_dir::market::source`） |
| quantcustom 模型 ready 但点不动 | `schema_hash` 只哈希**列名集合**，273→282 列多出 9 个 OHLCV 基础列即锁死 | 改为「缺列才硬失败，漂移只出软提示」 |
| 港股 `02057.HK` / `700.HK` 查空、5 位代码跨市场串号 | `to_hk_suffix` 对任何 `.HK` 结尾直接 return，漏过补零/裁零/大写归一 | `stock_utils.to_hk_suffix` + 前端 `utils/marketSymbol.ts`（分市场归一唯一入口） |
| 多模型共识恒为 1 | 日更批推理只跑「生效模型」一个，信号表天然每标的每日 1 行 | `predict-stock` 的 `consensus_model_ids` + `execute` 现场补算（上限 4） |
| HK/US 模型整片被标「缺权重」 | 权重按写死文件名匹配，真实产物是 `model_<算法>.<后缀>` | `model_assets`：按后缀匹配 + 排除 `pred*` 转储 |
| 分位/IC 面板显示捏造数值 | 无 IC 记录时兜底 `or 0.128` | 改为 `None`，前端按「—」渲染 |

### 7.4 剩余缺口（未处置，按优先级）

1. **HK/US 个股分数曲线仍回落信号表**：`get_default_model(market=...)` 要求
   `is_default=TRUE AND 市场匹配`，账户里只有一个默认模型（CN），故 HK/US 恒为 `None`
   → 曲线走 `engine_signal_scores`（实测 AAPL 只有 1 点 @2026-09-10、0700.HK 245 点止于 09-03）。
   CN 走 pred.parquet 已正常（600519.SH 484 点，2024-09-20→2026-09-18）。
   **建议**：在分数曲线调用点做「无该市场默认模型时，取该市场最近激活且带 pred.parquet 的模型」，
   并在响应里回传实际使用的 model_id（不要静默换源）。
2. **分位扇形**：需要 `metadata.quantile_models`，57 个模型 0 个有 → 面板恒空。
3. **SHAP 对非树模型**：37/57 是 pytorch，现改为返回失败码而非空白（不再静默），但归因本身仍不可用。
4. **T+N 周期分布不均**：HK 全 T+1、US 全 T+5、CN 以 T+5 为主，T+3 一个模型都没有；
   选择器现在按模型真实周期置灰/联动，跨周期对比仍需先训练对应周期模型。
