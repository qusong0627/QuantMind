# 评估与打分体系设计方案（因子 · 模型 · 策略 · 选股 · 账户）

> 版本：v1（2026-09-15）　配套：`docs/统一交易栈_设计方案.md`（v3）、`docs/模型量化细则_设计方案.md`
> 目标：一套**专业、统一、可比较**的评估打分系统——回答"这个模型/策略/今天的选股，到底好不好？好多少？能不能上生产？"
> 已有资产：`model_ic_monitor.py`（滚动 IC）、`factor_quality.py`（PFS+DH 质量闸门）、模型卡（train/val/test 静态指标）、confidence_level、回测报告。

---

## 一、设计原则

1. **分对象、分时相**：五类对象（因子/模型/策略/选股/账户）× 三个时相（事前准入 → 事中监控 → 事后复盘）。
2. **客观可复现**：所有分数由脚本从数据算出，输入（数据版本/参数）留档，同输入必同分。
3. **可比较**：统一 0–100 分制；**同批比较用截面分位**（本期所有模型/策略里排第几），**跨期比较用绝对阈值**（防"矮子里拔将军"）。
4. **分数即门槛**：打分不是看板装饰——**晋级/降级/告警直接由分数驱动**（策略上模拟/上实盘、模型上线/降仓、选股是否进入调仓计划）。
5. **多维度+一票否决**：总分 = 加权维度分；任一"红线维度"不合格 → 总分封顶（如成本后为负 → 最高 59 分）。

## 二、五类对象的评分卡

### 2.1 因子评分卡（已有基础，接线即可）

| 维度 | 指标 | 权重 | 红线 |
|---|---|---|---|
| 预测力 | RankIC / ICIR | 30 | ICIR < 0.2 |
| 稳定性 | 子样本 IC 方差 / 半衰期 | 20 | 半衰期 < 2 日 |
| 独立性 | 与存量因子最大相关 | 15 | 相关性 > 0.9 去重 |
| 质量闸门 | PFS（扰动保真）/ DH（多样性增益） | 20 | PFS 不达标 |
| 覆盖 | 覆盖率 / 缺失率 | 15 | 覆盖 < 60% |

### 2.2 模型评分卡

| 维度 | 指标 | 权重 | 红线 |
|---|---|---|---|
| OOS 预测力 | 样本外 RankIC / ICIR | 30 | IC < 0.02 或 ICIR < 0.3 |
| 分层能力 | Q1–Q5 单调性 + 分层价差 | 25 | 非单调 |
| 稳健性 | 子样本（牛/熊/震荡）表现 | 15 | 任一子样本崩坏 |
| 滚动健康 | 近 20/60 日滚动 IC 衰减（`model_ic_monitor`） | 15 | 20 日均值 < 0.01 |
| 换手与成本 | 换手率 + 成本后组合收益 | 15 | 成本后 ≤ 0 |

### 2.3 策略评分卡（回测+模拟+实盘三段合一）

| 维度 | 指标 | 权重 | 红线 |
|---|---|---|---|
| 收益 | 年化 / 超额（对基准） | 20 | — |
| 风险 | 最大回撤 / Calmar / 波动 | 20 | MDD > 阈值 |
| 稳定性 | 月度胜率 / 滚动 Sharpe | 15 | 连续 3 月负 |
| 成本 | 换手率 + 成本占比 | 15 | 成本吃掉 > 50% 毛利 |
| 一致性 | **回测↔模拟实盘跟踪误差**（§粒度对齐） | 20 | 误差 > 阈值（晋级红线） |
| 容量 | 容量粗估 / 参与率 | 10 | 目标资金 > 容量 |

### 2.4 每日选股评分（"今天的选股好不好"）

| 维度 | 指标 | 说明 |
|---|---|---|
| 事前质量 | 信号强度（rank_pct 分布）、行业分散、板块状态 | 当日推理完成即算 |
| 事后验证 | T+1…T+H 实际收益 vs 基准（超额）、命中率、盈亏比 | 滚动 T+H 日回填 |
| 一致性 | 实际买入 vs 计划清单差异（执行偏差） | 执行端产出 |
| 校准 | 分数分档 vs 实际收益的分层单调（分数校准曲线） | 月度 |
| 覆盖 | 入选数/空仓判断与市场状态匹配 | 每日 |

输出：**当日选股评分（0-100）+ 评级（A/B/C/D）+ 每条入选的贡献分**，次日自动回填事后验证。该分数直接决定"调仓计划"里的执行力度（A 级正常执行，C 级减半仓，D 级跳过——可配置）。

### 2.5 账户/组合评分卡

| 维度 | 指标 |
|---|---|
| 风险暴露 | 行业/风格暴露、集中度（前 5 持仓占比）、净敞口 |
| 归因 | Brinson：行业配置 / 选股 / 择时 贡献（模型细则 §九） |
| 风控事件 | 拦截次数/类型、状态机迁移史、误杀率 |
| 资金效率 | 仓位利用率、现金拖累 |

## 三、打分方法（统一算法）

```
1) 每维度指标 → 得分映射：
   - 截面模式：本期同批对象的该指标做分位映射（0-100，防单一异常值 → winsorize 5%/95%）
   - 绝对模式：阈值表线性/阶梯映射（用于跨期与红线判定）
2) 总分 = Σ(维度分 × 权重)，红线维度不合格 → 总分封顶（min(总分, 59)）
3) 评级：A ≥85 / B 70-84 / C 60-69 / D <60
4) 置信标注：样本量不足（n < 阈值）→ 分后加 "†"（低置信），不参与自动晋级
```

**分数联动（关键设计）**：

| 对象 | A/B | C | D |
|---|---|---|---|
| 模型 | 可绑策略 | 观察/降权 | 降仓建议 |
| 策略 | 可晋级下一环境 | 降仓观察 | 暂停 |
| 每日选股 | 正常执行 | 减半 | 跳过 |

## 六、回测体检（Backtest Health Check，对标 QSX Strategy Score 类工具）

**定位**：策略评分卡（§2.3）回答"策略多好"，回测体检回答一个更前置的问题——**"这条曲线可信吗"**。输入一条净值曲线（+可选交易日志+基准），输出四分类判定：

| 判定 | 含义 | 判定依据（统计） |
|---|---|---|
| **真 alpha（A）** | 收益来自可重复的选股/择时能力 | alpha 显著（t>2）且 **DSR 通过**、跨 regime 稳健、成本后仍显著、样本 ≥ MinTRL |
| **Beta 主导（B）** | 收益主要来自市场/风格暴露 | 对基准+风格因子回归 R² 高；alpha 不显著或 alpha 占收益 <30% |
| **运气（L）** | 看着好，但统计上站不住 | 多重检验校正后不显著（DSR < 0.95 门槛）；或 bootstrap 置信区间跨 0；或**收益集中在少数几天/几笔**（剔除 Top5 交易日/交易后超额消失） |
| **证据不足（E）** | 样本/数据不够下结论 | 样本长度 < MinTRL；交易笔数 < 阈值（如 30）；缺交易日志无法做集中度检验；区间未覆盖至少一个完整牛熊周期 |

### 6.1 统计工具箱（九项检验，全部要落实现）

| # | 检验 | 回答什么问题 | 关键输入 |
|---|---|---|---|
| 1 | **因子回归**（CAPM + 市值/价值/动量风格） | alpha 还是 beta？ | 净值序列 + 基准 + 风格因子序列 |
| 2 | **DSR 紧缩夏普** | 扣掉"我试了很多参数"后还显著吗？ | Sharpe、样本长度、偏度峰度、**试验次数 N**（从参数扫描记录取） |
| 3 | PSR 概率夏普 | Sharpe > 0 的概率 | 同上 |
| 4 | **MinTRL 最短样本** | 要多少年才能证明它不是运气？ | 目标 Sharpe、置信水平 |
| 5 | **PBO 回测过拟合概率**（CSCV） | 参数优化的过拟合程度 | 参数扫描结果矩阵（有则必跑） |
| 6 | Block Bootstrap | 收益分布的置信区间（保留自相关） | 收益序列 |
| 7 | **收益集中度** | 靠的是能力还是几笔神操作？ | 净值 + 交易日志（剔 Top 收益重算） |
| 8 | 跨 regime 分段 | 牛/熊/震荡下都活着吗？ | 净值 + 市场状态历史 |
| 9 | 成本敏感性 | 换手×费率上浮后还剩多少？ | 换手率 + 费用模型 |

### 6.2 输出（体检报告）

```
结论标签：⚠ 运气嫌疑（L）          可信度分：42/100
────────────────────────────────────
alpha 回归: 年化 alpha 8.2%, t=1.31 ✗ 不显著; R²=0.71（beta 主导特征）
DSR: 0.61 < 0.95 （曾扫描 240 组参数，需更强证据）
集中度: 剔除最好 5 天后超额从 +12% → -3% ⚠
样本: 15 个月 < MinTRL(28 个月) →勉强进入 E 区
建议: ①延长样本 ②减少参数扫描 ③核对是否有事件依赖
```

- **简单模式**（消费者）：一个标签 + 三句话解释 + 一个建议（"再观察 8 个月"）。
- **专业模式**：全部九项数值 + 分布图 + 可下载 JSON。
- **自助体检入口**（产品化）：像 QSX 那样支持**上传净值曲线/交易日志**（CSV/图片OCR/接口），几分钟出报告——既是用户功能，也是我们自己的晋级门禁。

### 6.3 系统集成（三处强制）

1. **回测完成自动体检**：R2 精确回测产出净值后自动跑九项 → 报告附在证据卡（`evidence.health`）。
2. **晋级门禁**：策略进 SIM 前，体检结论必须为 A 或 B（且 B 需标注收益来源）；L/E 不得晋级。
3. **定期复检**：实盘/模拟策略每月自动体检一次（曲线增长后结论可能变化：E→A 或 L→L 坐实）。

## 七、全链证据矩阵（"每环有数、每数可验、每验留档"）

用户原则：**每个环节都要有数据验证**。全链每环的"体检项 + 证据产物"统一如下：

| 环节 | 验证什么 | 证据产物 | 频率 | 不合格动作 |
|---|---|---|---|---|
| 数据 | 完整性/PIT/质量六项 | 数据质检报告 | 每日 | 阻断下游 |
| 特征 | 覆盖/漂移/未来扰动测试 | 特征体检表 | 每日/训练前 | 阻断训练 |
| 模型 | IC/分层/DSR 类检验/契约 | 模型卡 | 训练后+每日滚动 | 降权/停绑 |
| 信号 | 分布/就绪/一致性 | 信号日报 | 每日 | 红灯告警 |
| **回测** | **九项体检（§六）** | **体检报告** | 每次回测 | **阻断晋级** |
| 模拟 | 跟踪误差/成交偏差 | 模拟对照报告 | 每日 | 降仓建议 |
| 执行 | IS/滑点/成交率/撤单率 | 执行报告 | 每日 | 参数调整 |
| 账本 | 对账零差异 | 对账报告 | 每日 | 红点告警 |
| 策略 | 五维评分卡 | 策略卡 | 每周+事件触发 | 降级/暂停 |
| 系统 | 体检 12 项断言 | 健康卡 | 每日 | 红黄绿告警 |

**呈现统一**：交易台"证据"面板按此矩阵组织，每格红黄绿 + 下钻至报告原文——一屏看清"整条链哪一环没证据"。

## 八、动线与管线简化原则（界面可简单、功能不能少）

- **管线（后端）简单**：一条主干（§主文档），所有 ring 挂契约；用户可见的"管线视图"= 一根进度条（数据✓→特征✓→推理✓→信号✓→计划✓→执行中→已结算），不暴露内部 worker 拓扑。
- **动线（前端）简单**：常见任务 ≤3 步——看结果（打开交易台）/ 订阅策略（一键）/ 写策略（描述→生成→回测）/ 查问题（一键体检）。任何新功能评审时回答："用户几步能用到它？>3 步则重设计"。
- **功能不减**：全部机构级能力保留，收敛进「专业模式」与下钻层；简单模式是默认视图，不是功能裁剪。
