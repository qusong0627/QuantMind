# 因子挖掘文档链：启用开关与 MinerU 通道指南

> 本文面向**部署与运维人员**：说明因子挖掘「上传文档」链路的默认状态、双开关
> 启用步骤，以及 MinerU 云端解析通道的配额、限流与数据出网边界。
> 链路功能：上传 PDF/图片/Office 文档 → MinerU 云端解析 → 提示词整理 →
> RD-Agent 挖掘因子/复现论文 →（物化 → 模型训练）。
> 免责声明见根目录 [DISCLAIMER.md](../DISCLAIMER.md)。

---

## 一、默认状态：整条文档链不渲染、不通

默认构建（未显式注入开关）下：

- 因子挖掘首页 **不出现**「上传文档」输入方式（只有「文字指令」）；
- 挖掘历史 **不出现**「文档解析」Tab（任务中心照常）；
- 后端文档端点（上传 / 列表 / 详情 / 整理 / 预览 / 删除 / 配额 / 统计）一律 `403`，
  响应体带机器可读标记 `detail=doc_mining_disabled`；
- **其它链路不受影响**：文字指令挖掘、任务中心、因子库、回测全照常。

这是「源码入仓 ≠ 功能可见」的刻意设计：代码全部保留，仅收敛入口。

## 二、双开关机制

| | 前端开关 | 后端开关 |
|---|---|---|
| 变量 | `VITE_ENABLE_DOC_MINING` | `ENABLE_DOC_MINING` |
| 生效期 | **构建时**（Vite 内联进 bundle） | 运行期（进程环境变量） |
| 管什么 | 渲染不渲染 | 端点通不通 |
| 唯一读取点 | `electron/src/config/docMiningFlags.ts` | `backend/services/engine/alpha_agent/doc_gate.py`（router 级依赖） |
| 词表 | 三态：显式 `true` / 显式 `false` / 缺省按构建环境（生产=false，开发=true） | **只有 `true`**（`strip().lower()` 归一后精确匹配；`1`/`yes`/`on` 不算开） |

### 组合行为矩阵

| 前端 | 后端 | 结果 |
|---|---|---|
| 关 | 关 | 默认态：无入口、无 API |
| 开 | 关 | UI 渲染，但所有文档调用 403（安全的失败方向：看得见、传不了） |
| 关 | 开 | 无入口；后端通但界面不可达（安全的失败方向） |
| 开 | 开 | 完整文档链可用 |

两个方向失败都是安全的：**启用文档链必须两端同时打开**。

## 三、启用步骤

### 3.1 申请 MinerU Token

1. 注册并登录 <https://mineru.net>；
2. 在 <https://mineru.net/apiManage/token> 创建 API Token；
3. 记下账号的**日页数额度**——平台预算是按「页」计的（`MINERU_DAILY_PAGE_BUDGET`
   默认 1000 是保守值，请按实际套餐调整，见第五节）。

> **三种持有口径**（生效顺序见下）：
> - **服务器级** `MINERU_API_TOKEN`：全体用户共用，费用记在平台账号；
> - **用户自带（云端）**：因子挖掘「解析设置」各自填写（按账号保存，不写进
>   个人档案），费用各记各的账号。批次用哪个凭据建，就用哪个查——用户中途
>   清除，其名下在途文档会定格失败并提示重新配置后重新上传；
> - **用户自带（本地 / 局域网）**：同一处可选 **本地通道**，填自建 MinerU
>   4.x 服务地址（HTTP API），文档不出网、不消耗平台云页数配额。
>
> 生效顺序：**用户本地 > 部署 `MINERU_MODE=local` 硬顶 > 用户云端 > 部署云端**。
> 部署填了 `MINERU_MODE=local` 后，用户云端配置不再生效（隐私承诺，界面明示）；
> 用户自己的本地地址仍可覆盖 URL（如各自指向自己网段的机器）。
> 两边都没有 → 上传 `503`，提示指向因子挖掘「解析设置」。

### 3.2 后端

在 `.env` 注入（`docker-compose.yml` 已预置转发键，只改 `.env` 即可）：

```bash
ENABLE_DOC_MINING=true
MINERU_API_TOKEN=<你的 token>   # 可选：允许用户自带 Token 时可留空
# 可选：整机隐私模式——文档一律走内网 MinerU 服务，用户云端配置不生效
# MINERU_MODE=local
# MINERU_LOCAL_URL=http://192.168.1.10:8000
# MINERU_LOCAL_API_KEY=<内网服务若开鉴权则填>
# MINERU_LOCAL_TIER=          # 缺省档：flash/basic/standard/advanced，留空=服务端默认
```

其余键都有安全默认值（见 3.4 与 `.env.example` 的「因子挖掘文档链」段）。
改完 `docker compose up -d quantmind` **重建容器**拾取环境变量：

> ⚠️ 本 compose 是 `environment` 白名单（无 `env_file`）——不在 compose 里转发的键，
> `.env` 里填了也读不到（静默不生效）。上面这批键都已转发。

### 3.3 前端

前端开关是**构建期**的，改环境变量后必须重新构建与部署：

```bash
VITE_ENABLE_DOC_MINING=true bash scripts/deploy_frontend.sh --allow-doc-mining
```

两道防线都在 `scripts/deploy_frontend.sh` 里：

1. **环境变量闸**：检测到 `VITE_ENABLE_DOC_MINING=true` 而没带 `--allow-doc-mining`
   参数 → 拒绝构建（防「顺手开着环境变量跑部署」）；
2. **产物形态闸**：产物 `assets/*.js` 里内联了 `VITE_ENABLE_DOC_MINING:"true"`
   标记（Vite 构建期把 env 内联进 bundle），没带 `--allow-doc-mining` 就拒绝部署
   （防「构建时忘了去掉开关的历史产物被误发」）。

### 3.4 验收（建议每次改动部署后跑一遍）

**关的方向**：

```bash
# 1) 产物内联标记应为不命中
grep -rqs 'VITE_ENABLE_DOC_MINING:"true"' <web 根>/assets && echo "!! 打开了" || echo "关闭 ✓"

# 2) 文档端点应 403 且 detail 为 doc_mining_disabled（未登录时 401，属正常）
curl -s http://<host>:8000/api/v1/alpha-agent/docs/quota | head -c 200

# 3) 浏览器：因子挖掘首页无「上传文档」；挖掘历史无「文档解析」Tab
```

**开的方向**：

```bash

# 2) 浏览器：首页出现「上传文档 ⇄ 文字指令」切换；挖掘历史出现「文档解析」Tab
# 3) 自动化探针（需本地 vite dev + 后端在跑；注意别用 5173——那是另一个项目的）：
cd electron && PROBE_EXPECT=on node tests/probe_docmining_flag.mjs
```

> 正式上线前的**真 token 全量验收**（主链冒烟、扫描件 OCR、重启续轮询、
> 配额告警演练、失败路径、删除语义、关闭回滚）见
> [文档挖掘_真token验收清单.md](文档挖掘_真token验收清单.md)。

## 四、上传通道与形态上限

请求链：浏览器 → `quantmind-web`(nginx) → api(8000) → engine(8001)。

| 关卡 | 上限 | 出处 |
|---|---|---|
| nginx 请求体 | `210m` | `docker/web/nginx.conf`（**镜像内**，见下） |
| api→engine 代理体 | `ENGINE_PROXY_MAX_BODY_MB`（默认 210） | `backend/services/api/routers/engine_proxy.py` |
| 单文件 | `RD_AGENT_DOC_MAX_MB`（默认 200MB）+ **200 页** | `alpha_agent_docs.py` / MinerU 平台限制 |
| 单次合计（多文件） | `RD_AGENT_DOC_MAX_TOTAL_MB`（默认 200MB）+ **≤20 件** | `alpha_agent_docs.py`（正文+附录/多图一批提交） |
| MinerU 解包 | zip ≤1GB、解压总量 ≤512MB、≤2000 条目 | `mineru_client.py`（Zip-Bomb 闸） |

**多文件合并**：同一字段 `file` 重复提交（顺序=合并顺序，正文在前），一次
MinerU 批次解析后合并为一份 `full.md`（各部分前插入隐藏 HTML 注释形式的
「第 i/N 部分」章节标记，整理链靠它感知边界；图片跨部分按内容去重，同名
不同内容自动改名绝不覆盖）。复用键 = 各文件（原名+内容哈希）顺序拼接的
复合 sha256——换序或改名不命中复用。

**支持的格式与内容定形**（上传件按**内容**判型，不再按后缀一票否决）：

- **直通**：PDF、PNG、JPG/JPEG。扩展名与内容不符时按内容纠尾缀
  （PNG 改名 `.jpg` → 存成 `original.png`），解析不受影响；
- **转码**：WebP / GIF / BMP / TIFF / AVIF 由服务端 Pillow 解**首帧**压制为
  PNG 再入库（MinerU 只吃 png/jpg/jpeg）；动图只取首帧；单图转码上限
  64MB；复用键按**转码后**字节计算；
- **Word/PPT**：docx/pptx（zip 容器）与 doc/ppt（OLE 容器）要求扩展名与
  容器同族——把 docx 改名 `.pdf` 会被拒（400「不符」）；
- **HEIC/HEIF**（iPhone 默认照片格式）：服务端无解码器，一律 400 并给出
  「导出/另存为时选 JPG 或 PNG」的可执行指引；前端在选择文件时先拦同文案；
- **其余无法识别的内容**：400（防「改名成 .pdf 的可执行文件」——落盘仍按
  定型后的 magic 复验一遍）。

⚠️ **合计上限与部署链同口径（默认 200MB）**：nginx 与 api→engine 代理体都卡
同一个请求。要抬到 200MB 以上，三处必须**同时**抬，否则会在外层先吃 413
（nginx 那层还是裸 HTML 错误页）：

1. `RD_AGENT_DOC_MAX_TOTAL_MB`（本容器 env）；
2. `ENGINE_PROXY_MAX_BODY_MB`（本容器 env，要 ≥ 合计 + 余量）；
3. nginx `docker/web/nginx.conf` 的 `client_max_body_size`（**镜像内**，
   需按下方步骤重建 `quantmind-web`）。

前端早拒常量（`electron/src/features/alpha-research/services-v2/docMiningApi.ts`
的 `DOC_MAX_UPLOAD_BYTES` / `DOC_MAX_TOTAL_UPLOAD_BYTES` / `DOC_MAX_FILES`）
也镜像了默认值，抬上限时要一并改并重新构建部署前端。

⚠️ **nginx 上限在镜像里，`deploy_frontend.sh` 管不到**：只 `docker cp` 静态产物。
旧版 `quantmind-web` 镜像（2026-09 之前）的 `client_max_body_size` 是 100M，
大于 100MB 的上传会被 nginx 413 拦下、到不了后端。升级姿势：

```bash
docker build -f docker/Dockerfile.web -t quantmind-web:latest .
docker stop quantmind-web && docker rm quantmind-web
docker run -d --name quantmind-web -p 3080:80 \
  --network quantmind_quantmind-net --restart unless-stopped quantmind-web:latest
```

（`quantmind-web` 是独立 nginx 容器，不在 `docker-compose.yml` 里。）

## 五、配额、限流与告警

三层闸（按**页**计数，北京时间日界）：

| 闸 | 默认 | 变量 |
|---|---|---|
| 平台日预算 | 1000 页/日 | `MINERU_DAILY_PAGE_BUDGET` |
| 单用户日上限 | 200 页/日 | `MINERU_USER_DAILY_PAGES` |
| 频控（整点小时桶） | 上传 30 次/时、整理 60 次/时 | `DOC_UPLOAD_RATE_PER_HOUR` / `DOC_ORGANIZE_RATE_PER_HOUR` |

- 页数预估**保守**：PDF 按实际页数；数不出页数的（docx/图片等）按单文件上限预留，
  解析完成后按实际页数**结算多退少补**；
- **删除/中途放弃的批次同样结到实际**：批次已在 MinerU 建好后删除的行，
  由后台收尾任务盯批次到终态——云端烧了几页就结几页（没交付产物则全退），
  绝不把保守预留（如 docx 的 200 页）原样留在账上（幽灵占账会假性用尽当日
  配额）；已结算过的行收尾自动跳过；
- 同用户同 sha256 命中已解析文档 → 直接复用，**不占配额、不重复提交**；
- 配额耗尽 → 上传 `429`（界面显示后端原文）；
- **告警**：平台余量低于预算 10% 时，向全部管理员发一次站内通知
  （类型「系统」，QQ 告警旁路随之生效），按配额日去重，一天最多一条；
- `MINERU_USER_DAILY_PAGES` 只约束单个用户；调大平台预算前先确认 MinerU 套餐额度。
- **用户自带 Token 的批次同样计入平台页预算与个人日上限**（记账统一、防跑飞；
  页面费用记在用户自己的 MinerU 账号）。平台预算因此成了全体上传量的安全上限：
  用户自带 Token 为主时，按预期总用量调大 `MINERU_DAILY_PAGE_BUDGET`。

## 六、数据出网与留存（重要）

- **原件出网**：上传的文件会送往 MinerU 云端 API 解析。界面上传区有固定披露文案
  （「文档将上传至 MinerU 云端服务」）；面向公网的部署启用此链，等于接受
  「用户上传的文档内容出网」——请先确认合规上可接受。
- **本地留存**：原件与解析产物落在 `RD_AGENT_DOCS_DIR`（默认 `/data/rd_agent_docs`，
  随 `./data:/data` 卷持久化）。
- **留存期**：解析已定型的行（parsed/organized/parse_failed）超过
  `RD_AGENT_DOC_RETENTION_DAYS`（默认 90 天）由 GC 删目录转 `expired`；
  在途（uploaded/parsing）不碰。
- 删除是软删 + 产物目录连根清；已整理草稿文本随行保留在 PG（软删后不可见）。

## 七、故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| 端点 `403 doc_mining_disabled` | 后端开关没开 / 容器没重建拾取 env | 检查 `.env` 与 `docker compose up -d quantmind` 是否执行 |
| UI 无「上传文档」 | 前端构建期开关没开（或部署了默认产物） | 按 3.3 重新构建部署 |
| 上传 `503`（提示解析服务未就绪） | 该用户未配解析通道，且服务器未配默认通道 | 在因子挖掘「解析设置」填写云端 Token 或本地 / 局域网服务地址，或按 3.1/3.2 注入服务器配置后重建容器 |
| 想确认文档确实不出网 | 部署侧 `MINERU_MODE=local` + `MINERU_LOCAL_URL` 可达 | 上传披露与配额条会显示「本地 / 局域网」；生效通道以 `/docs/quota` 的 `mineru_mode` 为准 |
| 文档定格「用户 MinerU Token 已失效」 | 用户提交后清除了自带 Token（批次建在用户账号下，不能换账号续查） | 提示用户重新配置 Token 后重新上传；服务器级 Token 不受影响 |
| 上传 `413` | nginx 100M/210m 旧镜像 或 超 `RD_AGENT_DOC_MAX_MB` / `RD_AGENT_DOC_MAX_TOTAL_MB` | 重建 `quantmind-web` 镜像（见第四节）；多文件合计超限则按第四节「三处同抬」 |
| 上传 HEIC 照片报「暂不能直接解析」 | iPhone 默认格式，服务端无解码器 | 属预期：在「导出/另存为」时选 JPG 或 PNG 再上传（界面文案已给同样指引） |
| 上传报「文件内容与扩展名不符」 | 部署还是旧版后端（2026-10-09 前按后缀+magic 双验，改名图片一律拒） | 重建 quantmind 容器拾取新版：改名/异格式图片现按内容定形（纠尾缀或转码），仅容器族错配与不可识别内容才拒 |
| 文档详情里扩展名与文件名后缀不一致 | 改名/异格式图片按内容定形（PNG 改名 .jpg 纠正为 .png；webp/gif 等转码为 .png） | 正常行为：扩展名以**真正进解析链的内容**为准 |
| 多文件合并产物章节顺序不对 | 上传顺序≠预期顺序 | 属用户操作面：待上传清单里用上移/下移调整（顺序即合并顺序），或删除后按序重选 |
| 上传 `502` | engine 子进程异常 | 看 engine 日志；OSS 单容器由 `main_oss.py` 看门狗自动 respawn |
| 解析失败 `-60018` | MinerU 平台当日额度用尽 | 调大套餐或次日再试；见平台后台 |
| 整理报「LLM 输出被截断」/「只产出推理内容」 | 推理模型（如网关上的 v4-flash）的思考内容计入输出预算（max_tokens），预算被思考耗尽 | 整理链**默认已关推理思考**（`DOC_ORGANIZE_DISABLE_THINKING` 精确 `false` 才是开思考）；仍出现则调大 `DOC_ORGANIZE_FINAL_MAX_TOKENS` / `DOC_ORGANIZE_MAP_MAX_TOKENS`（默认 8192），或改用非推理模型；改后重建容器 |
| 解析卡在 `parsing` 超时 | 网络/下载抖动 | 引擎重启后**自动续轮询**（PG 是权威状态）；超总时限（默认 2h）定格「解析超时」 |
| 配额显示「已用尽」但 MinerU 云端只烧了几页 | 旧版幽灵占账：批次预留（如 docx 200 页）在删除/放弃后无人收尾 | 升级后端到 2026-10-09 后版本（删除后自动盯批次结到实际页数）；已卡住的当日账手工对齐：Redis `qm:docmining:pages:{YYYYMMDD}` 与 `:…:{user_id}` 改成云端实际页数（北京时间日界） |
| 告警收不到 | 无管理员账号 / QQ 未配置 | 站内通知受众是 `users WHERE is_admin`；QQ 见 `qq_notify` 配置 |

## 八、关闭方式

- 后端 `ENABLE_DOC_MINING` 改回 `false`（或删除）→ 重建容器：端点立刻 403；
- 前端去掉 `VITE_ENABLE_DOC_MINING` 重新构建部署：入口消失；
- 两个方向任一关闭都是安全的失败方向，不需要同时操作；
- 已上传数据不会自动清理，按第六节留存策略自然过期，或手动清理
  `RD_AGENT_DOCS_DIR` 与 `rd_agent_docs` 表。
