# 首页六宫格多市场方案（共享层 + 内容分层）

> 目标：首页（导航「A股/港股/美股/期货」那一栏，即路由 `/`）六宫格里的 **6 个框**全部跟随顶部市场切换器，
> 各市场只显示自己的数据；没有数据就明说，绝不拿 A 股数据顶替。
>
> 做法沿用仓库已验证两次的路径（`stock-terminal-shared`、`inference-center-shared`）：
> **先抽共享层，再按市场做内容分层**。

---

## 一、结论先行

1. **现状是「标题市场化、数据钉死 CN」**：切到港股后，`资金概览 (港股/模拟)` 显示的仍是 A 股账户
   ￥1,035,249.58；`实时交易记录 (港股)` 列的是招商银行/正帆科技等 A 股成交；`策略监控` 显示 89 条
   （后端 `?market=HK` 实际只有 15 条）。**标题改了、口径没改**，比不切换更误导。
2. **后端家底比预期好**——三类数据已经有市场维度，只是前端没传：
   - 模拟账户 `GET /api/v1/simulation/account?market=` ✅（CN 有账户；HK/US/FUTURES 返回
     `account_not_initialized: true`，是明确信号，不是 0 元假账户）
   - 策略列表 `GET /api/v1/strategies?market=` ✅（实测 CN 74 / HK 15 / US 0 / FUTURES 0）
   - 账户开通 `POST /api/v1/simulation/reset`（带 `market`）✅ 空态可直接提供「开通」动作
   - **缺**：成交 `/simulation/trades`、成交统计 `/simulation/trades/stats/summary`、通知 `notifications`
     都没有市场维度（表里没有 market 列，市场只隐含在 `symbol` 形态里）。
3. **方案**：新增共享层 `electron/src/features/dashboard-shared/`——
   一个**市场内容注册表**（5 份市场内容 × 6 个框的规格）+ 统一卡头/空态组件。
   6 个卡片**布局与视觉完全不动**，只把数据源换成「带市场参数」的取数，并按规格渲染空态。
   加一个市场 = 加一份内容规格 + （必要时）后端一个过滤参数，README 里写成 5 步清单。
4. **空市场不装样子**：港股/美股/期货暂无模拟盘时显示「未开通 + 一键开通」；暂无成交显示「该市场暂无成交」。
   用户要的是「别骗我」，不是「每格都有数」。

## 二、现状实测（2026-09-13，跑在 localhost:3080 + 后端 8000）

### 2.1 六个体检（组件 → 取数 → 市场维度）

| 框 | 组件 | 取数链路 | 现状 |
|---|---|---|---|
| 市场概览 | `components/modules/MarketOverviewCard.tsx` | `useMarketData({market})` → `/api/v1/market/overview?market=` | ✅ 唯一跟市场切换的 |
| 资金概览 | `FundOverviewCard.tsx` | `useFundData()` → `portfolioService.getFundOverview(u, mode, tenant)` → `/api/v1/simulation/account`（**不传 market**） | ❌ 恒 CN |
| 实时交易记录 | `TradeRecordsCard.tsx` | `useTradeRecords()` → `/api/v1/simulation/trades`（**无 market 参数**） | ❌ 恒 CN |
| 策略监控 | `StrategyMonitorCard.tsx` | `useStrategies()` → `/api/v1/strategies`（**后端已支持 ?market=，前端不传**） | ❌ 恒全量 |
| 智能图表 | `IntelligenceChartsCard.tsx` | `useIntelligenceCharts()` → `getTradeStats` + `getRuntimeAccount`（**都不传 market**）+ `/account/ledger/daily` | ❌ 恒 CN |
| 信息通知 | `NotificationQuickCard.tsx` | `useNotifications()` → `/api/v1/notifications`（**表无 market 列**，参数被忽略） | ❌ 无市场概念 |

### 2.2 接口实测

```
GET /api/v1/simulation/account?market=CN       → total_asset 1035249.58 / 27 持仓
GET /api/v1/simulation/account?market=HK       → {cash:0, total_asset:0, positions:{}, account_not_initialized:true}
GET /api/v1/simulation/account?market=US       → 同上（未开通）
GET /api/v1/strategies?market=CN               → 74 条（63 条 parameters.market='A' + 11 条历史 NULL）
GET /api/v1/strategies?market=HK               → 15 条（全部 parameters.market='HK'）
GET /api/v1/strategies?market=US               → 0 条
GET /api/v1/simulation/trades/stats/summary    → 35 笔；加 ?market=HK 数字不变（参数被忽略）
GET /api/v1/notifications?market=HK            → 901 条，与不传一致（参数被忽略）
```

DB 事实：`sim_trades` / `trades` / `orders` / `notifications` / `simulation_fund_snapshots` 均**无 market 列**，
市场只能由 `symbol` 形态推断；`simulation_accounts` 的 Redis 键已经分市场
（`backend/shared/simulation_account_keys.py`：CN 无后缀，HK/US 加 `:{MARKET}`）。

### 2.3 已有的可复用件（不要重复造）

- `backend/shared/simulation_account_keys.py` — 账户键唯一规范（`normalize_market` / `account_key` / `parse_account_key`）
- `backend/shared/stock_utils.py::StockCodeUtil.detect_market` — 代码 → CN/HK/US，判据互斥且精确（有实测误判的教训注释）
- `backend/services/simulation/services/market_rules.py::infer_market` — 模拟引擎同款推断（含期货/加密）
- `electron/src/config/marketConfig.ts` — 每市场 label / benchmark / currency / calendar（已含 5 个市场）
- `realTradingService.getRuntimeAccount(userId, tenantId, mode, market)` — 已带 market，
  「模拟交易」页 `RealTradingPage.tsx:150` 已在用；首页没用
- `realTradingService.resetSimulationAccount(userId, cash, tenantId, market)` — 空态「一键开通」可直接用

## 三、目标架构

```
electron/src/features/dashboard-shared/          ← 新增：唯一实现（共享层）
├── README.md                 维护手册：加市场 / 加框要动什么
├── types.ts                  BoxId / BoxContent / MarketContent 契约
├── marketContent.ts       ★  内容分层：5 市场 × 6 框的规格（唯一差异声明处）
├── components/
│   ├── BoxFrame.tsx          统一卡头（标题 + 市场徽标 + 数据源标注）与内容容器
│   ├── BoxPlaceholder.tsx    空态四态：加载 / 无数据 / 未开通（带动作）/ 失败
│   └── index.ts
└── hooks/
    └── useMarketBoxes.ts     从 Redux currentMarket 取当前市场内容 + 工具函数

components/modules/*.tsx                         ← 6 个卡片：壳不动，数据换源
```

**契约（types.ts）**

```ts
export type BoxId = 'market' | 'fund' | 'trade' | 'strategy' | 'charts' | 'notify';

export interface BoxContent {
  title: string;            // 卡标题（写清市场，如「资金概览 (港股/模拟)」）
  source: string;           // 数据源标注：QuantDB / QuantHK / QuantUS / QuantFutures
  currency?: string;        // 货币符号（¥ / HK$ / $ / USDT）
  emptyTitle: string;       // 无数据时的标题
  emptyHint: string;        // 无数据时的说明（写清为什么空）
  canOpenAccount?: boolean; // 空态是否给「开通模拟盘」动作
}

export interface MarketContent {
  market: AppMarket;
  label: string;            // A股 / 港股 / 美股 / 期货 / 区块链
  accent: string;           // 卡片徽标主题色
  boxes: Record<BoxId, BoxContent>;
}
```

**数据流**：卡片 → `useMarketBoxes()` 拿本市场内容规格 → 调带 `market` 的取数 hook →
数据为空时按规格渲染 `BoxPlaceholder`（未开通的给开通按钮，开通后 `refresh()`）。

**硬约束（写进 README）**
- 市场差异一律加到 `marketContent.ts`，**不许**在卡片里写 `if (market === 'HK')`
- 任何数值出口挡 null/NaN（历史事故：`null.toFixed` 整页白屏）
- 空就是空：不回落到其它市场数据，也不显示 0 元假账户

## 四、内容分层：每个市场每格显示什么

| 框 | A股 (CN) | 港股 (HK) | 美股 (US) | 期货 (FUTURES) |
|---|---|---|---|---|
| 市场概览 | 上证/深成/创业板/沪深300/中证500/上证50（QuantDB） | 恒指/国企/恒生科技/红筹（QuantHK） | 道指/纳指/标普（QuantUS） | WTI/螺纹/沪金/沪铜…（QuantFutures） |
| 资金概览 | 模拟账户 ¥（已有 103 万） | 未开通 → 一键开通（HK$） | 未开通 → 一键开通（$） | 未开通 → 一键开通（$） |
| 实时交易记录 | 模拟成交（sim_trades，symbol 过滤） | 该市场暂无成交 | 该市场暂无成交 | 该市场暂无成交 |
| 策略监控 | 74 条（含历史 NULL 归 A 股） | 15 条 | 0 条 → 暂无策略 | 0 条 → 暂无策略 |
| 智能图表 | 成交统计 + 实盘台账曲线 | 统计按市场；台账无该市场 → 空态 | 同港股 | 同港股 |
| 信息通知 | 含 A 股代码的通知 + 全局通知 | 含港股代码的通知 + 全局通知 | 含美股 ticker 的通知 + 全局通知 | 全局通知 |

说明：
- **实盘模式**下账户是账户级（`/api/v1/account` 无 market，单一实盘账户），
  资金概览此时显示实盘账户并标注「实盘账户（账户级，非市场级）」；模拟模式才是市场级。
- **信息通知**本轮用「代码形态推断 + 全局分区」（按 `symbol` 形态扫 title/content/action_url），
  明确分「本市场 N 条 / 全局 M 条」；后端加 `notifications.market` 列列为 P2。
- **期货/区块链**同样进注册表（CRYPTO 生产隐藏，规格保留）。

## 五、后端改动（配套，尽量小）

| # | 改动 | 文件 | 说明 |
|---|---|---|---|
| B1 | `/simulation/trades` 与 `/simulation/trades/stats/summary` 加 `market` 查询参数 | `services/simulation/routers/simulation_history.py`、`services/simulation/services/trade_service.py` | 由 `symbol` 形态过滤；判据来自新增的 `market_rules.market_symbol_sql_regex`（与引擎 `infer_market` 同源，单测钉住）。不传 = 现行为（零回归） |
| B2 | 重置模拟盘按市场收窄删除范围 | `services/simulation/routers/simulation.py` | 原实现重置任一市场都 `DELETE FROM sim_trades/sim_orders`（全用户全市场）。新开「按市场开通模拟盘」入口后这会把别的市场成交一起清掉 —— 实测触发过一次。现按 symbol 形态加 `AND symbol ~* :pat` |
| B3 | `/simulation/snapshots/daily` 加 `market`（可选） | `services/simulation/routers/simulation.py` + service | 快照表无 market 列，短期由前端按市场空态处理；列为 P2 |
| B4 | `notifications` 加 `market` 列 + 创建时打标（含历史回填） | `services/api`… 通知写入点 | P2；本轮前端分区兜底 |

**不动**：账户（已支持）、策略（已支持）、开通/重置（已支持）、行情概览（已支持）。

**已知的结构性缺口（本轮未动，风险已登记）**

- **PG 台账没有市场维度**：`simulation_accounts` 唯一索引是 `(tenant_id, user_id)`、`account_id = sim:{tenant}:{user}`，
  且 `trade_shared/simulation_manager.py::_rebuild_from_ledger(user_id, tenant_id, market)`
  **收了 market 却没用**。后果：港股/美股账户的 Redis 键一旦丢失（重启/淘汰），会被 A 股台账投影重建 → 跨市场串仓。
  修复要给 ledger 主键加市场段并迁移回填，成本最高，单独排期。
- **资金快照只统计 A 股**：`fund_snapshot_service.py` 显式跳过带 `:MARKET` 后缀的账户
  （快照表唯一约束 `(tenant_id, user_id, snapshot_date)`，跨市场会互相覆盖）。
  这就是非 A 股关掉「资金曲线/持仓分布」子面板的原因。
- **实盘账户快照无市场维度**：`RealAccountSnapshot` 只有 account_id，
  即使用户给港股配了 futu、美股配了 tiger，两个市场的实盘资金也混在同一条快照里 —— 所以资金卡对实盘显式标注「账户级」。
- **重置会停掉运行中的策略**（`active_strategy` 键也是用户级，不分市场）：重置期货会顺带停掉 A 股策略。

E2E 断言口径：非 A 股页**不得出现** A 股成交/账户特征串（招商银行/正帆科技/600036.SH），

取决于 hook 依赖里有没有 market —— 本轮四个 hook 都加了 market；此外 `ModuleGrid`
的卡片 key 含 `currentMarket`，切换市场会整卡重挂载，数据必然重取。

## 七、维护手册（摘要，完整版在 dashboard-shared/README.md）

**加一个市场**：① `marketContent.ts` 加一份规格 → ② 检查后端该市场是否有账户/成交/策略端点
→ ③ 有则确认接口带 `market`，没有则加过滤参数 → ④ 首页无需改（卡片读注册表）
→ ⑤ `electron/tests/dashboard-market.e2e.mjs` 的 MARKETS 加一项。

**加一个框**：① `BoxId` 加枚举 → ② 5 份 `boxes` 补 `BoxContent` → ③ 写卡片组件并读 `useMarketBoxes()`
→ ④ `ModuleGrid.tsx` 的 `moduleComponents` 注册。

**三条铁律**：市场差异只写在 `marketContent.ts`；空就是空（不回退别的市场）；数值出口挡 null。
