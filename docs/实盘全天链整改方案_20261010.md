## 0. 执行纪律（硬规则，违反即回退重做）

1. **逐文件提交**：`git add`/`git commit` 一律带 pathspec；**禁止 `git add -A`**（历史上真删过 11 个迁移脚本）；提交前先 `git log --oneline -5` 体检（多会话共享工作区，并行会话会夹带）。
2. **三份真相核对**：本机运行态 = 工作树 bind mount ≠ HEAD ≠ 镜像。「已修复」的判定必须 `git show HEAD:<file>` + 运行态双核（cb81f137 回归事故的教训）。
3. **展示面/执行面用词边界**：展示面只说位置/程度（靠前/居中，0–100 分位）；执行面保留「买入/卖出」。模拟动作**必须**显式标注「模拟」。缺失一律「—」，**绝不**显示 0。
4. **写活动判据**：`engine_signal_scores` 判活一律用 `signal_ts`（`created_at` 是「首见」冻结值，专用于排障时识别陷阱）。
5. **技能改动双副本同步**：项目级 `skills/` 改完必须 `cp` 到用户级 `~/.claude/skills/`（既有运维纪律）。
6. **交易环境分级复核**：触单链路（决策/风控/执行/台账/复盘原料）改动 → 单测+集成测试+（可行时）回放/金样验证；纯展示面改动 → 类型检查+探针截图。
7. 部署（SSH 目标/目录）一律先问用户；本方案一切改动先在本地与 `next` 分支落地。
