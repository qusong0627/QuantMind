# ADR-0011 内部信任链密钥治理（C1 事故后定版）

- 状态：已采纳（2026-09-17，安全审查驱动）
- 背景：compose `${INTERNAL_CALL_SECRET:-changeme-internal-secret}` 的公开默认回退值 +
  缺失的头剥离，使匿名者仅凭 `X-Internal-Call`+`X-User-Id` 两枚请求头即可冒充任意用户
  （含 admin）并经内部网关直下真单；且"env 优先"的解析把轮换后的 runtime.env 新值遮蔽
  （与 QuantDB key 同型事故）。
- 决定：
  1. **唯一读取点** `shared/auth.get_internal_call_secret()`：**runtime.env 权威**（可热换，
     免重启）> 环境变量（非公开默认）> ""（空 = 一切内部校验必败，fail-closed）；
     `changeme-internal-secret` / `dev-internal-call-secret` 一律视为未配置。
  2. **发送端单 helper**：所有内部调用头都由该函数生成（禁止就地读 env）。
  3. **入口剥离双层**：nginx 与 api 代理对 `X-Internal-Call/X-User-Id/X-Tenant-Id` 一律
     清空/重建（客户端携带的信任头永不透传）。
  4. **启动守卫**：main_oss 检测无效即生成强随机并落 runtime.env（永久化，不只进程内）。
  5. **轮换纪律**：轮换 = 更新 runtime.env（+ host .env 供未来重建）；旧值按"已泄露"处理。
- 后果：轮换免重启、无公开默认面；未来新服务的内部调用必须走 helper 与剥离清单
  （新增信任头需同时登记到 nginx/trade_proxy 剥离表）。
