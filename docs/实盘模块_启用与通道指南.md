# 实盘模块：启用开关与交易通道指南

> 本文面向**部署与运维人员**：说明 QuantMind 实盘模块的默认状态、双开关启用步骤，
> 以及两条 Windows 侧交易通道（通达信桥 / 大 QMT）的组成与使用方式。
> 投资风险与合规边界见根目录 [DISCLAIMER.md](../DISCLAIMER.md)；本文不构成任何投资建议。

---

## 一、默认状态：整条实盘链不渲染、不通

默认构建（未显式注入开关）下：

- 侧边栏 **不出现**「实盘交易」栏目（连导航项都不构造）；
- 深链 `#/live` 仍可达，但渲染的是「实盘控制台未启用」说明页（`LiveDisabledPage`）；
- 顶栏不显示「实盘」标识与真实券商账户概览——外壳只呈现模拟盘；
- 后端实盘端点（下单 / QMT 镜像 / 券商配置 / TDX 推单等）一律 `403`，
  响应体带机器可读标记 `detail=real_trading_disabled`；
- **行情链路不受影响**：`/api/v1/tdx/*` 下行情与交易同前缀，后端闸门按**端点**判定，
  TDX 桥热集行情、L2 通道照常工作。

这是「源码入仓 ≠ UI 可见」的刻意设计：代码全部保留，仅收敛入口。

## 二、双开关机制

| | 前端开关 | 后端开关 |
|---|---|---|
| 变量 | `VITE_ENABLE_REAL_TRADING` | `ENABLE_REAL_TRADING` |
| 生效期 | **构建时**（Vite 内联进 bundle） | 运行期（进程环境变量） |
| 管什么 | 渲染不渲染 | 端点通不通 |
| 唯一读取点 | `electron/src/config/tradingFlags.ts` | `backend/shared/live_trading_gate.py`（中间件）+ `trade_shared/trade_config.py`，共用 `backend/shared/env_flags.py` 一份读取实现 |
| 词表 | 三态：显式 `true` / 显式 `false` / 缺省按构建环境（生产=false，开发=true） | **只有 `true`**（`strip().lower()` 归一后精确匹配；`1`/`yes`/`on` 不算开） |

### 组合行为矩阵

| 前端 | 后端 | 结果 |
|---|---|---|
| 关 | 关 | 默认态：无入口、无 API |
| 开 | 关 | UI 渲染但所有实盘调用 403（安全的失败方向：看得见、下不了单） |
| 关 | 开 | 无入口、深链到说明页；后端通但界面不可达（安全的失败方向） |
| 开 | 开 | 完整实盘控制台 |

两个方向失败都是安全的：**恢复实盘必须两端同时打开**。

## 三、启用步骤

### 3.1 后端

在 `.env` / `docker-compose.yml` 注入环境变量后重启 api / trade 服务：

```bash
ENABLE_REAL_TRADING=true
```

（`docker-compose.yml` 中为 `ENABLE_REAL_TRADING=${ENABLE_REAL_TRADING:-false}`，
不改 compose 文件、只改 `.env` 即可。）

### 3.2 前端

前端开关是**构建期**的，改环境变量后必须重新构建与部署：

```bash
VITE_ENABLE_REAL_TRADING=true bash scripts/deploy_frontend.sh --allow-local-live
```

两道防线都在 `scripts/deploy_frontend.sh` 里：

1. **环境变量闸**：检测到 `VITE_ENABLE_REAL_TRADING=true` 而没带 `--allow-local-live`
   参数 → 拒绝构建（防「顺手开着环境变量跑部署」）；
2. **产物形态闸**：构建产物 `assets/*.js` 里内联了
   `VITE_ENABLE_REAL_TRADING:"true"` 标记（Vite 构建期把 env 内联进 bundle），
   没带 `--allow-local-live` 就拒绝部署（防「构建时忘了去掉开关的历史产物被误发」）。

Electron 桌面端同理：打包前需带 `VITE_ENABLE_REAL_TRADING=true` 前缀构建，
否则桌面壳同样不渲染实盘栏目。

### 3.3 验收（建议每次改动部署后跑一遍）

**关的方向**：

```bash
# 1) 产物内联标记应为不命中（或干脆 grep 不到 true）
grep -rqs 'VITE_ENABLE_REAL_TRADING:"true"' <web 根>/assets && echo "!! 打开了" || echo "关闭 ✓"

# 2) 实盘端点应 403 且 detail 为 real_trading_disabled
curl -s -o /dev/null -w '%{http_code}' -X POST http://<host>:8000/api/v1/orders
curl -s http://<host>:8000/api/v1/qmt-mirror/status | head -c 200

# 3) 浏览器：底部栏无「实盘交易」；访问 #/live 应显示说明页
```

**开的方向**：前端产物含内联标记且带了 `--allow-local-live` 部署；
后端端点返回 200/正常业务响应。

## 四、通达信桥（TDX，Windows 侧）

代码与本机文档都在 `tools/bridge-windows/`（**源码唯一事实源**），详细部署见：
- `tools/bridge-windows/Windows操作说明.md`（3 步快速上手）
- `tools/bridge-windows/通达信实盘桥_完整部署指南.md`（完整故障排查）
- `docs/integrations/tdx-bridge.md`（架构与双通道容灾）

### 要点

- **为什么必须有桥**：通达信的交易 RPC 端口 `127.0.0.1:17709` 只监听本机回环，
  Linux/容器无法直连 → 必须在 Windows 交易机上跑桥转发。
- **桥的形态**：Windows 侧一个 HTTP 服务（默认 `0.0.0.0:8550`，token 鉴权），
  把 HTTP 请求转成通达信 JSON-RPC。TdxW.exe 需登录交易账号（模拟/实盘均可）。
- **最小步骤**：(1) 启动通达信并登录交易账号；(2) 右键运行 `setup.ps1`
  （按提示输入 `BRIDGE_AUTH_TOKEN`，64 位 hex）；(3) PowerShell 里
  `curl.exe http://127.0.0.1:8550/api/v1/health` 返回 `{"status":"ok","tdx_connected":true}`。
- **两端 token 必须一致**：Windows 侧 `BRIDGE_AUTH_TOKEN` ⇄ Linux 侧 `.env` 的
  `TDX_BRIDGE_TOKEN`；桥地址在 Linux 侧配 `TDX_BRIDGE_URL`（默认
  `http://127.0.0.1:8550`，容器部署时指向 Windows 局域网 IP）。
- **验证桥别只看 health**：`/health` 只证明**行情通道**通；
  账户通道要用 `account/query` 真查一次（桥「假活」——行情通 ≠ 账户通）。
- **侧车止损 daemon**：桥源码里自带的 sltp daemon 已改为**默认关闭**——
  止损统一由 Linux 侧 `sltp_executor` 执行，两边同时触发会超卖。
  若手上有 2026-10 之前打好的旧版已部署包，行为以包内版本为准，
  需用现源码重新打包后部署。
- **下单返回语义**：下单返回值 `2=直接提交`（TQ 收费账号）/ `1=待确认`
  （需在通达信客户端点确认）/ `0=失败`。

## 五、大 QMT（Windows 侧）

大 QMT 相关有**两条独立链路**，都运行在装了 QMT 客户端的 Windows 主机上：

### 5.1 QMT Agent（信号桥，独立交付）

位置 `tools/qmt_agent/`，详见 `tools/qmt_agent/README.md` 与 `help.md`。

- 按**独立程序**交付：可打包为 Windows `.exe` / 安装器（`qmt_agent_setup.iss`），
  不与 Electron 混合打包；前端「QMT 实盘连接中心」只负责凭证初始化、
  在线状态查看与下载入口（下载的是 `qmt_agent_client.zip`）。
- 桌面壳入口 `python tools/qmt_agent/desktop_app.py`（GUI 配置 + 托盘常驻），
  CLI 入口 `qmt_agent.py`；崩溃自动重启与交易/非交易时段调度收敛在
  `runtime_supervisor.py` / `schedule_policy.py`。
- 鉴权：`access_key + secret_key` 换短期 `bridge_session_token`，再连 `ws/bridge`；
  周期上报账户快照与心跳。
- **关闭 Electron 前端不影响已运行的 QMT Agent**——这是刻意的独立部署原则。

### 5.2 大 QMT 真单镜像（big-convert RPC 通道）

完整部署见 [大QMT真单镜像_部署与上线手册.md](大QMT真单镜像_部署与上线手册.md)（前置条件、
Windows 侧逐步部署、对账与熔断）。要点：

- **Windows 侧组件**是大 QMT **内置 Python** 里常驻的 big-convert RPC 服务端
  （入口 `BIGQMT_REDIS_DRYRUN.py`，需 `rpc_allow_order_methods=True`，带看门狗）——
  不是外接 xtquant（该通道已按监管下线）。QMT 上走「内置执行端」才是官方合规通道。
- **传输**：专用 Redis 实例（建议默认 6380 + 密码 + 防火墙白名单，**不要复用业务
  Redis**）；Linux 侧 `pip install "xtquant-big-convert[redis]"`（requirements 已固定版本）。
- **Linux 侧客户端**：`backend/services/live_trading/services/qmt_exec_client.py`
  （RPC 为同步阻塞的 brpop 等响应，对外暴露 async），配置两个来源、**页面配置优先**：

1. **页面配置**（交易 Redis `broker:config:qmt_exec`，由常驻任务每轮刷新）；
2. **环境变量**（页面未配时兜底）：

| 变量 | 别名 | 说明 |
|---|---|---|
| `QMT_EXEC_ENABLED` | — | 默认 `false`；只有 `true` 打开 |
| `QMT_EXEC_ACCOUNT_ID` | `BIGQMT_ACCOUNT_ID` | 资金账号 |
| `QMT_EXEC_ACCOUNT_TYPE` | — | 默认 `STOCK` |
| `QMT_EXEC_REDIS_HOST` / `_PORT` / `_DB` / `_PASSWORD` | `BIGQMT_REDIS_*` | 桥侧 Redis（默认端口 6380）；未单独部署时回落 trade Redis |
| `QMT_EXEC_TIMEOUT` | — | 默认 10s |
| `QMT_EXEC_STRATEGY_NAME` | — | 默认 `quantmind`，QMT 侧策略名须同名 |

- 真单前置纪律：**本地优先落库**（外部报单前必须先持久化），
  成败判据看**订单终态**（只有终态 `REJECTED` 才算失败；超时保持 `submitted`，
  可能已在柜台，**绝不可当失败重试**）。
- 大 QMT 另一个角色是**备源行情席**（`qmt_quote_backup.py`）：主源陈旧超 30s 时
  旁路写 `market:snapshot/series`（`source=qmt_big`）。
- 镜像面控制端在「模拟交易设置 → 大 QMT 真单镜像」卡片
  （`electron/src/pages/trading/components/QmtMirrorCard.tsx`），
  状态/开关/急停/限额/名单/补交/对账走 `qmt_mirror` 路由。

### 5.3 Windows 侧最小使用步骤

1. 在 Windows 交易机安装并登录 **大 QMT 客户端**（投研版），确认账号有交易权限、
   内置 Python（big-convert 服务端跑在这里）可用；
2. **真单镜像**：按[部署与上线手册](大QMT真单镜像_部署与上线手册.md)完成
   Windows 侧部署（先跑 `probe_qmt_env.py` 只读探测，再起 big-convert 常驻服务）；
   Linux 侧配 `QMT_EXEC_*`（或用页面配置），并在「模拟交易设置 → 大 QMT 真单镜像」
   卡片里开启——镜像**默认关，白名单点名才镜像**；
3. **信号桥**：部署 QMT Agent 安装包（或源码运行 `desktop_app.py`），在 GUI 填入
   access_key / secret_key 与 Linux 侧地址；
4. 验证：页面「QMT 实盘连接中心」在线状态 + `qmt-mirror` 状态端点；再走一笔
   小额真单探针 round-trip（下单 → 成交回报 → 撤单/平仓）。平仓类探针
   **必须用 `--from-file` 精确数量**，不要用全量 `can_use` 平仓。

## 六、合规边界（重要）

- **开关是工程闸门，不是合规判定**。打开双开关只代表「本部署启用了实盘 UI 与
  交易端点」，不代表满足任何监管要求；实盘交易前请自行确认账户、券商与
  程序化交易报备义务。
- **程序化交易报告义务**：法规常量（高频阈值 300 笔/秒、20000 笔/日）与待填报
  信息（软件名称/版本号/开发者）的唯一出处是
  `backend/shared/programmatic_trading_disclosure.py`；
  「设置 → 系统信息」可一键复制填报内容（端点
  `GET /api/v1/system/programmatic-trading-disclosure`）。
- 风控 `l3.order_frequency.max_per_minute` 撞线时**只告警不拦单**——
  频率约束的兜底靠报告义务与券商侧，不靠本系统硬拦。
- 其余免责与合规声明以根目录 [DISCLAIMER.md](../DISCLAIMER.md) 为准。
