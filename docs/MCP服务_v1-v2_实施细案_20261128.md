# MCP 服务 v1 + v2 实施细案（2026-11-28）

> **实施状态（2026-11-28 当晚）**
> - 已完成：Sprint 0（权限码/三张表/管理 API）、Sprint 1（独立 `quantmind-mcp` 容器、
>   SDK Key 认证、数据/清单/任务/模拟盘工具、配额/审计/管理页）、Sprint 2 的读能力
>   （推理排名、单票评分）。
> - 未完成：Sprint 2 的任务结果体/取消；Sprint 3 的模型/策略写工具与权限矩阵完整化。
>   工具目录中未实现的项**没有注册**，管理页不会出现。
> - 部署：compose `mcp` 服务（宿主 18765→容器 8765），web nginx `/mcp` 反代；
>   对外 API 需 `EXTERNAL_API_SECRET`。管理入口「系统设置 → MCP 服务」。

> 目标：让外部 AI 客户端（Claude Desktop / Claude Code / Cursor / 其他 MCP 客户端）
> 通过 **MCP 协议**接入 QuantMind，读取数据、提交任务、使用模拟盘；v2 补齐推理排名、
> 任务结果与模型/策略写操作。
>
> 授权复用现有 **SDK Access Key / Secret Key**（`/api/v1/api-keys`），不另造一套账号；
> MCP 服务入口放在「后台管理 → 系统设置 → MCP 服务」，并带权限开关、配额、审计。

## 1. 范围

### 1.1 v1（先交付）

| 能力 | 说明 |
|---|---|
| 数据读取 | 数据集目录、分区、有界查询（JSON 小切片）、文件下载元信息 |
| 清单读取 | 策略清单、模型清单（只读） |
| 任务 | 提交训练 / 回测 / 因子演化 / 数据同步，轮询状态 |
| 模拟盘 | 账户、持仓、委托、成交、下单、撤单（**仅模拟**） |
| 管理 | 后台「MCP 服务」页：总开关、连接信息、客户端/密钥、工具权限、配额、审计 |

### 1.2 v2（第二批）

| 能力 | 说明 |
|---|---|
| 推理读取 | 模型/日期维度的评分排名（分页），单票评分/位置 |
| 任务结果 | 训练/回测结果摘要（不返回大文件；产物给下载引用） |
| 任务取消 | 仅在上游可映射的 kind 上开放（回测的 cancel 键问题先解决） |
| 模型/策略写 | 新建/更新/归档（**不做物理删除**），独立权限码 + 二次确认 |
| 权限编辑 | API Key 的 permission 编辑界面（当前只有 `/init` 写入点，是 v2 前置） |
| 审计增强 | 工具调用明细、配额命中、失败原因、导出 |

### 1.3 明确不做（至少不在 MCP 里做）

- **实盘交易**：MCP 只接模拟盘；实盘保留人工确认链路，不暴露给 AI。
- 后台管理写操作：MCP 不提供用户管理、系统设置、密钥签发等管理工具。
- 实时行情 WebSocket：MCP 用轮询快照/数据面增量替代（`stream` 面对外仍未开）。
- 任意文件系统/数据库访问：MCP 服务不直连 DB，只调 `/api/ext/v1`。

## 2. 现状与可复用底座

- 对外 API `/api/ext/v1` 已有四个面：`data` / `control` / `task` / `trading(sim)`。
- 认证：Access Key + Secret Key → `POST /api/ext/v1/auth/session` → 1h Bearer token；
  token 带 `user_id` / `tenant_id` / `permissions`，可续期。
- 多租户：策略/模型/模拟账户按 token 的 `user_id` + `tenant_id` 隔离；
  QuantDB 数据、新闻富化是平台共享。
- 权限：`api_keys.permissions` 目前只约束交易面（`trade.read` / `trade.write`），
  数据/控制/任务面暂不挂码。
- 任务：`training` / `backtest` / `alpha_evolve` / `data_sync` 提交 + 轮询；
  结果体暂不返回（只有 `result_available`）。
- 数据面：parquet over HTTP + 游标增量；`engine_signal_scores` 因缺 `updated_at` 被排除。

**结论：MCP 服务只需要做协议适配、权限/配额/审计，不需要复制业务逻辑。**

## 3. 总体架构

```text
Claude Desktop / Claude Code / Cursor / 其他 MCP 客户端
        │  Streamable HTTP（推荐）或 stdio 桥
        ▼
quantmind-mcp 容器（Python，MCP SDK）
  - 无 DB、无业务逻辑
  - 持有/接收每用户 SDK Key，换短期 token
  - 工具注册表、权限判定、配额、审计上报
        │  /api/ext/v1 + Bearer token
        ▼
quantmind api
  - 现有四面 + v2 新增的 inference / task-result / model-write
  - 管理面：/api/v1/admin/mcp/*
```

### 3.1 部署形态

- **主形态：Streamable HTTP**，独立容器 `quantmind-mcp`
  - 端口 `8765`，默认只绑 `127.0.0.1`；远程接入经 nginx `/mcp` + TLS
  - 与 `quantmind` 同 docker 网络，`QM_API_BASE=http://quantmind:8000`
  - 无状态：可重启/水平扩，token 缓存放进程内，配置从 API 拉取并短缓存
- **可选：stdio 桥**
  - 同一份工具代码，启动参数 `--stdio`；给 Claude Desktop 本机用
  - 通过环境变量 `QM_ACCESS_KEY` / `QM_SECRET_KEY` 注入单用户凭据
  - 多用户场景仍用 HTTP，不靠 stdio

### 3.2 MCP 服务不碰的东西

- 不直连 PostgreSQL / Redis（配额计数走 Redis 可以，但属于 MCP 自己的 namespace，不读业务库）
- 不持有 `EXTERNAL_API_SECRET`（不自己签 token；token 只由 api 签发）
- 不落盘用户 Secret（仅内存缓存；日志只留指纹）

## 4. 认证与多用户

### 4.1 复用 SDK 密钥

MCP 客户端配置里填：

```json
{
  "mcpServers": {
    "quantmind": {
      "type": "http",
      "url": "https://<host>/mcp",
      "headers": {
        "X-QM-Access-Key": "ak_...",
        "X-QM-Secret-Key": "sk_..."
      }
    }
  }
}
```

MCP 服务收到请求后：

1. 取 `X-QM-Access-Key` / `X-QM-Secret-Key`（stdio 模式取 env）；
2. 调 `POST /api/ext/v1/auth/session` 换短期 token；
3. 缓存 `(access_key_fp, secret_fp) → token`，按 `renew_after` 提前续期；
4. 后续工具调用一律带该 token 调 `/api/ext/v1`；
5. 认证失败统一返回 MCP 错误 `auth_failed`，不区分「key 不存在 / secret 错 / 过期」。

> 不把 Secret 写进工具参数（会被 LLM/日志看到）；只允许出现在连接头或进程 env。

### 4.2 多用户模型

- **一枚 SDK Key 对应一个用户/租户**；MCP 服务按 key 识别 principal，不做跨用户代理。
- 用户 A 的 key 只能看到 A 的策略/模型/模拟账户；QuantDB 数据为平台共享。
- 管理员在「后台管理 → 系统设置 → MCP 服务 → 客户端」里：
  - 查看所有已启用 MCP 的 key（用户、指纹、最近使用、工具权限、配额）；
  - 签发/吊销 MCP 用 key（本质仍是 `/api/v1/api-keys`，只是带 MCP 权限码）；
  - 暂停某个用户/某枚 key 的 MCP 访问。
- v2 再评估「用户自助申请 MCP key」；v1 先由管理员签发，避免权限界面未就绪时放开。

### 4.3 令牌与权限

- 新增权限码（命名空间 `mcp.*`，避免与现有 ext API 的码混淆）：

| 权限码 | 允许 |
|---|---|
| `mcp.use` | 允许建立 MCP 会话 |
| `mcp.data.read` | 数据面工具 |
| `mcp.control.read` | 策略/模型清单 |
| `mcp.task.submit` | 提交训练/回测/因子演化/数据同步 |
| `mcp.task.cancel` | v2 取消任务 |
| `mcp.inference.read` | v2 推理排名/单票评分 |
| `mcp.model.write` | v2 模型新建/更新/归档 |
| `mcp.strategy.write` | v2 策略新建/更新/归档 |
| `trade.read` / `trade.write` | 模拟盘读/写（沿用现有码） |

- **MCP 层强制校验**：没有对应码 → 工具直接返回 `permission_denied`，不调 API。
- v2 增加权限编辑 UI 后，再考虑把这些码下沉到 ext API 层做统一闸门；
  v1 不改现有 ext API 的权限行为，避免影响已接入的外部节点。
- 存量 key 迁移：不自动加码（空列表=无权限）；管理员在 UI 里逐枚授予；
  `/api-keys/init` 新签发的 key 默认给 `mcp.use` + 只读三码，模拟盘读写保持现有默认。

## 5. MCP 工具面

工具命名统一 `qm_` 前缀；每个工具在**一个注册表**里声明：
`name / description / inputSchema / outputSchema / permission / annotations / handler / version`。
管理后台的工具开关直接读这份注册表，避免「页面有开关、服务里没工具」。

### 5.1 v1 工具

| 工具 | 权限 | 类型 | 说明 |
|---|---|---|---|
| `qm_capabilities` | `mcp.use` | read | 部署能力、实盘开关、当前 principal、可用工具 |
| `qm_list_datasets` | `mcp.data.read` | read | 数据集目录（market/kind/as_of） |
| `qm_list_partitions` | `mcp.data.read` | read | 某数据集分区清单 + etag |
| `qm_query_dataset` | `mcp.data.read` | read | **有界查询**：symbol/日期区间/列/limit，返回 JSON 行；单次 ≤ 5000 行 |
| `qm_get_dataset_file` | `mcp.data.read` | read | 返回文件下载 URL + etag（不把大 parquet 塞进 tool 结果） |
| `qm_list_strategies` | `mcp.control.read` | read | 策略清单 |
| `qm_list_models` | `mcp.control.read` | read | 模型清单 |
| `qm_submit_task` | `mcp.task.submit` | write | kind = training/backtest/alpha_evolve/data_sync |
| `qm_get_task` | `mcp.task.submit` | read | 轮询状态 |
| `qm_sim_account` | `trade.read` | read | 模拟账户 + 持仓 |
| `qm_sim_orders` | `trade.read` | read | 委托列表/单笔 |
| `qm_sim_trades` | `trade.read` | read | 成交列表 |
| `qm_sim_preview_order` | `trade.write` | read | 预估金额/风控预检，不发单 |
| `qm_sim_place_order` | `trade.write` | **write/destructive** | 需 `client_order_id` 幂等键；建议先 preview |
| `qm_sim_cancel_order` | `trade.write` | **write/destructive** | 撤单 |

### 5.2 v2 新增工具

| 工具 | 权限 | 说明 |
|---|---|---|
| `qm_get_inference_rankings` | `mcp.inference.read` | model_id + date + limit/offset；返回 symbol/name/score/rank/rank_pct |
| `qm_get_stock_score` | `mcp.inference.read` | 单票在某模型/日期的评分与截面位置 |
| `qm_get_task_result` | `mcp.task.submit` | 训练/回测结果摘要（指标 + 产物引用，不返回大文件） |
| `qm_cancel_task` | `mcp.task.cancel` | 仅已映射的 kind |
| `qm_create_model` / `qm_update_model` / `qm_archive_model` | `mcp.model.write` | 归档代替删除 |
| `qm_create_strategy` / `qm_update_strategy` / `qm_archive_strategy` | `mcp.strategy.write` | 归档代替删除 |

### 5.3 写工具的共同规则

1. **预览 → 确认 → 执行**：下单先 `qm_sim_preview_order`，返回预估金额/风控提示与
   `preview_token`；`qm_sim_place_order` 必须带该 token（或 `client_order_id`）。
2. **幂等**：下单必须带 `client_order_id`；重复调用返回同一委托。
3. **金额/频率上限**：MCP 层按 key 配置检查（如单笔 ≤ 5 万、每日 ≤ 20 笔）。
4. **可审计**：每次写调用落 `qm_mcp_audit`，含参数摘要（脱敏）。
5. **实盘永不出现**：工具注册表里不存在 real 交易工具；即使未来加，也必须在
   独立开关 + 人工确认之后。

### 5.4 输出规范

- 时间：UTC ISO8601 带 `Z`；需要展示上海时间由客户端转换。
- 金额：元；数量：股；比例：小数（0.0123 表示 1.23%）。
- 缺失：`null`，**不写 0**（与平台口径一致）。
- 大结果：返回 `{summary, row_count, truncated, next_cursor}`，禁止无界返回。
- 错误：`{code, message, retryable}`；不把上游 HTML/堆栈返回给模型。

## 6. 后台管理 UI

「后台管理 → 系统设置」二级菜单增加第三项 **MCP 服务**（顺序：金融情感 → SDK 接入凭证 → MCP 服务）。

### 6.1 概览

- MCP 总开关（启停，热生效；停用后 MCP 服务返回 503 `mcp_disabled`）
- 服务状态：容器健康、版本、当前连接数、24h 调用量
- 接入地址（HTTP / stdio 配置示例，一键复制）
- 「测试连接」按钮：用当前管理员 key 走一次 `qm_capabilities`

### 6.2 工具权限

- 全局工具开关矩阵：每个工具一行，`启用/禁用`；禁用后 MCP 服务在 `tools/list` 里不返回
- 全局配额：每分钟调用数、每日任务提交数、每日模拟下单数、单笔金额上限、数据查询行数上限
- 只读工具默认开；写工具（下单/任务提交/模型策略写）默认关，由管理员显式打开

### 6.3 客户端与密钥

- 列表：用户、access_key 指纹、状态、权限码、最近使用、24h 调用量、配额命中
- 操作：暂停/恢复 MCP、编辑权限、吊销 key
- 签发：选择用户 + 权限模板（只读 / 研究 / 模拟交易）→ 生成 key（Secret 只展示一次）
- 权限模板：
  - `只读`：`mcp.use`, `mcp.data.read`, `mcp.control.read`
  - `研究`：只读 + `mcp.task.submit`, `mcp.inference.read`
  - `模拟交易`：研究 + `trade.read`, `trade.write`
  - 不提供「实盘」模板

### 6.4 审计

- 最近调用：时间、用户、key 指纹、工具、参数摘要、状态、耗时、request_id
- 过滤：用户/工具/状态/时间段；导出 CSV
- 保留天数可配（默认 90 天）；写操作与权限拒绝单独标色

### 6.5 SDK 凭证页联动

- 每枚 key 增加「MCP 权限」折叠区（勾选权限码、MCP 启用开关）
- 显示该 key 最近一次 MCP 调用时间
- 不改变 Secret 只展示一次的规则

### 7.3 数据模型（迁移 `upgrade_v1.3.0.sql`）

```sql
qm_mcp_settings (
  id smallint primary key default 1 check (id = 1),
  enabled boolean not null default true,
  tool_flags jsonb not null default '{}',      -- {tool_name: bool}
  limits jsonb not null default '{}',          -- 全局配额
  updated_at timestamptz not null default now(),
  updated_by text
);

qm_mcp_key_settings (
  access_key text primary key,
  tenant_id text not null,
  user_id text not null,
  enabled boolean not null default true,
  tool_flags jsonb not null default '{}',      -- 单 key 覆盖
  limits jsonb not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

qm_mcp_audit (
  id bigserial primary key,
  ts timestamptz not null default now(),
  tenant_id text not null,
  user_id text not null,
  access_key_fp text not null,
  session_id text,
  tool text not null,
  args_digest text not null,                   -- 参数哈希，不存明文
  status text not null,                        -- ok / denied / error / quota
  error_code text,
  latency_ms integer,
  request_id text,
  client_info text
);
create index on qm_mcp_audit (ts desc);
create index on qm_mcp_audit (access_key_fp, ts desc);
```

配额计数走 Redis `qm:mcp:quota:{access_key_fp}:{window}:{metric}`，窗口 1m/1d，过期自动清。

### 7.4 权限码校验

- `api_keys.permissions` 增加 `mcp.*` 码白名单校验（`PUT /api-keys/{key}` 拒绝未知码）。
- MCP 层判断：`required_permission(tool)` + 全局开关 + key 级开关 + 配额。
- 新签发的默认 key：`mcp.use` + `mcp.data.read` + `mcp.control.read` + `trade.read` + `trade.write`；
  `task.submit` / `inference.read` / 写模型默认关（管理员按模板开）。

## 8. MCP 服务实现

### 8.1 技术选型

- Python 3.11 + 官方 `mcp` Python SDK（FastMCP / Streamable HTTP）。
- 镜像 `docker/Dockerfile.mcp`，独立容器 `quantmind-mcp`；代码 `mcp_server/`（与 backend 分离）。
- 依赖：`mcp`、`httpx`、`pydantic`；不装 pandas/duckdb（数据处理在 API 侧）。

### 8.2 目录

```text
mcp_server/
├── main.py                # 启动（http / --stdio）
├── auth.py                # SDK key → token 缓存/续期
├── config.py              # 从 API 拉配置（30s 缓存）
├── quota.py               # Redis 计数
├── audit.py               # 审计上报
├── errors.py
├── api_client.py          # /api/ext/v1 客户端（统一错误/超时/Request-ID）
└── tools/
    ├── registry.py        # 工具注册表（唯一事实源）
    ├── data.py
    ├── control.py
    ├── task.py
    ├── trading.py
    └── inference.py       # v2
```

### 8.3 启动与健康

- `GET /health`：进程健康 + 到 api 的连通性（不暴露内部地址）
- `GET /version`：`mcp_contract_version`、镜像版本、工具数量
- 配置拉取失败：启动继续，但工具调用返回 `config_unavailable`（fail closed，不放过权限）
- MCP 总开关关闭：除 `/health` 外一律 503 `mcp_disabled`

### 8.4 错误与日志

- 结构化 JSON 日志：`request_id`、`tool`、`access_key_fp`、`status`、`latency_ms`
- Secret/Token 永不进日志；参数只存 hash + 少量安全字段（symbol/side/kind）
- 上游 5xx → `upstream_unavailable`（retryable），不把上游 HTML 返回给模型

## 9. 安全、限流、合规

| 项 | 规则 |
|---|---|
| 传输 | 生产必须 HTTPS（nginx / 反代）；8765 默认只绑本机 |
| 认证 | SDK key → 1h token；失败统一 `auth_failed`；握手节流沿用 ext API |
| 权限 | 最小权限模板；新 key 默认不授予写；模型/策略写仅管理员显式开启 |
| 配额 | 每 key：调用/分钟、任务/日、模拟下单/日、单笔金额、查询行数 |
| 审计 | 所有工具调用（含拒绝）落库；写操作强制记录 |
| 提示注入 | 新闻/股票名/数据字段均视为不可信数据；工具输出不含指令性文本 |
| 实盘 | MCP 无实盘工具；`ENABLE_REAL_TRADING` 与 MCP 无关，不复用其开关放行 |
| 合规 | AI 驱动下单属程序化交易；沿用 `programmatic_trading_disclosure.py` 的披露口径 |
| 数据边界 | 策略/模型/模拟账户按 tenant+user 隔离；QuantDB 平台共享 |

## 10. 部署与运维

### 10.1 compose

```yaml
mcp:
  image: quantmind-mcp:latest
  container_name: quantmind-mcp
  restart: unless-stopped
  depends_on:
    quantmind:
      condition: service_healthy
  environment:
    QM_API_BASE: http://quantmind:8000
    MCP_PORT: "8765"
    MCP_AUTH_MODE: api_key
    REDIS_HOST: redis
    REDIS_PORT: "6379"
    REDIS_MCP_DB: "0"
  ports:
    - "127.0.0.1:8765:8765"   # 远程接入走 nginx/TLS
  networks: [quantmind-net]
```

- 构建：`docker build -f docker/Dockerfile.mcp -t quantmind-mcp:latest .`
- 发布：并入 `deploy/update.sh`（第 3 个镜像），管理页显示版本/健康
- 配置热生效：MCP 只从 API 拉配置，不挂配置文件；改开关不重启容器
- 回滚：保留上一版镜像 tag；MCP 无状态，回滚只切镜像

### 10.2 nginx

- `location /mcp/ { proxy_pass http://quantmind-mcp:8765/; ... }`
- 开 `proxy_buffering off`（Streamable HTTP）、`X-Request-ID` 透传、HTTPS

## 12. 测试策略

- **配额**：分钟/日窗口、并发写、窗口过期

## 13. 维护约定

1. **工具注册表唯一事实源**：`mcp_server/tools/registry.py`；新增工具必须同时更新
   管理页（通过 API 读取）、权限映射、测试。
2. **契约版本**：`MCP_CONTRACT_VERSION`；工具改名/删参数必须升版本并在管理页提示。
3. **只增不改**：已发布工具的参数只做可选新增；破坏性变更走新工具名 + 旧工具弃用期。
4. **配置热更新**：开关/配额从 API 拉取，30s 缓存；改配置无需重启。
5. **审计不可关**：写操作与拒绝必须落库；只读审计可按保留期清理。
6. **实盘红线**：MCP 代码里不出现 real order 工具；代码评审必查。
