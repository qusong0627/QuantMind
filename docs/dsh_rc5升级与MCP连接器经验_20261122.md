# dsh rc.5 升级与 MCP 连接器经验（2026-11-22）

## 结论

- dsh 从 **0.2.2-rc.3 → 0.2.2-rc.5**
- MCP 连接器 **0.2.76 → 0.2.119**（0.2.119 的 2026-11-21 更新正好修了面板显示：长诊断信息/多按钮下正文被挤压、逐字换行、卡片异常增高）
- QuantBot（3080）里的 MCP 连接器面板恢复显示；DS Bot 的 MCP 开放局域网访问（`http://<host>:8088/mcp`，Bearer token）
- 回滚镜像：`quantmind-dsh:pre-rc5-20261122`

## 三个坑与修法

### 1. 插件安装被 pnpm 最短发布年龄策略拒绝

`dsh plugin --profile web install --frozen-lockfile` 报
`ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`（ds-bot 0.3.9 等新版本落在冷却窗内）。

修法：`entrypoint.sh` 在 frozen 安装失败后**一次性**重试
`--config.minimum-release-age=0`（仍按仓库 `pnpm-lock.yaml` 装，版本可审计；日志写明已绕过）。

### 2. MCP 连接器面板在 QuantBot 里白屏/拒绝连接

现象：直连 `http://192.168.31.68:8088/mcp-connector/ui/` 正常；从
`http://192.168.31.68:3080/#/quantbot` 的 iframe 里打开就白屏或「拒绝连接」。

根因：连接器页面的 CSP 是 `frame-ancestors 'self'`，只允许同源内嵌；3080 的 QuantBot
外壳是跨源祖先，浏览器直接拦截。

修法：`docker/dsh/dsh.cordis.yml` 给 `id: mcp-connector` 追加 `frameAncestors`
（self + localhost/127.0.0.1/31.68/31.56 的 :3080 + tauri.localhost/tauri://localhost）。
注意 dsh patch 的 config 是**整体替换**，要连同 bundle 字段一起重声明。

验证：`curl -sI http://127.0.0.1:8088/mcp-connector/ui/ | grep content-security-policy`
必须列出上述源。

### 3. DS Bot 的 MCP 只绑 127.0.0.1:8797，局域网连不上

8797 的 loopback 绑定是**安全设计**（Host 白名单 + 禁止 Origin + 每客户端独立可撤销 token），
不要改它。

修法：dsh 前门 nginx 增加 `location = /mcp`，代理到 `http://127.0.0.1:8797/mcp`：
Host 改回 `127.0.0.1:8797`、剥掉 `Origin`/`Cookie`、保留 `Authorization`，关闭 buffering、长超时。
客户端使用 `http://<host>:8088/mcp` + `Authorization: Bearer <token>`。

验证：不带 token `POST /mcp` → **401 Unauthorized**（说明已到 ds-bot，只是缺令牌）。

## 验证清单（升级后必做）

1. `docker exec quantmind-dsh dsh --version` → `0.2.2-rc.5`
2. `dsh-mcp-connector` package.json → `0.2.119`

## 教训

1. **逐层定位**：先确认端口监听与页面 200，再查 iframe/CSP，最后才怀疑应用——「直连正常、内嵌失败」几乎一定是 `frame-ancestors`/`X-Frame-Options`/sandbox。
2. **升级版本不会自动放宽安全策略**：插件升级后 CSP 默认仍是 `'self'`，跨源嵌入必须显式配置。
3. **供应链冷却 vs 最新版**：`minimumReleaseAge` 会拦新版本；用 frozen lock + 一次性 bypass，比直接关策略可审计。
4. **loopback 服务不要为局域网改绑定**：用前置代理重写 Host/剥 Origin，安全边界留在服务里。
5. **保留回滚**：镜像打旧 tag，profile/存储都在持久化卷，升级失败可切回。
6. **客户端 IP 轨迹**：`docker exec quantmind-dsh tail /var/log/nginx/access.log` 按用户设备 IP 看请求，能快速区分「没到服务器」与「到了但页面/API 错」。
