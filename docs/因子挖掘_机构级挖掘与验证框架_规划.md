## 1. 现状速查（全部实测，2026-10-10）

### 1.1 挖掘链（方向 → 拆解 → 派发 → RDA → 回测 → 池）

- `POST /alpha-agent/evolve`：前端传 `directions`（多选类别）+ `direction_mode`，
  服务端**收敛成单条** direction（selected=第一条 / random=均匀随机一条）。
- `POST /alpha-agent/directions/decompose`：粗方向 → N 张正交卡片（**只拆解不落任务**）。
  实现 `alpha_agent/direction_decompose.py`：`PROMPT_VERSION="decompose_v1"`、
  `validate_cards` 归一（title/hypothesis 必填，categories 白名单收敛，可选字段空则省略，
  超量 `dropped` 如实上报）、金样 `tests/fixtures/decomposeCardsGolden.json`、
  注入层纪律（类别/池摘要失败只告警不拦主链）。
- `POST /alpha-agent/mining/batch`：卡片逐条 `start_or_queue`（请求级问题整包 400，
  运行期错误逐条回传）。**direction 是唯一载体——卡片上的额外字段不随派发落地**。
- 池摘要注入已存在：`pool_service.build_injection_digest`（=避重提示词，排序
  pool_scoring：ICIR 分位×疲劳×冗余×新鲜度，`exclude_task_id` 排除本任务）。
- **父本种子注入：无**（本框架 T-MV-01）。

### 1.2 闸门与验证现状

- 五门禁已注册（`mining_plugins/gates/builtin.py` + `registry.py`）：
  `pfs_floor / rre_floor / ic_pool_pct / turnover_cap / net_return_floor`，soft/hard 两模式。
- **质量闸门未接线**：设置页 `qualityGateEnabled` 与 `并行方向数` 均标注「后端暂未生效」，
  且实测两字段只进前端本地任务卡片（startMining 请求体无此二参）。
- 清理建议已有相关性去重判据（corrDup≥0.9 冗余被支配 / ICIR 后 20% 分位）。
- 回测引擎已交付（T-FB：`/api/v1/factor-backtest` 批量求值 + 诚实降级矩阵）；

## 2. 框架总览：五环流水线

```
环0 数据供给面 ──→ 环1 方向智能 ──→ 环2 执行调度 ──→ 环3 入库闸门 ──→ 环4 验证与排名
 目录/列对齐        供给面统计/父本      并行方向/配额        五门禁/去重/正交     验证流水线/战力榜
      ↑                                                                              │
      └────────────────────────── 供给面回写（环4 产出反哺环1）────────────────────────┘
```

| 环 | 职责 | 单源模块（维护锚点） | 契约 | 现状 |
|---|---|---|---|---|
| 0 数据供给面 | 目录化因子库、对齐挖掘数据面、L2 全量、多市场 | 新 `factor_libraries.yaml` + 既有 catalog | 目录 schema（T-MV-06） | catalog 单目录 |
| 1 方向智能 | 供给面统计、加权抽样、父本定向、结构化拆解 | `direction_decompose.py` + `pool_service` | `PROMPT_VERSION`+金样 | v1，无种子 |
| 2 执行调度 | 并行方向落地、每类配额预算 | `launcher.start_or_queue` + `/mining/batch` | 任务记录 schema | 单方向、方形数未接线 |
| 3 入库闸门 | 五门禁硬/软判定、相关性去重（含父本关系）、正交增量 | `gates/` + `pool_cleanup` | GateContext | 已建未接线 |
| 4 验证与排名 | 机构级验证、方向战力榜、供给面回写 | T-FB 引擎（复用）+ 池统计 | 报告结构 | 回测已交付、排名未建 |

**「高质量·低重复」四条防线**（贯穿五环，按时间序）：

1. **避重（挖前）**：池摘要注入（已有）+ 饱和度提示（T-MV-02）+ 父本定向只做受控变异（T-MV-01）。
2. **去重（入库）**：五门禁 + 相关性去重；父本子代与父本的相关性**标注但不豁免**（仍须过 corrDup）。
3. **增量（正交）**：残差正交挖掘（T-MV-08）——对池内强因子正交化后只挖解释不了的残差。
4. **验证（排名）**：方向战力榜（T-MV-10）——每类方向产出的因子统一回测排名，供给面回写环 1。

## 3. 维护性设计原则（「后期好维护」的落地清单）

1. **单源清单**（新增能力只扩单源，禁止平行实现）：

   | 概念 | 唯一出处 |
   |---|---|
   | 因子大类分类 | `mining_plugins/factor_classify.py` |
   | 类别/特征目录 | `config/features/model_training_feature_catalog_v1.json` → `fetch_l1_factor_categories` |
   | 因子值库目录（新） | `config/factor_libraries.yaml`（T-MV-06 建） |
   | 拆解提示词 | `direction_decompose.py` 模板 + `PROMPT_VERSION` |
   | 避重/种子注入 | `pool_service.build_injection_digest` / `build_seed_digest`（同构两兄弟） |
   | 入库闸门 | `gates/registry.py` 注册表 |
   | 池排序 | `pool_scoring.py` |
   | 回测指标 | T-FB 纯函数层（只读复用） |

2. **版本化三件套**（decompose 先例复制到一切提示词面）：
   提示词文本改动 → bump `PROMPT_VERSION` → 同步金样 → 契约测试红/绿。历史结果可按版本追溯。

3. **注入层纪律**（decompose 模块 docstring 纪律 3）：上下文注入（类别/池摘要/种子）
   都是**增益层**——加载失败只告警、提示词用显式占位、主链照跑；**绝不静默**：
   请求级问题 400，数据级缺失在 `context` 里如实上报（requested/used/dropped）。

4. **契约显式**：直调测试必须显式传全部 Query 参数（2026-10-10 教训：
   `Query("")` 默认值直调即 AttributeError）；可选字段空则省略；超量截断必报 `dropped`。

5. **只读边界**：并行会话 WIP（`factor_report/*`、factor-research 前端）只读引用；
   T-FB 端点只调用不拷贝；`data/upgrade_v1.1.x.sql` 不碰。

### 本批实施：T-MV-01（父本定向演化）

设计（2026-10-09 会话已定稿，本批实施）：

1. 拆解请求加 `seed_factor_ids: list[str]`（≤3 个；超量 400，请求级问题整包拒绝）。
2. `pool_service.build_seed_digest(seed_factor_ids, user_id, market, universe)`：
   从池内（本用户×本市场×本池，未归档）取 `factor_name/formulation/ic/icir` 渲染
   父本 markdown；不在范围内的 id 丢弃并**如实上报**（UI 选取与提交间存在归档竞态，
   不硬失败）。
3. 提示词注入段「种子因子（父本）——围绕其做系统变异」，变异算子提示：
   滞后/窗长/标准化/差分/比值/非线性；系统提示词纪律加一条：
   给种子时每卡围绕一个父本做一个变异维度、与父本保持显式差异。
4. 卡片可选字段 `seed_factor_id`：LLM 输出后过白名单归一（不在种子集内 → 省略，
   不静默改写成别的 id）；`validate_cards` 增加 `allowed_seeds` 参数 + 金样同步。
5. `PROMPT_VERSION` bump `decompose_v2`；`context` 增 `seeds: {requested, used}`。
6. 前端入口最小化：拆解输入区加「父本因子（可选，≤3）」选择器（取本市场本池
   pool_score **正/反方向各前 N**），卡片上父本徽章。
