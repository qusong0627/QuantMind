## 1. 总体架构

```text
Huntly RSS / 公告 / 研报
  → 新闻门卫 (relevance/source/dedup)
  → 新闻智能体 (L1/L2, event validation, pre5, n_spec, cluster/echo)
  → 研究风控席 (deterministic news_decision)
      ├─ P0/P1 → Redis + news_decisions.json → sentinel / 决策轮唤醒
      └─ all → 新闻主编 (LLM narrative) → latest.json (decisions + risk_overlay)
  → 持仓情报 / 盘中实况 / 晚间复盘 / 宏观政策 / 板块个股
  → 交易智能体 (09:25 / 盘中 / 次日开盘)
```

**两条通道**：
- **快速通道** `scripts/news_fast_risk.py`：1–2 分钟，确定性，扫全部新增 A 股相关页；P0/P1 低延迟。
- **叙事通道** `scripts/news_brief.py`：现有 5 段，读快速通道 decisions；只写解释，不改 decision。

### 2.2 决策规则（v1）

```text
P0: 硬利空 and pre5 > 5%
P1: 硬利空 and 2% < pre5 <= 5%
P2: (硬利好 or 泛利好) and pre5 > 5%
WATCH: 软利空 and -2% <= pre5 <= 5%
WATCH: L1 代码 and 利好
INFO: 其他
```

边界：
- `pre5` 缺失 → `INFO`（不猜）；
- `tier=L2` 不升级为 L1；
- `source_quality` 只调 confidence，不改 decision；
- `layer>=3` 不单独改 decision，写 `no_add=true`；
- `n_speculative` 只进 risk_overlay，不改 decision。

- 交易层无任何读取改动（零行为变化）；

## 3. P1 — 快速通道 + Redis + P0/P1 告警（2–3 天）

### 3.1 交付

| 文件/任务 | 内容 |
|---|---|
| `scripts/news_fast_risk.py` | 增量游标、全量新增 A 股相关页、事件验证、pre5、cluster/echo、n_spec、source_quality、写 JSON/Redis |
| `data/news_brief/fast_state.json` | 游标、去重、失败记账 |
| Redis 写侧 | `qm:news:decision:{date}`、`qm:news:stock:{code}:{date}`、`qm:news:market:{date}` |
| `backend/tests/test_news_fast_risk.py` | 游标、去重、P0/P1、stale、缺数据、source_quality |
| cron/celery | 09:15–15:05 每 2 分钟；盘后每 10 分钟；08:30/15:30/19:05 |

容器内 cron 示例（盘后部署时加）：

```cron
*/2 8-15 * * 1-5  cd /app && python3 scripts/news_fast_risk.py >> /data/logs/news_fast.log 2>&1
```

### 3.2 数据流

1. 读 `fast_state.json` 的 `last_seen`；
2. 从 `/api/v1/news/articles` 拉全部新增页（不设 400 条上限；分桶、分页、time_desc）；
3. 只保留 A 股主体（`n_a_stock>0` / `is_subject`）、非噪音、非聚合；
4. 事件验证（标题关键词 + 公司名/代码 + 否定词 + 多股票名 + 研报评级排除）；
5. 计算 `pre5`（本地日线缓存；缺失 → INFO）；
6. 计算 `cluster_size/layer/echo_count`（同股票+交易日）；
7. 计算 `n_speculative/n_articles/n_sources/source_hhi`（当日累计）；
8. `decide()` → P0/P1/P2/WATCH/INFO；
9. 原子写 `news_decisions.json`；P0/P1 写 Redis + sentinel 队列；
10. 推进游标（只有本轮完整成功才推进；失败保留旧游标，宁可重复不可丢失）。

### 3.3 告警

- P0 持仓：即时告警（QQ/站内），文案 `P0 回避/减仓 … pre5 … 首发 … T+1开盘卖`；
- P0 候选：只进禁买名单，不告警；
- P1 持仓：弱减仓提示，不强制；
- 同一 `decision_id` 只告警一次；同码同向 5 分钟冷却；
- P0 不占日唤醒预算；P1 占预算。

### 3.4 验收

- 影子 2 个交易日：P0 时延中位 <5 分钟，p90 <15 分钟；
- 同一事件不重复告警；
- 断网/坏 JSON/缺 pre5 降级为 INFO 并记 `data_quality`；
- 交易层仍未读取（只写 Redis/JSON）。

### 4.2 `backend/shared/decision_blocks.py::build_news_block`

```
【盘中新闻·决策】
- P0 回避/减仓：...
- P1 弱减仓：...
- P2 不追/不加仓：...
- WATCH：...
- 持仓命中：...
- 池外异动：...
```

P0 置顶；P0 行必须带 `pre5`、`tier`、`layer`、`source`、`reason`。

### 4.3 `decision_round_wake.py`

  - 盘中 90 分钟；

### 4.4 `scripts/live_model_analysis.py::_news_block`

### 4.5 `scripts/night_pool_agent.py`

## 5. P3 — 晚间审计 + 来源质量 + 纸面（2 周）

### 5.1 `scripts/news_review.py`

按 `decision_id` 记录：
- `outcome_1d/5d/20d`（同股同 pre5 安慰剂 DID）；
- `p0_hit`（T+1/T+5 DID<0）、`p1_hit`、`p2_no_chase_hit`（后续 5 日负）；
- `blocked_buy_return`（被 P0/P2 拦截的买入，5 日收益）；
- `missed_opportunity`（被拦截但 5 日大涨）；
- 按 `source × event_type × layer` 更新 `source_quality` / lessons。

### 5.2 `scripts/premarket_builder.py`

- 15:30 / 19:05 / 08:30 生成 `data/news_brief/premarket.json`：
  - `p0`（持仓回避/减仓）
  - `p2`（不追）
  - `watch`
  - `risk_overlay`
  - `data_quality`
- 次日 09:25 交易 agent 读它。

### 5.3 纸面组合

- 用现有交易 agent 信号 + 新闻过滤，做 2026-09~11 纸面组合；
- 对比：不接新闻 vs 接 P0/P2 vs 接 P0/P2+n_spec；

- 验收：P0 过滤后胜率提升 ≥2pp 或回撤下降 ≥1pp，且不显著降低收益；否则只保留告警。

### 5.4 验收

- 审计文件每日生成；
- P0 精确率/召回率月度可解释；
