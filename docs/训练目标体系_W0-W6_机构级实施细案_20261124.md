## 0. 决策摘要（开工前必须拍板）

### D1. 目标注册表落 Postgres，文件仅作导出

**决策**：`qm_label_targets` 表 + 不可变触发器 + 审计表；内置目标由 Python 幂等种子写入。
**理由**：机构级要求版本不可变、创建/启用/废弃可追责、并发创建不互相覆盖。文件注册表无法提供这些保证。
**代价**：新增 `backend/shared/db_migrations/upgrade_v1.1.9.sql`；启动期自动迁移必须幂等且不含破坏性语句（`main_oss.py:553` 有硬约束）。

### D2. 默认硬阻断，逃生开关必须审计

**决策**：以下组合默认 422 / 容器 abort，不再静默降级：
- `classification` × Qlib DL 六类（gru/lstm/alstm/transformer/tcn/tabnet）+ nativetft 阻断；mlp 是 sklearn 实现且支持分类，不在此列；
- `prediction_mode=quantile` × 非 LightGBM / 非 CN / 非 return；
- 排序损失 × 非 LightGBM/XGBoost/CatBoost；
- `sample_weight` × 不支持样本权重的模型（mlp、全部 DL）；
- `label_drop_extreme_pct>0` × classification / top_tail / size_excess（语义未定义）；
- `execution_price=open` 但没有直读 QuantDB 因子源（当前会在加载后才失败）。
**逃生开关**：`QM_TARGET_CAPABILITY_GATE=strict|warn|off`、`QM_LABEL_DIAGNOSTIC_GATE=strict|warn|off`，默认 `strict`；开关值写入模型 metadata 的 `contract_flags`，可审计。

### D3. 旧请求行为零差异，但 metadata 增字段

**决策**：不带 `target_ref` 的请求，`config.yaml` 键集合与训练数值保持逐字节/逐值不变；`metadata.json` 新增 `target_id="legacy"`、`target_hash`、`label_contract_version`、`label_stats`。这是**有意的**可追溯性增强，需更新 metadata 金样，不视为破坏兼容。
**理由**：`config.yaml` 是容器契约，动键集合风险最高；metadata 是消费面，只增不改。

## 1. 问题定义（代码级证据）

### 1.1 目标定义未版本化

- 目标字段平铺在训练请求里：`target_mode` / `target_horizon_days` / `execution_price` / `label_transform` / `label_top_pct` / `label_drop_extreme_pct`（`backend/shared/training/request.py:194-200`）。
- `label_formula` 名字像公式，实际是 `k=v;...` 覆盖通道（`docker/training/train.py:293-320`），且能绕过 API 白名单覆盖 `execution_price` / `label_transform`。
- 模型 metadata 只记录平铺字段（`train.py:1432/1774/2060`），没有 target id/version/hash；同一“T+5”在不同模型间可能口径不同，无法横评。

### 1.2 13 模型能力差异被静默忽略

- classification × Qlib DL：`loading.py:973-976` 把标签二值化，但 Qlib 模型固定 MSE（`trainers_dl.py:365-379`），nativetft 固定 `nn.MSELoss()`（`trainers_dl.py:706`）——训练“成功”，语义是回归 0/1。
- sample_weight × linear/rf/mlp/DL：`registry.py:80-105` 对非三棵 GBDT 只告警并忽略。
- quantile × 非 LightGBM：只在容器入口校验（`train.py:351-366`），提交侧不拦，用户要等容器启动才失败。
- `label_transform` × classification：`loading.py:986` 分类分支完全跳过截面变换，前端仍展示下拉（`TrainingTargetConfig.tsx:163-176`）。

### 1.3 目标与回测口径已解耦，但缺少守卫

标签由 `label.target_horizon_days` + `label.execution_price` 独立构造（`loading.py:790-847`），回测只用 `context.deal_price`。目前没有源码级守卫防止未来把两者重新耦合。

### 1.4 机构验收缺口

| 机构要求 | 现状 | 结论 |
|---|---|---|
| 同目标跨模型可横评 | 只有平铺字段，无 target id/hash | 不满足 |
| 目标定义不可变、可追责 | 无注册表、无审计 | 不满足 |
| 训练前拒绝无效组合 | 多处静默降级或晚失败 | 不满足 |
| 标签质量可核验 | 仅 classification 打印正负样本数 | 部分 |
| 模型产物可复现 | 有 config/data fingerprint，无 label hash | 部分 |
| 旧模型/旧脚本不中断 | —— | 必须保持 |

## 2. 机构级设计原则（所有 WP 必须遵守）

1. **单一事实源**：13 模型能力、目标族、排序损失集合只在 `backend/shared/training/capabilities.py` 定义；其它模块 import，不得复制。
2. **冻结与自校验**：目标在提交时冻结成 `spec + hash` 写入 config；容器重新校验 hash 与平铺字段一致性，不信任外部文件。
3. **纵深防御**：提交 API、编排器、容器入口三层校验同一规则；任一层可独立拒绝。
4. **失败显式化**：禁止“告警后继续”代替能力校验；逃生开关必须显式设置并记录。
5. **不可变版本**：同一 `(target_id, version)` 内容永不修改；改口径必须升 version。
6. **可追溯**：每次训练记录 target 三元组、contract flags、标签诊断；每次注册表变更写审计。
7. **旧路径零差异**：legacy 请求的 config 键集合与训练结果不变；所有新增字段仅在新路径出现（metadata 例外，见 D3）。
8. **统计有效性**：标签 NaN 率、正类率、每日截面数、test 尾部完整性在容器内硬校验；不合法即失败。
9. **安全边界**：不支持任意表达式求值；机构自定义标签只允许通过注册表或 P2 的 `external_column`。
10. **可回滚**：所有行为开关默认严格，但可一键降级到 legacy；DB 表保留不删。

## 3. 目标定义模型（LabelTargetSpec）

### 3.1 字段表（P1）

| 字段 | 类型 | 必填 | 默认 | 约束 | 语义 |
|---|---|---|---|---|---|
| `target_id` | string | 是 | — | `^[a-z][a-z0-9_]{2,63}$` | 稳定标识，不含版本 |
| `version` | int | 是 | — | `>=1` | 不可变版本号 |
| `market` | enum | 是 | — | `CN/HK/US/CRYPTO/FUTURES/CUSTOM` | 必须与 `context.market` 一致 |
| `family` | enum | 是 | — | P1：`forward_return/classification_binary/quantile_return` | 标签构造族 |
| `mode` | enum | 是 | — | `regression/classification/quantile` | 必须与 family 匹配 |
| `horizon_days` | int | 是 | — | `1..30` | T+N 的 N（交易日） |
| `entry.lag_days` | int | 是 | `1` | P1 只能为 `1` | 执行滞后；治理锁，防前视 |
| `entry.price` | enum | 是 | `open` | `open/close` | T+1 入场价 |
| `exit.price` | enum | 是 | `close` | P1 只能为 `close` | T+1+N 出场价 |
| `transform.type` | enum | 是 | `rank` | `rank/zscore/raw/top_tail/size_excess_rank/size_excess_zscore` | 截面标签变换 |
| `transform.top_pct` | float | 否 | `0.2` | `0.05..0.5`；仅 `top_tail` 可非默认 | 尾部比例 |
| `transform.drop_extreme_pct` | float | 否 | `0.0` | `0..0.2`；仅 `forward_return + rank/zscore/raw` 可 >0 | 训练段极端标签剔除 |
| `label_contract_version` | int | 是 | `1` | `==1`（P1） | 契约版本，容器据此拒绝未知 |
| `description` | string | 否 | `""` | `<=500` | 人读说明 |

**P1 不放进 spec 的字段**（避免“字段存在但未实现”的误导）：分类阈值/死区/类权重、中性化、成本、universe、样本权重。样本权重是训练策略，不是标签定义。

### 3.2 规范化与哈希

```python
canonical = json.dumps(
    spec.model_dump(mode="json"),
    sort_keys=True,
    separators=(",", ":"),
    ensure_ascii=False,
    allow_nan=False,
)
spec_hash = hashlib.sha256(canonical.encode("utf-8")).hexdigest()
```

规则：
- `spec_hash` 覆盖完整 spec（含 id/version），任何字段变化都改变 hash。
- 容器收到 `target_spec` 后必须重新 `LabelTargetSpec.model_validate`，再按同一函数计算 hash；不一致即 abort。
- 禁止用 YAML 文本哈希；YAML 序列化差异不得影响 hash。

### 3.3 覆盖白名单（overrides）

| family | 允许覆盖 | 说明 |
|---|---|---|
| `forward_return` | `horizon_days`、`transform.type`、`transform.top_pct`、`transform.drop_extreme_pct` | 不允许改 `entry/exit`（执行口径治理锁） |
| `classification_binary` | `horizon_days` | 不允许 transform/drop extreme |
| `quantile_return` | 无 | 分位水平固定 `0.1/0.5/0.9` |

覆盖后必须重新走完 3.1 的全部约束；覆盖不能把目标变成另一个 family。

### 3.4 状态机

```
draft ──activate(admin)──> active ──deprecate(admin)──> deprecated
   │                                                        ▲
   └──────────────deprecate(admin)──────────────────────────┘
```

- 新训练只允许 `active`；`draft` 仅 `allow_draft_target=true`（管理员）且强制 `deploy_to_production=false`、metadata `research_only=true`。
- 历史模型的滚动重训：只要 `target_hash` 与 metadata 一致，允许使用 `deprecated` 版本；新的 target_ref 不允许。
- 状态转换只允许上图路径，DB 触发器强约束。

- DL 无 GPU 只是 warning（`train.py:579`），不是硬性要求；表中不列 GPU。

### 4.3 组合规则

1. 多模型 `model_types` / ensemble：目标能力取**交集**；任一成员不支持即 422，错误信息列出不支持成员。
2. `prediction_mode=quantile`：要求 family=`quantile_return`、唯一模型 LightGBM、`context.market=CN`；反之 family=`quantile_return` 要求 prediction_mode=quantile。二者必须一致。
3. 排序损失：只允许三棵 GBDT；要求有按日分组（训练端自动排序），目标 family 必须是 `forward_return`（P1）。classification + 排序损失 422。
4. `label_transform=size_excess_*`：要求特征列表包含 `total_cap`，且仅 `forward_return`。
5. `label_drop_extreme_pct>0`：仅 `forward_return` + `rank/zscore/raw`；classification/top_tail/size_excess 422。
6. classification：`label_transform` 只能是默认 `rank`（训练端跳过变换）或空；`label_top_pct` 不能偏离默认 `0.2`；否则 422。
7. 非 top_tail 的 `forward_return`：`label_top_pct` 必须为默认 `0.2`，否则 422（防隐藏参数）。
8. `entry.price=open`：要求提交时存在直读因子源（`factor_source` 非空且为 QuantDB 直读）；legacy 快照路径不支持。

### 4.4 objective/metric 派生规则

| 目标 | 规则 | 处理 |
|---|---|---|
| forward_return | **拒绝**二分类 objective（`binary/binary:logistic/Logloss/CrossEntropy*`）；排序 objective 只允许三棵 GBDT；其余回归 objective 原样透传（保持现有灵活性） | 冲突 422 `target_objective_conflict` |
| classification_binary | 只允许空或本模型的二分类 objective/metric；训练器仍强制覆盖为 binary/Logloss 与对应 metric | 冲突 422 |
| quantile_return | objective/metric 必须为空 | 非空 422 |

提交侧对冲突值返回 422 `target_objective_conflict`；不允许“页面选了但训练器覆盖”。

## 5. 端到端契约

### 5.1 提交（API）

新增请求字段（`TrainingRequest`，`backend/shared/training/request.py`）：

```json
{
  "target_ref": {"id": "cn_ret_5d_open_rank", "version": 1},
  "label_overrides": {"horizon_days": 10}
}
```

- `target_ref` 与 `label_overrides` 只做**形状**校验（dict、键存在、类型），值解析在 `_normalize_payload`（有 DB 的异步层）。
- 旧平铺字段全部保留。若同时传 `target_ref` 与平铺字段：平铺字段视为 overrides 的一部分，必须通过白名单；否则 422。
- 13 个独立入口（`training_per_model.py`）的 `_SHARED_FIELDS`（`per_model.py:18`）加入 `target_ref` / `label_overrides`，否则 per-model schema `extra="forbid"` 会 422。
- `label_formula` 含 `=` 且同时有 `target_ref` → 422 `target_formula_override_forbidden`；legacy 路径保留但 W3 后弃用。

### 5.2 解析与冻结（`_normalize_payload`）

顺序：
1. `TrainingRequest.validate_request(payload)`（纯形状/枚举）。
2. `resolve_target_contract(payload, market)`：
   - 有 `target_ref`：从注册表取 `(id, version)`，检查状态/市场，应用 overrides，重算 hash；
   - 无 `target_ref`：从平铺字段合成 legacy spec，`target_id="legacy"`，`version=0`，status=`legacy`，hash 照算。
3. `validate_target_capability(spec, model_types, prediction_mode, sample_weight, objective/metric)`。
4. 预检：`open` 价格需直读因子源；`size_excess` 需 `total_cap`；`drop_extreme` 语义。
5. 把规范化结果写回 payload：
   - `target_ref`、`target_meta`（id/version/hash/status/spec）；
   - 平铺 label 字段**由 spec 派生**（有 target_ref 时不再信任请求里的平铺值）；
   - legacy 路径平铺字段保持原值。

**关键约束**：`_normalize_payload` 是唯一写 `target_meta` 的地方；`submit_training_job` 把 `target_meta` 存入 `TrainingJobRecord.request_payload`。

### 5.3 config.yaml（编排器）

有 `target_ref` 时，`LabelCfg` 增加：

legacy 请求：**不新增任何键**，键集合与当前完全一致。

序列化实现：`LabelCfg` 新字段用 `None` 默认；`dump_contract_dict` 或 `_build_config_yaml` 只在 `target_meta` 存在时写入，避免 legacy 键集合漂移。`TrainingConfig` schema 的 `LabelCfg` 加类型但不改变默认序列化。

### 5.4 容器自校验（`docker/training/train.py`）

入口顺序（`main()`）：

1. `_apply_label_formula_overrides(cfg)`（legacy 兼容；有 target_spec 时禁止覆盖键）。
2. `TrainingConfig.from_dict(cfg)`（现有 gate）。
3. **新增** `validate_training_target_contract(cfg, model_type)`：
   - `label_contract_version` 已知；
   - `target_spec` 可解析，hash 匹配；
   - 平铺字段与 spec 一致（horizon/mode/execution_price/transform/top_pct/drop_extreme）；
   - 能力规则（同一 `capabilities.py`）；
   - `label_formula` 不含覆盖键（有 target_spec 时）。
4. `QM_TRAIN_VALIDATE_ONLY=1`：完成 1–3 后直接 `return 0`（部署冒烟，不加载数据）。
5. `load_data(...)`。
6. 切分后计算 `label_stats`，执行标签诊断门（5.5）。

### 6.1 `qm_label_targets`

```sql
CREATE TABLE IF NOT EXISTS qm_label_targets (
    id              TEXT        NOT NULL,
    version         INTEGER     NOT NULL CHECK (version >= 1),
    market          TEXT        NOT NULL,
    family          TEXT        NOT NULL,
    mode            TEXT        NOT NULL,
    spec            JSONB       NOT NULL,
```

### 6.2 不可变触发器

```sql
CREATE OR REPLACE FUNCTION qm_label_targets_guard() RETURNS trigger AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION 'qm_label_targets is append-only';
    END IF;
    IF NEW.id <> OLD.id OR NEW.version <> OLD.version
       OR NEW.spec IS DISTINCT FROM OLD.spec
       OR NEW.spec_hash <> OLD.spec_hash
       OR NEW.market <> OLD.market
       OR NEW.family <> OLD.family
       OR NEW.mode <> OLD.mode THEN
        RAISE EXCEPTION 'qm_label_targets spec is immutable';
    END IF;
    IF NOT (
        (OLD.status = 'draft'  AND NEW.status = 'active')
     OR (OLD.status = 'active' AND NEW.status = 'deprecated')
     OR (OLD.status = 'draft'  AND NEW.status = 'deprecated')
    ) THEN
        RAISE EXCEPTION 'invalid target status transition: % -> %', OLD.status, NEW.status;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS trg_qm_label_targets_guard ON qm_label_targets;
CREATE TRIGGER trg_qm_label_targets_guard
BEFORE UPDATE OR DELETE ON qm_label_targets
FOR EACH ROW EXECUTE FUNCTION qm_label_targets_guard();
```

`DROP TRIGGER` 不在启动迁移的破坏性关键字列表内（`main_oss.py:558-575` 只拦 DROP TABLE/SCHEMA/DATABASE/COLUMN、TRUNCATE、DELETE FROM），可自动执行。

### 6.3 审计表

| 13 个 per-model 入口 | 新增字段后仍 `extra="forbid"`；旧 body 不变 |
| 外部 task API（`extra=allow`） | 原样转发；无需改 schema |
| 多市场 | spec.market 必须匹配；其它市场走 legacy 或自建 target |
| 便携包 | 迁移随 `data/upgrade_*.sql` 自动执行；需在便携包构建验证中加“迁移两次”检查 |
| 旧前端草稿 | `normalizeTrainingTarget` 补默认；无 targetRef 显示 legacy |

## 11. 上线与回滚 Runbook（摘要）

### 上线顺序
1. **DB**：发布 `backend/shared/db_migrations/upgrade_v1.1.9.sql`（API 启动自动执行）；手动验证两次幂等。
2. **API**：部署含 W1/W2/W3 的镜像；先设 `QM_TARGET_CAPABILITY_GATE=warn` 观察 24h（可选：灰度按 tenant）。
3. **训练镜像**：部署含 W3 校验的镜像；跑 `QM_TRAIN_VALIDATE_ONLY=1` 冒烟（legacy + target_ref）。
4. **前端**：部署 W4 构建；强刷验证。
5. **切 strict**：确认无异常后设 `strict` 并重启 API。
6. **观察**：24h 内统计 blocked/failed；记录到发布说明。

### 回滚
1. `QM_TARGET_CAPABILITY_GATE=warn`、`QM_LABEL_DIAGNOSTIC_GATE=off`，重启 API。
2. 回滚 API/前端/训练镜像到上一版本。
3. DB 表保留；不执行 DROP。
4. 若 cache key 已变更，回滚后旧缓存可能重新命中——Runbook 要求回滚时清空 `QM_TRAIN_CACHE_DIR`（或接受首轮旧标签风险？不：必须清空，避免口径混淆）。

### 监控/审计查询
```sql
-- 被拒组合
SELECT action, detail->>'code' AS code, count(*)
FROM qm_label_target_audit
WHERE action='blocked_resolve' AND at > now() - interval '24 hours'
GROUP BY 1,2 ORDER BY 3 DESC;

-- 目标使用分布
SELECT target_id, target_version, count(*)
FROM admin_training_jobs
WHERE created_at > now() - interval '7 days'
GROUP BY 1,2;
```
（`admin_training_jobs` 列名以实际 schema 为准；若为 `request_payload->'target_meta'`，用 JSONB 查询。）

### C. 机构验收清单（给风控/研究负责人）

- [ ] 每个在用模型能回答：target_id、version、hash、标签公式、执行价、horizon、变换。

- [ ] 文档、Runbook、审计查询可用。

### D. 明确不做（防 scope creep）

- 不在 P1 引入分类阈值/死区/类权重（P2）。
- 不在 P1 引入中性化、成本后标签、三重障碍、external_column（P2/P3）。
- 不改推理算法、不改回测引擎、不改组合构建。
- 不做任意公式求值（安全边界）。
- 不批量改写历史模型 metadata（lazy 合成）。

### E. 与既有机构级能力的衔接（不重复建设）

| 既有能力 | 位置 | 与 Target Contract 的关系 |
|---|---|---|
| Purge/embargo（horizon+lag） | `backend/shared/training/rolling_window.py:120-128`、`data/splits.py` | target 的 horizon 是 purge 的唯一来源；target 变更自动带动净化带 |
| WFA/滚动训练 | `wfa` 配置、`rolling_window.py`、`rolling_dispatch.py` | 每个窗口复用同一 target hash；W5 保证不漂移 |
| 多 seed 稳定性 | `backend/scripts/multi_seed_dispatch.py` | target 作为 dispatch 参数的一部分；同 target 多 seed 结果可横评 |
| 样本权重（可交易/ST/时间衰减） | `docker/training/sample_weights.py` | 是训练策略不是标签；能力矩阵负责拒绝不支持的模型 |
| 数据指纹 | `docker/training/data/fingerprint.py` | 与 target_hash 一起构成“标签+数据”复现两件套 |
| 四道闸 | `docker/training/model_trainers/gates.py` | 评估面；target 变更后必须重跑，不得复用旧闸结果 |
| 评估/成绩单 | `backend/shared/score_window.py`、模型成绩单 | 消费 metadata 的 target 三元组；跨 target 不合并 |

**原则**：Target Contract 只定义“学什么”，不重复定义“怎么评估、怎么交易、怎么加权”。评估口径与执行口径继续由既有模块单源负责。
