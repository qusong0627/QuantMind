# 美股模型训练 / 推理 / 模型管理链路

> 面向维护者。记录 QuantUS（美股）在这三条链路上的**实际接线**、必须知道的配置项，
> 以及本次实测中定位并修掉的问题。A 股/港股的差异只在文中注明处。

## 一、训练链路

```
前端训练页 (ModelTrainingPage)  市场上下文取自顶部市场切换器 (uiSlice.currentMarket)
  ↓ POST /api/v1/models/run-training
submit_training_job (routers/admin/admin_training_utils.py)
  ├─ _resolve_market(context.market | benchmark 推断)      → market
  ├─ _resolve_quantdb_factor_payload(payload, market)      → 校验因子目录版本 + 钉死字段映射
  ├─ 写 admin_training_jobs 记录 (pending)
  └─ get_orchestrator(node_id) → launch_training_job
        ↓
   三选一执行体（training_runtime.resolve_training_executor）
   ├─ local_docker（默认）：起一次性训练容器 qm-train-{run_id}
   ├─ remote_ssh：AutoDL GPU 节点（**拒绝非 CN 的直读因子源**，美股只能走快照路径）
   └─ local_process：免 Docker 便携包
        ↓
   容器命令: sh -c "<bootstrap pip> && python /app/train.py --config /workspace/config.yaml"
        ↓
   训练完成 → POST /api/v1/models/training-runs/{run_id}/complete
        ↓
   _normalize_training_result_payload 校验（metrics / artifacts / summary 必填）
        ↓
   model_registry.register_model_from_training_run → 落盘 + 写 qm_user_models
```

### 美股关键配置（实测值）

| 项 | 值 | 说明 |
|----|----|------|
| `context.market` | `US` | 一切市场分支的唯一来源 |
| `context.benchmark` | `SPX` | 也可由 benchmark 反推 market |
| `data.factor_source` | `l1_factors` | 推荐路径：直读 `data/quantus/6_ml_datasets/l1_factors` |
| 因子目录版本 | `qdb-us-l1_factors-acecfaac0a9d` | 查 `qm_training_factor_catalog_version`（status=published） |
| 数据根 | `/data/quantus` | 容器内挂载为训练容器的 `/tmp/quantus_data` |
| 训练脚本 | `docker/training/train.py` | 整目录挂载覆盖镜像内快照 |

### 小批量验证（13 模型全测）

```python
payload = {
  "context": {"market": "US", "benchmark": "SPX"},
  "factor_source": "l1_factors",
  "factor_catalog_version": "qdb-us-l1_factors-acecfaac0a9d",
  "features": [...],                    # 从目录取，见下方「死特征」
  "model_types": [...13 个模型类型...],
  "target_horizon_days": 5, "target_mode": "return", "prediction_mode": "point",
  "train_start": "2025-01-02", "train_end": "2025-12-31",
  "valid_start": "2026-01-02", "valid_end": "2026-04-30",
  "test_start": "2026-05-01", "test_end": "2026-08-05",
  # 小批量关键：DL 默认 200 epochs，8 个 DL 模型在 CPU 上要跑 9 小时+
  "dl_params": {"n_epochs": 8, "early_stopping_rounds": 3, "batch_size": 4000},
  "num_boost_round": 60, "early_stopping_rounds": 20,
}
```

实测耗时（CPU，167 特征 / 19.3 万行）：树模型 90-180s/个，DL 模型约 3.5 分钟/个，
13 个模型合计约 35 分钟。**不设 `dl_params.n_epochs` 会跑到 9 小时以上。**

### 13 个模型类型（model_trainers/registry.py）

- 树/sklearn（5）：`lightgbm` `xgboost` `catboost` `linear` `random_forest`
- DL（8）：`gru` `lstm` `alstm` `transformer` `tabnet` `tcn` `nativetft` `mlp`

## 二、推理链路

```
POST /api/v1/models/inference/run  (或 /inference/batch)
  → _execute_single_day_inference  (model_training.py)
    → InferenceRouterService.run_daily_inference_script
      → InferenceScriptRunner.execute
        → subprocess: {model_dir}/inference.py --date ... --market US
```

- `--market` 来自**模型自己的** `metadata.json → context.market`（`script_runner.py`）。
  非 CN 会额外关闭 alpha158 兜底（避免被 A 股兜底信号污染），生效日日历用 `XNYS`。
- 因子数据目录同样由 `context.market` 决定（`_resolve_market_factor_data_dir`）。
- 信号落 `engine_signal_scores`，`universe_tag = 'US'`。

### symbol 口径（美股）

`engine_signal_scores.symbol` 对美股**原样存 ticker**（`AAPL` / `BRK.B`），
不做 A 股那套「剥 SH/SZ/BJ 前缀 + 切点」——美股 ticker 与交易所前缀同形
（`SHOP`/`SHW`/`BJ`/`SHAK`），误用会静默改成 `OP`/`W`/空/`AK`。

## 三、模型管理

- 落盘：`models/users/{tenant}/{user}/{market小写}/{model_id}`（**非 CN 才有市场子目录**）。
- `model_id`：`mdl_{market小写}_{run_id}_{8位hex}`。
- 注册表：PG `qm_user_models`，**没有 market 列**，市场存在 `metadata_json->>'market'`，
  缺失按 `COALESCE(..., 'CN')` 处理。查询一律带 `?market=`。
- 前端用户侧模型库（`ModelRegistryPage`）按顶部市场切换器过滤，链路正常。
- 管理后台模型扫描按 `metadata.market` 识别市场，读不到会显示成「A股」。

## 四、美股数据面的已知限制

| 项 | 现状 | 影响 |
|----|------|------|
| **8 个基本面特征恒为 0** | `pe_ttm/pb/roe/bp/ep_ttm/float_mv/total_mv/turnover_rate` —— `update_market_features.py` 对美股显式填 0（QuantUS 源缺这些列） | 选进特征等于白占维度 |
| **4 个行业特征恒为空** | `ind_ret_1d/ind_ret_20d/ind_strength_20/ind_momentum_rank_20` 全历史 NULL | 同上；**行业分类数据其实存在**（`2_base_sector/sector/*.parquet` 的 GICS），可自行计算补齐 |
| `ln_mv_total` 名不副实 | 美股走 `np.log(amount)` 兜底（≈20），**实为对数成交额而非对数市值** | 用它做市值因子的解释要留意 |
| 快照 `model_features_us.parquet` | 停在 2026-08-07（源数据到 09-10） | 仅影响旧快照路径；直读因子源不受影响 |
| Qlib 缓存 `.qlib_cache/us_data` | 日历停在 2026-09-01 | 影响回测，不影响推理 |
| 因子目录 `refreshed_at` | 2026-08-27 | 前端「建议区间」偏保守 |

## 五、运维注意

- **训练会暂停其它容器腾内存**：`_pause_others` 停掉所有不在
  `TRAINING_PROTECTED_NAME_PREFIXES` 名单内的运行中容器，训练结束后恢复。
  **新增业务容器时务必把前缀补进名单**（`docker-compose.yml`），否则训练期间会被停掉。
- **改后端要重启 api 子进程**：编排器跑在 api 服务进程里，新增/修改路由与编排逻辑后
  必须让 api 子进程重启（看门狗自动拉起），否则仍旧代码。
- **训练脚本走外挂载**：`docker/training/` 整目录挂进容器，改 train.py 不用重建镜像；
  但**镜像内还烘焙了一份旧副本**（`/app/train.py`），process 模式下曾被它遮蔽
  （已修：候选顺序改为活源码优先）。
