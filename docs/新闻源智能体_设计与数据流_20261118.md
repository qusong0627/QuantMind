# 新闻源智能体 — 设计与数据流（2026-11-18）

> 目标：把 2026-11-18 新闻研究的结论接进现有实盘新闻 Agent 管线，让 **盘中实况 / 新闻主编 / 晚间复盘 / 持仓情报 / 宏观政策 / 板块个股 / 新闻门卫 / 新闻智能体** 各自知道“看到新闻该做什么”，并把结构化决策送到盘中决策轮和次日开盘交易智能体。
>
> 原则：新闻层**只出决策与风险标记，不下单**；交易层拿到的是**决策信封**，不是原始新闻；P0 是唯一通过决策回测的动作，其余是风险/观察。

---

## 0. 现有链路（先认清）

| 层 | 文件/入口 | 现状 |
|---|---|---|
| 新闻管线 | `scripts/news_brief.py` | 5 段：news-gate / news-macro / news-micro / news-holdings / news-chief；产出 `data/news_brief/latest.json` |
| 盘中观察 | `data/news_brief/intraday_watch.json` | 池外异动，L2 轮询合并；TTL 60 分钟 |
| 晚间复盘 | `scripts/news_review.py` | 当日新闻 vs 当日涨跌 → `lessons.json`（事件类型×来源命中率） |
| 次日候选 | `scripts/night_pool_agent.py` | 读 `latest.json`，把新闻主线/持仓信号并入选股 |
| 决策轮 | `backend/services/trade/services/decision_round_feeds.py` | `read_news_files()` 读 `latest.json` + `intraday_watch.json` |
| 决策轮渲染 | `backend/shared/decision_blocks.py::build_news_block` | 丁4【盘中新闻】只渲染 holdings 命中 + 池外异动 |
| 唤醒 | `backend/services/trade/services/decision_round_wake.py` | `NewsHit` + `TRIGGER_NEWS_IMPACT=1.0`；简报新鲜窗 480 分钟 |
| 模型分析 | `scripts/live_model_analysis.py::_news_block` | 把 `latest.json` 摘要注入 arena 各模型提示词 |
| P0 推送 | `backend/services/trade/services/sentinel_alert_service.py` | 成交/风控/止损 P0；新闻 P0 尚未独立成级 |

**关键事实**：`latest.json` 已经是交易/研究唯一入口；不要另起一套平行文件。所有新增字段进 `latest.json`，同时落一份 `news_decisions.json` 供低延迟读取。

## 1. 目标架构

```text
Huntly RSS / 公告 / 研报
        │
        ▼
[新闻门卫]  relevance / source_tier / dedup / aggregator / procurement
        │  输出：clean_pages（全部 A 股相关，不砍成 400 条）
        ▼
[新闻智能体]  L1/L2/L3 + 事件验证 + pre5 + n_spec + cluster/echo
        │  输出：news_event（一条事件一个 decision_id）
        ▼
[研究风控席]  确定性规则（无 LLM）：
        │   P0/P1/P2/WATCH/INFO + action + reason + as_of
        ├──────────────► Redis qm:news:decision:{date}
        │                news_decisions.json
        │                P0/P1 → 即时告警 / 决策轮唤醒
        ▼
[新闻主编]  LLM 只做叙事与汇总，不新增代码、不改 decision
        │  输出：latest.json（decisions + risk_overlay + narrative）
        ▼
[持仓情报] [盘中实况] [晚间复盘] [宏观政策] [板块个股]
        │
        ▼
[交易智能体]  09:25 开盘 / 盘中决策轮 / 次日开盘
        └─ 读取 decision 信封：P0 回避/减仓；P2 不追；WATCH 观察；INFO 不动作
```

**两条通道**：

1. **快速通道**（新增 `scripts/news_fast_risk.py`，每 1–2 分钟）：
   - 只做确定性：L1/L2、事件验证、pre5、cluster/echo、source_quality、n_spec；
   - 扫**全部**新增 A 股相关页（不受 `MAX_TITLES=400` 限制）；
   - 写 `news_decisions.json` + Redis；P0/P1 立即推送；
   - 不调用 LLM，延迟可控。
2. **叙事通道**（现有 `news_brief.py`，09:25/09:55/10:55/12:55/13:55/19:05）：
   - 门卫→宏观→板块→持仓→主编；
   - 读快速通道的 decisions，主编只写“为什么/怎么读”，不重算 P0；
   - 产出 `latest.json`，供盘中决策轮和次日候选使用。

## 2. 角色重定义

### 2.1 新闻门卫（news-gate）

| 项 | 现状 | 新增 |
|---|---|---|
| 职责 | 金融相关/噪音/粗分 macro/micro/holdings | 保持；加 `source_quality`、`first_seen`、`is_dup`、`cluster_id` |
| 输入 | 标题+标签证据 | 全部新增 A 股相关页（快速通道不设 400 条上限） |
| 输出 | 黑名单式例外行 | `clean_pages` + `gate_meta`（source_tier、dedup、aggregator、procurement） |
| 不做 | 不下单、不判 P0 | 不变 |

**来源分层**：保留现有 `_TIER_S/A/B/X`（相关性/速度），另加 `source_quality`（研究 adj_did5）：
- 好：新浪财经、人民日报、东财行业研报、集思录、同花顺实时、ulapia 个股研报；
- 差：东财快讯、财联社电报、财联社热榜、7x24、格隆汇快讯、商业 Google。
- **快讯只做“事件发现”，不做 alpha**；`source_quality` 只调 confidence，不单独改 decision。

### 2.2 新闻智能体（tagger/matcher）

| 项 | 新增 |
|---|---|
| 层级 | L1 代码 / L2 标题主体 / L3 正文提及 / L4 实体情绪；L2 不升级为 L1 |
| 事件验证 | 标题含关键词 + 标题含公司名/代码 + 否定词 + 多股票名 + 研报评级排除 |
| 数值 | `pre5`、`pre5_bucket`、`cluster_size`、`layer`、`echo_count`、`n_speculative`、`n_articles`、`n_sources`、`source_hhi` |
| 输出 | `news_event`（一条事件一个 `decision_id`） |

### 2.3 研究风控席（新增，确定性，无 LLM）

这是整套设计的核心：把研究结论变成**可复现的决策**。

```python
def decide(event, stock_day, source, now):
    if event.category == "硬利空" and stock_day.pre5 > 0.05:
        return P0("reduce", "hard_risk_high_pre5")
    if event.category == "硬利空" and stock_day.pre5 > 0.02:
        return P1("weak_reduce", "hard_risk_mid_pre5")
    if event.category in ("硬利好", "泛利好") and stock_day.pre5 > 0.05:
        return P2("no_chase", "positive_high_pre5")
    if event.category == "软利空" and -0.02 <= stock_day.pre5 <= 0.05:
        return WATCH("watch", "soft_risk_bounce")
    if event.tier == "L1" and event.direction == "利好":
        return WATCH("observe", "l1_positive")
    return INFO("none", "no_action")
```

风险 overlay（独立于 decision，写给交易层）：

```python
risk_overlay = {
    "n_spec_pct": percentile(stock_day.n_speculative),  # 前 20% = high
    "n_articles_pct": percentile(stock_day.n_articles),
    "n_sources_pct": percentile(stock_day.n_sources),
    "source_hhi": stock_day.source_hhi,
    "echo_share": stock_day.echo_share,  # 注意与 n_articles 共线
    "position_hint": "de_risk" if n_spec_pct >= 0.8 else "normal",
    "stop_hint": "wider" if n_spec_pct >= 0.8 else "normal",
}
```

### 2.4 新闻主编（news-chief）

- 输入：门卫/宏观/板块/持仓 + **风控席 decisions**；
- 输出：`latest.json` 增加：
  - `decisions`: 逐票 P0/P1/P2/WATCH/INFO；
  - `risk_overlay`: 市场级/个股级；
  - `data_quality`: `as_of`、`first_seen`、`stale`、`coverage`、`missing`；
  - 原有 `macro/themes/watch_list/open_risks/holdings/editor_note` 保留；
- **硬约束**：主编不得新增代码、不得把 WATCH 改成 P0、不得出现“买入”字眼；`decisions` 由风控席生成，主编只写解释。

### 2.5 持仓情报（news-holdings）

- 输出 `per_stock` 增加：`decision`、`pre5_bucket`、`layer`、`n_speculative`、`source_quality`；
- 规则：
  - P0 持仓 → 风险告警，T+1 开盘处理；
  - P2 利好 + pre5>5% → 不加仓；
  - 同股同日 `layer>=3` → 不再按新闻方向加仓；
  - `n_speculative` 前 20% → 降仓位/放宽止损；
  - 无证据只输出 `C | 0`（现有约束保留）。

### 2.6 盘中实况（intraday live）

- 消费快速通道 `news_decisions.json` + `intraday_watch.json`；
- 只做：
  - 持仓 P0：即时告警（不自动下单）；
  - P1：弱减仓提示；
  - P2：不追/不加仓；
  - L2 利好：不追；L2 利空：不追空；
  - 概念板块利空：减仓/回避；
  - 炸板/失败板：回避；
- 不做：按新闻方向开新仓、午后硬利空单独动作。

### 2.7 晚间复盘（news-review）

- 现有：当日 verdict vs 当日涨跌 → lessons；
- 新增：
  - 按 `decision_id` 记录 T+1/T+5 的 DID（同股同 pre5 安慰剂）；
  - 评估 `P0 precision/recall`、`P2 no-chase` 是否正确、`WATCH` 是否该降级；
  - 按 `source × event_type × layer` 更新 `source_quality` / lessons；
  - 产出次日 `premarket.json`：P0 名单、不追名单、观察名单、风险 overlay；
  - 只做先验/权重，不做硬闸门（现有边界保留）。

### 2.8 宏观政策（news-macro）

- 现有：大盘方向/主线/风险；
- 新增：
  - 政策类型 × 板块的显著格（证券/保险政策簇正；电池负）；
  - 新闻量/风险占比作为**风险 overlay**，不做方向择时；
  - 海外/中国过滤；政策是慢变量，不用于盘中。

### 2.9 板块个股（news-micro）

- 现有：主题/事件/轮动；
- 新增：
  - 板块利空（概念板块 post5 -2.0bp、post30 -7.3bp）；
  - 主题生命周期只做展示（P2 失效）；
  - 跨市场映射只做 regime 记录（P1/P2 符号翻转）；
  - 涨停生态：炸板回避；首板不追持有。

### 3.3 Redis 键（低延迟）

| 键 | 内容 | TTL |
|---|---|---|
| `qm:news:decision:{YYYYMMDD}` | 当日全部 decision 信封（hash by code） | 2 天 |
| `qm:news:stock:{code}:{YYYYMMDD}` | 单票 decision + risk overlay | 2 天 |
| `qm:news:market:{YYYYMMDD}` | 市场级 risk overlay | 2 天 |
| `qm:news:intraday:{code}` | 盘中 P0/P1 最新一条 | 6 小时 |

写侧：快速通道（trade 库 db2 或独立 news 库，必须与读侧同库）；读侧：决策轮/交易智能体。**不要用哨兵 db0 写、交易 db2 读**——这是现有 QQ 速览的结构性空转陷阱。

## 4. 交易智能体怎么拿、怎么判

### 4.1 09:25 开盘前

读取顺序：
1. `latest.json`（昨日 19:05 版 + 今早 09:25 版）；
2. `news_decisions.json`（含隔夜/盘前 P0/P1/P2）；
3. `premarket.json`（晚间复盘生成的次日名单）。

注入交易提示词：

```text
【新闻决策·开盘】
- P0 回避/减仓：600519.SH 贵州茅台 — 硬利空/立案，pre5+7.2%，首发，T+1开盘卖；若开盘跌停/停牌，盘中/次日处理
- P2 不追：300750.SZ 宁德时代 — 利好+pre5>5%，不加仓
- 风险 overlay：n_spec 前 20% 的持仓（...）降仓位/放宽止损
- 数据：as_of 09:25，stale=false
```

### 4.2 盘中决策轮

`build_news_block` 改为：

```text
【盘中新闻·决策】
- P0 回避：...
- P1 弱减仓：...
- P2 不追：...
- WATCH：...
- 池外异动：...
- 风险 overlay：...
```

顺序：**P0 → P1 → P2 → WATCH → 持仓命中 → 池外异动**；P0 在前，避免被叙事淹没。

### 4.3 唤醒（decision_round_wake）

- `NewsHit` 增加 `decision`、`pre5`、`layer`、`decision_id`；
- 触发：
  - `decision == P0` 且持仓命中 → 立即唤醒（不受 `DAILY_WAKE_LIMIT` 限制，但按 `decision_id` 去重，同码同向 5 分钟冷却）；
  - `decision == P1` 且持仓命中且 `impact>=1` → 正常唤醒（受预算/冷却）；
  - `P2/WATCH` 不唤醒，只进提示词。
- `NEWS_FRESH_MIN` 拆分：
  - 盘中 `90` 分钟；
  - 隔夜/开盘 `720` 分钟；
  - 超过 → `stale=true`，只提示不动作（P0 仍告警，标 stale）。

### 4.4 次日开盘

`night_pool_agent` / 次日交易智能体读取：
- `premarket.json`：P0 名单（回避）、P2 名单（不追）、WATCH 名单（观察）、风险 overlay；
- `latest.json` 的 `decisions`；
- 不允许把 P0 当成“利空出尽”买点；不允许把 P2 当成买入信号。

## 6. 分阶段上线

| Phase | 内容 | 交易影响 |
|---|---|---|
| P0（1 天） | 决策 schema + 从现有 `latest.json`/事件生成 decisions；只落盘/日志 | 无（影子） |
| P1（2–3 天） | 快速通道 2 分钟；P0/P1 写 Redis；决策轮渲染；唤醒 P0 | 只告警，不自动下单 |
| P2（1 周） | 主编/持仓/盘中/晚间全部接 decisions；`live_model_analysis` 注入 | 影子对照，人工确认 |
| P3（2 周） | 晚间 T+1/T+5 审计；source_quality 滚动；纸面交易 | 纸面 |
| P4 | P0 进实盘风险告警；仍不做新闻买入 | 只减仓/回避 |

**上线前必须过**：
- 决策 schema 单测；
- P0/P1/P2 映射单测；
- `build_news_block` 渲染单测；
- `NewsHit` P0 唤醒单测；
- 缺文件/坏 JSON/stale 降级测试；
- 不出现“新闻买入”字样的提示词守卫；
- 影子运行 5 个交易日，P0 精确率/召回率可解释。

## 7. 观测指标

| 指标 | 目标 |
|---|---|
| P0 告警时延（first_seen → decision） | 中位 <5 分钟，p90 <15 分钟 |
| P0 精确率（T+1/T+5 DID<0） | ≥60%，月度同号 |
| P0 召回率（人工标注硬利空+pre5>5%） | ≥80% |
| stale 率 | <10% |
| 决策覆盖率（A 股相关页有 decision） | ≥95% |
| 交易 agent 采纳率 | 记录，不强制 |
| 新闻买入次数 | **0** |
| 来源质量漂移 | 月度 rank corr ≥0.3，否则重评 |

## 8. 边界与 Do-Not-Redo

- 新闻层不下单；P0 只是风险标记。
- P0 不因唤醒预算/冷却被吞；但同一 `decision_id` 只告警一次。
- P2/WATCH 不是买入信号；交易 agent 不得把“不追”读成“可以做多”。
- 主题生命周期、跨市场映射只做展示/regime，不做规则。
- 评级不是买点；高位/低位评级都负。
- 快讯/热榜只做事件发现，不做 alpha。
- 板块成员非 PIT；主题/跨市场结论只当方向。
- 新闻入库中位 4.7 分钟、p90 85 分钟；盘中不能用“发布时间”假设抢跑。
- 任何新规则必须过 P1/P2 同号 + |t|≥2 + 扣费；否则只观察或 Do-Not-Redo。
