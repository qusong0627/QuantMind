> 生成日期：2026-09-09（最后更新 2026-09-10：修复自定义类钩子 / 行情缓存 / 融合量纲，回测记录已重跑）

> 生成器：`scripts/gen_ashare_strategy_templates.py`（唯一真源，改参数改这里再重跑）
> 校验器：`scripts/validate_ashare_templates.py`（容器内跑，结构 + 契约校验）

## 一、这批模板解决什么问题

素材来自 `~/桌面/TradingView策略-重爬1001/策略分析/`：1001 份 Pine 策略 → 去重后 531 条
（A 级 126 / B 级 301 / C 级 104）。它们是**单标的、时序、多为日内**的信号逻辑，
不能直接搬到 A 股日频横截面量化上，但其中的因子思想（动量、反转、波动率目标、突破、风控）
可以直接映射到 AI-IDE 的策略模板体系。

因此这批模板的目标是：

1. **把 TradingView 的因子思想落成 AI-IDE 可跑的策略配置**，不是照搬 Pine 代码；
2. **以「模型信号 + A 股硬约束」为主结构**——模型负责选股（`signal: <PRED>`），
   模板负责把选出来的票约束成 A 股能买、能持有、能卖出的组合；
3. **组合成体系**：10 个文件夹 = 10 类风格，同一风格内 5 个模板从保守到激进，
   便于组合成多策略、也便于横向对比；
4. **能配模型跑出好回测**：所有模板都保留 `topk / n_drop / rebalance_days` 三个核心旋钮，
   与平台默认模型（`models/production`、`qm_user_models` 中 ready 的模型）直接对接。

## 二、AI-IDE 策略模板的真实契约（读源码得到，非文档）

| 约定 | 事实 | 源码 |
|---|---|---|
| 文件对 | `strategy_templates/<id>.json` + `<id>.py`，**同一目录、非递归** | `services/strategy_templates.py:216` |
| 文件夹 | JSON 的 `dir` 字段 → 虚拟目录树，按 `/` 分级；不落库、不建真实目录 | `routers/ai_ide/workspace.py:68-96` |
| 市场 | `markets: ["a_share"]`；**不写 markets 的历史模板也只在 A 股视图出现** | `services/strategy_templates.py:87-104` |
| 代码 | `.py` 里必须有 `STRATEGY_CONFIG = {"class": ..., "module_path": ..., "kwargs": {...}}` | 同上 `:156-203` |
| 信号 | `kwargs.signal = "<PRED>"`，运行时由 Runtime 用 `model_id` 的 `pred.parquet/pred.pkl` 替换 | `backtest_service_runtime.py:1737+` |
| 参数面板 | JSON `params[]` 每项 `{name, description, default, min, max}`，`default` 必须等于 `.py` kwargs 值 | `schemas` + `strategy_templates.py:44-49` |
| UI 覆盖 | 请求里的 `strategy_params` 会**覆盖 kwargs 中已存在的** ui_param：`topk/n_drop/min_score/max_weight/stop_loss/take_profit/rebalance_days/...` | `strategy_builder.py:405-425` |
| 基本面过滤 | `f_<列名>_<min|max|in|not>` 只在带 `FundamentalFilterMixin` 的类生效（本批用 `RedisRecordingStrategy` / `RedisRiskGuardTopkStrategy`）；**其它类静默丢弃**。注意：2026-09-09 之前这条链路对 Topk-Dropout 系策略实际是断的，见 §6.7 | `recording_strategy.py` |
| 自定义类 | 模板 `.py` 里直接定义类 + `STRATEGY_CONFIG`（不写 `module_path`），Builder 会从动态模块自动回填 | `strategy_builder.py:433-441` |
| 自定义类钩子 | Topk-Dropout 链路只认 `_adjust_signal(score, ref_date)` / `_dynamic_risk_degree(base, ref_date)` 两个钩子（基类 `generate_trade_decision` 会调用，ref_date=T-1）；覆写 `generate_target_weight_position` / `get_risk_degree` **无效**（见 §6.17/§6.18）。权重类策略走 `WeightStrategyBase` 链路，那两个方法才会被调用 | `recording_strategy.py` |
| 行情取数 | 自定义类取行情一律用基类 `_close_matrix()` / `_price_frame()`（首次取满回测区间并缓存）；直接调 `D.features` 会在每个调仓步重复拉全市场，把一年回测拖到几十分钟（见 §6.20） | `recording_strategy.py` `PriceFrameMixin` |
| 内置类免写 module_path | `_BUILTIN_CLASS_MODULE_MAP` 覆盖 RedisTopk/Recording/Weight/LongShort/StopLoss/CrashBuyDip/SimpleWeight | `strategy_builder.py` |

**关键推论（决定参数怎么定）**

- 模板 kwargs 里**不要写 `max_weight` / `account_stop_loss`**：它们是 UI 参数，
  请求会覆盖，写了也不生效（as37 因此把参数改名为 `weight_cap`）。
- `risk_degree`、`f_*`、自定义参数不在 ui_params 里，模板自己说了算。
- 要 f_* 过滤就必须继承 `RedisRecordingStrategy`；平台内置的 `RedisMomentumStrategy`
  **没有** mixin，f_* 会被静默丢掉——这是本批做 7 个自定义类的根本原因。

## 三、A 股适配规则（每条都对应一个参数或约束）

| A 股现实 | 模板中的落地 |
|---|---|
| T+1 | 全部 `rebalance_days >= 1`，最短 3 日；无日内模板 |
| 涨跌停不可成交 | `only_tradable: true`（剔除涨跌停/停牌）；as43 额外剔除近 10 日涨停 |
| ST 股 | **平台数据里没有 `is_st` 列**，无法直接过滤；用「净利润为正 + 市值下限 + 成交额下限」间接规避 |
| 100 股整手 | 由回测/交易引擎处理，模板不重复表达 |
| 印花税 + 双边佣金 | 用低换手模板（as02/as20/as35，`rebalance_days` 10–15、`n_drop` 小）对冲成本 |
| 做空受限 | **全部只做多**；原 TradingView 素材里约 79% 含做空腿，一律砍掉 |
| 复权口径 | 由 QuantDB/Qlib 数据层统一后复权，模板不接触原始价 |
| 成交额单位是**万元** | `f_amount_ma_5_min` 用 5000 表示 5000 万；写 5000 万会被当 5000 万元过滤到空 |
| 波动率/涨跌幅是**百分数** | `f_vol_std_20_max: 1.8` 表示 1.8%；不是 0.018 |
| 市值/净利润/营收是**元** | `f_total_mv_min: 3e9` 表示 30 亿 |
| 涨停板动量在 A 股会失效 | as43 显式规避涨停股；as19 用「站上 20 日线 3% + 量能放大」替代纯新高突破 |

## 五、参数与风控约定

- **三个核心旋钮**：`topk`（持仓数）、`n_drop`（单期换手数）、`rebalance_days`（调仓周期）。
  与平台 UI 滑块一一对应，用户改了就以 UI 为准。
- **仓位类参数**统一用 `risk_degree`（0–1），不用 `max_weight`（会被 UI 覆盖）。
- **止损止盈**只在 as41/as42 出现（内置类的固有行为），其余模板靠「低换手 + 基本面过滤」控制风险，
  避免止损参数与 A 股 T+1 冲突。
- **流动性底线**：全批最小 `f_amount_ma_5_min = 2000`（2000 万），微盘模板也不例外，
  保证回测成交假设不至于失真。
- **市值区间**：从 10 亿（as47 微盘）到 3000 亿（as04 大盘）全覆盖，避免全部押注单一风格。

## 六、平台坑位（写模板前必须知道，已在本批规避）

1. **`return_Nd` 是未来收益（标签）**，不是历史收益。当过滤器用会直接标签泄漏
   （`backend/scripts/generate_feature_snapshots.py:47-51` 有注释）。本批 0 处使用。
2. **`is_st`、`listed_days`、`roe`、`industry` 不在 `features_daily` 里**，
   `f_is_st_not` 之类会**静默跳过**（只打 debug 日志）。本批不使用这些列。
3. **单位陷阱**：`amount_ma_5` 是万元、`vol_std_*`/`ma_gap_*`/`rsi_*`/`pct_change` 是百分数、
   市值/利润/营收是元。线上 `risk_guard_topk.json` 的 `f_vol_std_20_max: 0.06`
   实际是「波动率<0.06%」——等于过滤掉所有股票；`f_ma_gap_20_min: -0.12` 同理接近无效。
   本批按真实单位写。
4. **`RedisCrashBuyDipStrategy` 不接受 `only_tradable`**：它的 `__init__` 只 pop
   自有参数 + `_OUR_KWARGS`，其余透传给 `BaseStrategy` 会 `TypeError`。as41 已去掉该键。
5. **自定义类不要写 `module_path`**：写了反而可能指向不存在的模块；Builder 会自动回填动态模块名。
6. **JSON `params[].default` 必须与 `.py` kwargs 一致**，否则 UI 显示的默认值和实际跑的不一样。
7. **`f_*` 在修复前对 Topk-Dropout 系策略完全无效（本次已修）**：qlib 的
   `TopkDropoutStrategy.generate_trade_decision` 自己直接读 `self.signal.get_signal()`
   做选股，**从不调用** `generate_target_weight_position`，而 `FundamentalFilterMixin`
   只在后者里过滤 → `RedisRecordingStrategy` / `RedisRiskGuardTopkStrategy` 上的
   `f_*` 全部被静默忽略（实测：同区间下「无过滤 / 市值>1万亿 / PE 0-80+PB<10」
   三组回测结果逐字节相同）。修复方式：在 `generate_trade_decision` 里用
   `_fundamental_filtered_signal()` 临时把 `self.signal` 包成带过滤的代理。
   同时修掉两个连带缺陷：① `apply_fundamental_filter` 只支持
   `(datetime, instrument)` 多级索引，而 `SimpleSignal` 返回的是单级 instrument 索引
   （旧代码会抛 `IndexingError: Too many indexers`）；② 过滤结果为空时返回
   `pd.Series(dtype=float)` 丢掉了索引结构。
   回归测试：`backend/tests/test_backtest_guardrails.py::test_topk_dropout_filters_signal_inside_trade_decision`。
8. **`features_daily` 路径在容器里解析不到（本次已修）**：`FundamentalAligner` 只找
   `/data/6_ml_datasets/features_daily` 和 `<项目根>/data/quantdb/...`，而容器里实际在
   `/data/quantdb/6_ml_datasets/features_daily`（`QM_QUANTDB_DATA_DIR=/data/quantdb`，
   项目根是 `/app`）→ 旧版每次都回退到 2.7GB 的 `fundamental_aligned.parquet`，
   单次快照 **182 秒 / 峰值 20.6GB 内存**。已把 `QM_QUANTDB_DATA_DIR` 与
   `/data/quantdb/6_ml_datasets/features_daily` 加入候选路径；修复后单日快照
   **0.04 秒 / 5234 行**。
   后续：`fundamental_aligned.parquet` 兜底已彻底移除，对齐器统一走
   `quantdb_hub.fetch_latest_rows` 读 features_daily，单一数据源。顺带说明：`features_daily` 50 列里已经包含
   `pe_ttm/pb/ps_ttm/net_profit_ttm/revenue_ttm/equity/annual_net_profit/dividend_rate/total_mv/float_mv`，
   不必依赖回退文件。
9. **UI 参数受 `QlibStrategyParams` 约束**：`momentum_period` 上限是 60
   （`schemas/backtest.py:76`），模板里写 120 会在**请求构造阶段**就 422，
   回测根本起不来（as20 已从 120 改为 60）。校验器现在会先用 JSON 参数构造一次
   `QlibStrategyParams`，把这类问题挡在生成阶段。
10. **已上线的 `risk_guard_topk` 模板有单位 bug**：`f_vol_std_20_max: 0.06`
    实际含义是「波动率 < 0.06%」（等于过滤掉全市场），`f_ma_gap_20_min: -0.12`
    同理。本次一并改成 `6.0` / `-12.0`——修复 §6.7 之后这些约束会真正生效，
    不改会把该模板打成「永不成交」。
11. **`f_*` 过滤曾经自带 1 日前视偏差（本次已修）**：回测是「T-1 收盘信号 → T 日开盘价成交」
    （`deal_price=open` + `signal_lag_days=1`），但 `FundamentalAligner` 读的是
    `features_daily/dt=T` 分区，而该分区是 **T 日收盘后**才生成的
    （实测 `pct_change(2024-06-03)=-0.5035%` 就是当天自己的涨跌幅，`close` 就是当天收盘价）。
    等于用当天收盘信息在当天开盘下单。该偏差只影响 `f_*`（信号侧有滞后），
    对慢变的基本面列（市值/PE）影响很小，但对价格量能类列（`pct_change`/`ma_gap`/量比）
    是致命的：as32 用 `f_pct_change_min=2.0` 一度跑出**年化 418%、夏普 13.7、回撤仅 6.9%**
    的假曲线。修复方式：过滤改用**上一交易日**快照
    （`get_step_time(trade_step, shift=1)`，qlib 的 `shift>0` = 更早的 bar），
    解析异常时直接跳过过滤（宁可少一层约束，不引入未来信息）。
    回归测试：`test_topk_dropout_filters_signal_inside_trade_decision`。
12. **`RedisCrashBuyDipStrategy` 全年 0 笔交易（本次已修，两个 bug 叠加）**：

## 八、怎么用

```bash
# 1. 改模板：只改生成器，然后重跑（生成器会从 ashare_backtest_results.json 读回测记录写进 .py 开头）
python3 scripts/gen_ashare_strategy_templates.py

# 2. 结构校验（容器内）
docker exec quantmind python /app/scripts/validate_ashare_templates.py

# 3. 单模板真实回测（模板 .py 开头「怎么用」里就是这条命令，可直接复制）
docker exec quantmind python /app/scripts/verify_ashare_backtest.py as01_core_multifactor \
  --start 2024-01-02 --end 2024-12-31 --model-id mdl_cn_train_20260906023306_57ce74a7_d5a3faa7

# 4. 全量 51 个（含 baseline）重跑，结果落 scripts/ashare_backtest_results.json
docker exec quantmind python /app/scripts/run_ashare_backtest_all.py \
  --start 2024-01-02 --end 2024-12-31 --model-id mdl_cn_train_20260906023306_57ce74a7_d5a3faa7 --force
```

回测可复现性：§6.14 的哈希种子问题修复后，同一条命令在不同进程、不同时间跑出来的
年化/夏普/回撤/笔数完全一致（已用 `PYTHONHASHSEED=1` 与 `=2` 两次独立进程验证）。

AI-IDE 里：策略模板面板 → 选择「A股策略」文件夹下的模板 → 模型选好后回测。
