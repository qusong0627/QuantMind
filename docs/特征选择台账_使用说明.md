# 特征选择台账与自动经验/坑（protocol v1）

> 目标：每一次「选特征 → 训练 → 样本外」都留下可对账记录，自动提炼经验与坑；
> 但**不自动改门槛/配额**——参数变更必须升 `protocol_version` 后重跑，避免在
> 评估同一段数据上越调越过拟合。

## 一、文件在哪

默认根目录（容器内）：

```
/data/stock_classifier/feature_selection/registry/
  index.json            # 每次 run 的摘要
  features.json         # 每个特征跨 run 的历史（成长视图）
  lessons.json          # 合并后的经验/坑清单
  lessons.jsonl         # 追加式原始事件（审计用）
  lessons.md            # 人读版
  runs/<run_id>.json    # 单次 run 全量记录
  runs/<run_id>_oos.csv # 特征级 OOS 明细
```

宿主机对应：

```
/media/zbox/data/quantmind/stock_classifier/feature_selection/registry/
```

## 二、一次完整收口

### 1. 选特征（已有）

```bash
docker exec quantmind python backend/scripts/stock_classifier/select_daily_features.py \
  --coarse 240 \
  --out /data/stock_classifier/feature_selection/daily_feature_selection_2016_2024.json
```

### 2. 提交训练（自动登记台账）

```bash
# 在宿主机（API 8000 可达）
PYTHONUNBUFFERED=1 INTERNAL_CALL_SECRET=... \
python backend/scripts/stock_classifier/submit_daily_model_jobs.py \
  --selection /data/stock_classifier/feature_selection/daily_feature_selection_2016_2024.json \
  --top 100 --submit \
  --registry /data/stock_classifier/feature_selection/registry
```

给了 `--registry` 时：提交前 upsert 台账；每个 job 创建/完成后 attach
`model_jobs`。没给则完全保持旧行为。

### 3. 算 OOS（容器内，约 5–10 分钟）

```bash
docker exec quantmind python backend/scripts/stock_classifier/oos_ic.py \
  --selection /data/stock_classifier/feature_selection/daily_feature_selection_2016_2024.json \
  --top 100 --start 2025-01-01 --end 2026-11-05 --step 5 \
  --out /data/stock_classifier/feature_selection/oos_daily_2025_2026.json
```

口径与选择器一致：`close[t+h]/open[t+1]-1`，同一套 ST/涨停/停牌/成交额/
上市满 60 日/市值可得的可交易过滤。OOS 只用于审计，不参与选特征。

### 4. 收口：台账 + 经验/坑 + 审计报告（幂等）

```bash
docker exec quantmind python backend/scripts/stock_classifier/daily_growth.py \
  --selection /data/stock_classifier/feature_selection/daily_feature_selection_2016_2024.json \
  --top 100 \
  --jobs /data/stock_classifier/feature_selection/model_jobs.json \
  --oos /data/stock_classifier/feature_selection/oos_daily_2025_2026.json \
  --registry /data/stock_classifier/feature_selection/registry \
  --out-md /app/docs/特征选择台账_20261110.md
```

`daily_growth.py` 可重复跑：同一 `generated_at+top` 复用同一条 run，不会产生
`_2`；OOS 已挂过则跳过（要重算加 `--force-oos`）。

## 三、自动生成的经验/坑规则（v1）

只从 **valid（2025）** 窗口生成；test（2026）只做最终核验，`do_not_apply_to`
恒含 `"test"`。

| 规则 | 类型 | 触发 |
|---|---|---|
| 特征方向翻转 | pitfall | 选择 ICIR 与 valid OOS ICIR 异号且 \|OOS\|≥0.15 |
| 特征方向+强度保留 | lesson | 同号且 \|OOS\| ≥ 0.5×\|选择\| |
| 特征强度衰减 | lesson | 同号但 \|OOS\| < 0.5×\|选择\| |
| 类别/库同号率低 | pitfall | n≥5 且同号率 < 50% |
| 类别/库同号率高 | lesson | n≥5 且同号率 > 65% |
| 选择指标有正向预测力 | lesson | 与 OOS ICIR 的 Spearman ≥ 0.3 |
| 选择指标反向 | pitfall | Spearman ≤ −0.2 |
| 选择指标对强度无预测力 | lesson | 与 \|OOS ICIR\| 的 Spearman ≤ 0.1 |
| 数据问题 | pitfall | 注册跳过/字段未刷新等，登记时通过 `--data-issues` 传入 |

单次 run 只标 `open`；同一 `(kind, scope, key)` 跨 ≥ 2 个独立 run 复现才标
`confirmed`。`confirmed` 的 pitfall 才值得升协议版本处理。

## 四、防过拟合三条硬约束

1. **经验只从 valid 生成**：test 的数字只用于最终验收，不能拿来挑经验或调门槛。
2. **不自动改参数**：台账只记录与诊断；改门槛/配额/窗口必须新建
   `protocol_v2.json` 并重跑，旧 run 保留可追溯。
3. **单次不确认**：一次 run 的结论只标 `open`；跨 run 复现才 `confirmed`，
   避免把一次样本外噪声当成规律。

## 五、以后怎么升级

- **P1**：加子区间稳定性门槛（2016–2019 / 2020–2022 / 2023–2024 的 ICIR 同号率），
  相关性聚类后按代表+稳定性选。
- **P2**：冠军/挑战者——保留当前生产名单与挑战者，只有 OOS + 扣费 + 回撤显著
  更好才升级。
- **P3**：用累积台账校准 gate 权重。必须 purged/embargoed walk-forward，且
  `min_runs_for_weight_update`（默认 3）满足后才允许人工评估，不自动生效。
