# 实盘智能体交易策略重构（三阶段设计与实施）· 2026-10-28

> 状态：阶段 1 已实施（本提交，2026-10-28 收盘后部署）；阶段 2/3 仅设计，不在本批改代码。
> 口径：2026-10-28 用户拍板——3 个智能体各 ¥20 万（合计 ¥60 万）、单笔上限 ¥20 万、
> 股票不限（池外可买）、按默认模型分数+新闻交易、盈利优先；止损/止盈、单日亏损熔断、
> ST/黑名单/停牌、T+1 保留。

## 0. 为什么重构

现有实现是「按需求补丁式堆叠」，同一个资金参数分散在五层，任何一层口径漂移都会
让「模型看到的额度」与「闸门执行的额度」不是同一个数：

| 层 | 当前落点 | 谁在读 |
|---|---|---|
| 账本额度 | `agent_ledger.DEFAULT_AGENT_QUOTA` + `QM_AGENT_QUOTA` | 决策轮提示词、执行段 quota、arena 展示、净值基线 |
| 档位预算 | Redis `qm:risk:tier` 的 `per_stock_pct/max_new_buys` | `BuyGate`、提示词档位块、风险规则 |
| 显式覆盖 | `runtime.env` 的 `QM_DECISION_PER_STOCK_PCT/MAX_NEW_BUYS` | `capital_policy` → 提示词/闸门 |
| 开关 | `runtime.env` 的 `QM_DECISION_ALLOW_OUT_OF_POOL/PROFIT_FIRST` | 提示词、闸门、分数榜 |
| 镜像 | Redis `mirror:config` | `real_mirror_service` 单笔/单日/标的/笔数上限 |

此外还有两个**不是资金参数、但同属「交易策略」口径**的问题：

1. **双账户合并**：`real_positions.load_real_positions` 把 `qmt_exec`（50 只、现金
   ¥2,162 万）与 `tdx_bridge`（2 只、现金 ¥88.99 万）并成一张持仓表；决策轮日志
   「桥账户 51 只持仓」就是这两本账的并集。真实下单走 `broker:selected:CN=tdx`，
   但「账户/持仓」这一层的边界没有在代码里显式化。
2. **展示面旧文案**：arena 静态说明仍写「每 agent ¥10 万 / 单票 ≤20%」，与动态
   额度 ¥20 万不一致。

**结论**：不是再改一个数值，而是把「交易策略」收敛成一个**单一配置对象 + 单一
加载入口**，再逐层把账户/券商与展示面收口。

## 1. 目标与 kill criteria

### 1.1 目标

- **G1**：额度、单票比例、单轮新开仓、池外开关、盈利优先、分数榜条数、镜像五项
  上限，全部来自**一个** `TradingPolicy` 对象；任何消费方不得再读第二份配置。
- **G2**：策略文件损坏/字段非法时**失败关闭**（决策轮明确报错、不下单），不得
  静默回退到「更松/更紧」的默认值。
- **G3**：行为与 2026-10-28 已验收口径逐项等价：3×¥20 万、单票 100%、单轮 9 只、
  池外可买、盈利优先、镜像 20 万/120 万/40/80。
- **G4**：阶段 1 不改账户/券商选择、不改前端；阶段 2/3 另案。
- **G5**：回归零新增失败；阶段 1 的相关测试套件全绿，策略解析有独立单测。

### 1.2 Kill criteria（出现任一条即回滚阶段 1）

- 决策轮提示词里的额度/单票/新开仓与 `BuyGate` 实际夹取值不一致；
- 策略文件缺字段/写错字段时仍继续下单；
- 同一 agent 在同一轮出现两个不同的 quota（提示词一个、执行段一个）；
- 镜像实际生效上限与策略文件不一致（且不是显式 Redis 运维覆盖）；
- 相关回归出现**新增**失败（以提交前基线的相对失败集为准）。

## 2. 阶段 1：`TradingPolicy` 单一配置源（本批交付）

### 2.1 新模块

`backend/shared/trading_policy.py`（shared 叶子，只读文件/环境，不连 Redis/DB）：

```python
@dataclass(frozen=True, slots=True)
class AgentPolicy:
    quota: float = 100_000.0
    per_stock_pct: float = 0.20
    max_new_buys: int = 3
    allow_out_of_pool: bool = False
    profit_first: bool = False
    score_leaders_limit: int = 0

@dataclass(frozen=True, slots=True)
class MirrorPolicy:
    max_order_value: float = 10_000.0
    max_daily_value: float = 50_000.0
    max_daily_symbols: int = 5
    max_daily_orders: int = 20
    max_slippage_pct: float = 0.02

@dataclass(frozen=True, slots=True)
class TradingPolicy:
    default: AgentPolicy = AgentPolicy()
    agents: Mapping[str, AgentPolicy] = field(default_factory=dict)
    mirror: MirrorPolicy = MirrorPolicy()
    source: str = "builtin"       # 文件路径或 builtin
    problems: tuple[str, ...] = ()

    def for_agent(self, agent: str) -> AgentPolicy: ...
```

要点：

- **per-agent 覆盖**：`agents[<normalized agent>]` 只需写差异字段，其余继承
  `default`；键按名册同一归一（`normalize_agent`）后查重。
- **文件位置**：`QM_TRADING_POLICY_FILE` 优先；缺省 `config/trading_policy.json`
  （容器内 `/app/config/...`，`./config` 是挂载卷，重启/重建不丢）。
- **缓存**：按 `(path, mtime_ns, size)` 做进程内缓存；文件改动下一轮生效，不需要
  重启。测试/运维可 `clear_cache()`。
- **失败姿态**：文件不存在 → `builtin` 默认（开源/测试可用）；文件存在但 JSON
  坏、顶层/agent 字段未知、数值非法 → 抛 `TradingPolicyError`，决策轮 abort
  并留痕（不静默用默认值下单）。
- **旧 env 退役**：`QM_AGENT_QUOTA`、`QM_DECISION_PER_STOCK_PCT`、
  `QM_DECISION_MAX_NEW_BUYS`、`QM_DECISION_ALLOW_OUT_OF_POOL`、
  `QM_DECISION_PROFIT_FIRST` **不再读取**；`runtime.env` 里的旧键删除（留备份）。
  镜像的 `MIRROR_MAX_*` 仅在**没有策略文件**时作为开源兜底，文件存在时以文件为准。

### 2.4 决策轮接线

`RoundDeps` 增加一个可选注入点：

```python
load_trading_policy: Callable[[], TradingPolicy] | None = None
```

- 生产 `default_round_deps` 注入 `backend.shared.trading_policy.load_trading_policy`。
- 测试替身不注入 → 用 `TradingPolicy()` 内置默认；显式注入可测覆盖。
- 读取失败（`TradingPolicyError`）→ 该轮 `abort`，状态键 `note` 写明文件路径与
  首个错误；**不写 done 键**，补跑槽可重来。

### 2.5 测试（TDD）

新增 `backend/tests/test_trading_policy.py`：

1. 缺文件 → `builtin` 默认（10 万/20%/3/关/关，镜像 1 万/5 万/5/20）。
2. 完整文件 → 解析逐字段；per-agent 差异继承 default。
3. agent 键归一（大小写/空格/点号）后命中同一份。
4. JSON 坏、顶层键未知、agent 键未知、quota≤0、pct 越界、buys<0、镜像上限≤0
   → `TradingPolicyError`（逐参数化）。
5. mtime 缓存：文件未变只读一次；文件改动后 `clear_cache()`/mtime 变化生效。
6. `AgentLedgerRead.quota_total` 用注入的 quota；缺省回退常量。
7. `tier_with_policy`：有覆盖时写回两个旋钮 + source 后缀；无覆盖时原样返回。
8. `build_score_leaders_block(limit=N)`：0 不渲染；N 截断。
9. `real_mirror_service.load_config`：文件优先、无文件 env 兜底、Redis 覆盖优先。
10. 决策轮替身：注入 policy=200k/1.0/9/池外开/盈利开 → 提示词与 `BuyGate` 同值。

回归：阶段 1 相关套件（decision_round / gates / context / execution / ledger /
blocks / risk tier / mirror）全绿；对比提交前基线无新增失败。

## 3. 阶段 2：账户 / 券商 / 账本边界（细案另出）

本阶段解决「`qmt_exec` + `tdx_bridge` 合并」与「真实下单走哪本账」的口径问题：

- 新增 `AccountBook` 概念：`{broker_key: {cash, positions, snapshot_at}}`，不再把
  多券商持仓摊平成一张表；决策轮只读**当前选定券商**的账，其他券商账只进
  「多账户视图」。
- `broker:selected:CN` 与 `real_positions.active_source` 同一出处；下单、风控、
  提示词三处读同一个 `AccountBook`。
- 分账账本 `qm_agent_ledger_*` 的 `account_id` 增加 broker 维度（或显式绑定），
  避免「agent 账本属于 TDX、下单落到 QMT」这类跨账。
- 一键卖出按持仓 `sources` 路由券商（现有能力保留）。
- Kill criteria：任何一条腿的 `account_id` 与 `broker:selected` 不一致 → 整轮 abort。

## 4. 阶段 3：展示面（细案另出）

- arena「智能体台账/实况」的额度、单票上限、新开仓上限、分数榜、账户面板全部读
  `TradingPolicy` + `AccountBook` 的 API，不再写死文案。
- 设置页支持编辑 `config/trading_policy.json`（保存前 schema 校验 + diff 预览 +
  「仅纸面」/「立即生效」二选一），保存走 trade 服务的单一写入口。
- 移除「每 agent ¥10 万 / 单票 ≤20%」等旧静态文案；指标说明按「是什么/当前值/
  怎么看」重写。
- Kill criteria：UI 显示额度与决策轮提示词额度不一致 → 阻断发布。

## 5. 不做什么（边界）

- 阶段 1 不改账户/券商选择、不改 `real_positions` 合并逻辑、不改前端；
- 阶段 1 不把 `mirror:config` 的运维覆盖删掉（它是显式 override，不是第二份默认）；
- 阶段 1 不引入 DB 表；策略文件先满足「单一出处 + 可编辑」，DB/UI 留给阶段 3；
- 不碰 `config/runtime.env` 里的密钥，只删本批五个旧资金键。
