## 一、三层账

| 层 | 来源 | 作用 | 现状 |
|---|---|---|---|
| **主账** | PG `orders` / `trades` | 委托全生命周期 + 成交（数量/价格/佣金/印花税/过户费）+ agent 归属 | 完整。9.1 起 337 单（9月242 / 10月66 / 11月29） |
| **资金锚** | `real_account_snapshots`（source=qmt_exec / tdx_bridge） | 每日现金/市值/总资产，用来勾稽主账 | 有 |
| **外部凭证** | 券商柜台当日（QMT/TDX 都可查）；历史只能人工导对账单 | 逐笔核对主账 | 当日可查；历史缺口 |

**主账只认成交，不认委托**：委托可能撤单/废单，只有 `trades` 是真金白银。委托台账用于
审计「为什么没成交」，成交台账用于记账。

## 二、日结（每个交易日）

15:20 自动生成当日账单并留档：

1. **当日委托**：笔数 / 成交 / 部分成交 / 撤单 / 拒单（按 agent 分组）；
2. **当日成交**：成交额、佣金、印花税、过户费、净现金流（买为负、卖为正）；
3. **期末持仓**：数量、成本、当日市值（用收盘价）；
4. **期末资金**：取 `real_account_snapshots` 最新一条（现金/市值/总资产）；
5. **勾稽**：期初现金 + 当日净现金流 − 费用 = 期末现金（容差内），不平则告警；
6. **柜台对账**：拉当日柜台委托（QMT `query_orders` / TDX `query_stock_orders`），
   与 PG 当日委托逐笔比对（client_order_id / 委托号），差异分级告警（不自动改账）。

## 三、历史补账（9.1–11.6）

券商历史接口拿不到的，按这个顺序补：

1. **系统账本出账**：PG 直接按区间/月出账单（成交额、费用、按 agent 分账），
   这是**唯一完整**的一手数据；
2. **券商对账单导入**：从 QMT 客户端「对账单导出」/ 通达信「交割单导出」拿 CSV/Excel，
   导入 `broker_statements` 表（新增），按 `日期+代码+方向+数量+价格` 与 PG 成交匹配：
   - 完全匹配 → 标记已核；
   - 券商有、PG 无 → 漏记（可能是手工单），补录到 PG 并标注 `source=statement_import`；
   - PG 有、券商无 → 存疑（可能未成交/废单），列差异清单人工确认。

## 四、还缺的地基：`orders.broker`

现在每笔单**没有记录执行券商**。单账户时不影响记账，但一旦 QMT/通达信并行（多账户方案），
就无法按券商对账、也无法回答「这笔单走的哪条通道」。所以记账的地基是先补：

- `orders.broker varchar(16)`（NULL = 历史单，按当时全局选择推断）；
- 派发/下单入口写当前执行券商；止损、镜像、补单跟随来源单；
- 对账单、日结、交易记录全部按 broker 可分可合。

## 五、口径红线

- 金额一律用**成交额**（`filled_value`），不用委托额；
- 费用以成交回报落库值为准（QMT 回报含佣金；缺失时按费率估算并标注 `estimated=true`）；
- 时区统一 UTC（`executed_at TIMESTAMPTZ`），日结按**北京时间交易日**切分；
- 券商凭证迟到/缺失不阻塞当日日结：日结先出，凭证到了再补核（`reconciled_at` 字段）。
