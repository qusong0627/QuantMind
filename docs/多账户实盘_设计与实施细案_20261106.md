# 多账户实盘（QMT + 通达信并行）设计与实施细案

> 日期：2026-11-06　状态：设计待评审（未动工）
> 目标：同一市场同时挂两个实盘账户（大 QMT / 通达信），agent 可指定账户下单，
> 风控/止损/对账/记录全部按账户分区；默认单账户行为不变。

## 一、现状

- **单活跃券商**：`broker:selected:{market}`（Redis trade db2）决定唯一通道；
  `TradingEngine._get_broker` 按市场读它 → 手动下单、止损执行器、决策轮派发、
  镜像/补单共用这一把钥匙。顶栏「实盘：{券商} ▾」与「设置 → 券商接入」写同一键。
- **账户快照已有 `source` 维度**（`real_account_snapshots.source`：qmt_exec / tdx_bridge），
  但组合、风控、止损都按单账户语义。
- **记录已分层**：系统账本（PG，全历史+agent 归属）/ 券商当日（broker-records）/
  券商历史（QMT 支持，TDX 无）。
- **QMT 下单链路已接线但未落地**（`runMode=0` 模拟 + passorder 无委托），
  是多账户方案的前置阻塞项。

## 二、目标 / 非目标

**目标**
1. 同一市场可同时启用 ≥2 个实盘账户（QMT、TDX）。
2. agent/策略可指定账户；支持「按账户资金比例拆分」。
3. 风控、止损、对账、交易记录按账户分区，**绝不跨账户卖**。
4. 默认仍是单账户：开关关闭时行为与今天 100% 一致。

**非目标**：跨券商套利、自动搬券、改 QMT/TDX 各自协议。

## 三、数据模型

| 变更 | 说明 |
|---|---|
| `orders.broker` varchar(16) | 订单归属券商（qmt_exec/tdx）；历史行为 NULL = 按当时全局选择路由 |
| `trading_accounts`（新表） | id、broker、market、account_id、display_name、enabled、portfolio_id |
| `portfolios.broker`（或账户↔组合绑定表） | 风控按账户算可用资金/持仓 |
| `sltp` 规则/状态 | 规则加 `broker`；状态键 `symbol|owner|broker` |
| `engine_signal_scores` | 增加 `broker` 观测列（决策落库时可追溯） |

迁移脚本遵循「加列不改语义」：先加列、双写、再切读，最后清理。

## 四、执行链路

1. **派发入口** `dispatch_internal_strategy_order(order_data)` 接受 `broker`；
   缺省回退 `broker:selected:{market}`（现状）。
2. **引擎路由** `TradingEngine._get_broker(mode, symbol, broker=None)`：显式 broker 优先。
3. **幂等键**：沿用 `(tenant_id,user_id,client_order_id)`；SLTP 的
   `client_order_id` 追加 broker 段（`sltp-{broker}-{symbol}-{day}-g{n}`），
   避免同号跨账户互相顶掉。
4. **止损执行器**：按 `(symbol, owner, broker)` 分组评估；可卖量取对应账户柜台；
   账户快照缺失 → 该账户本轮跳过（fail-closed），不拿另一账户的量补。
5. **镜像/补单**：跟随来源订单的 `broker`，不读全局选择。

## 五、风控

- **账户层**：可用资金、可卖量、T+1、单笔金额/分钟频次按账户独立计算。
- **组合层**：仓位上限、行业暴露仍按组合；跨账户合并计算。
- **fail-closed**：任一账户快照超过新鲜度阈值（复用 `freshness.py`）→ 该账户禁下单并告警。
- 账户之间**不共享额度**（各自独立），避免一个账户的行为影响另一个。

## 六、决策层

- 规则三选一（按 agent 配置）：
  1. 固定账户（agent → broker）；
  2. 按资金比例拆单（同一信号按账户可用资金分配，最小手数取整）；
  3. 主账户 + 备账户（主账户不可用时切备）。
- 决策审计表记录 broker 与拆分明细；对账单按账户可分开、合计一致。

## 七、前端

1. 顶栏「实盘：{券商} ▾」→ 多账户列表（每个账户一条，显示在线/新鲜度，勾选启用）。
2. 下单表单：账户选择器（默认上次使用；不可用账户置灰并给原因）。
3. 交易记录：账户筛选（系统账本按 `orders.broker`；柜台视图 `source` 已支持）。
4. 账户概览：并列账户卡（`source` 维度已有基础）。
5. Agent 对账单：按账户分组列示。

## 八、对账

- **每日 15:20** 自动对账任务：
  - QMT：拉当日 `query_orders/query_trades` 与 PG 逐笔比对（client_order_id/remark）；
  - TDX：只能拉当日**委托**（无成交接口），成交侧用 PG + 柜台资金变动交叉验证。
- 差异分级：数量/价格不一致 → 告警（QQ），不自动改账；缺失单 → 人工核对。
- 历史对账：QMT 走 `get_history_trade_detail_data`（已接通），TDX 由客户端导出对账单。

## 九、实施阶段与估时

| 阶段 | 内容 | 估时 |
|---|---|---|
| P0 | `orders.broker` 加列+迁移；dispatcher/引擎参数；幂等键检查；单测 | 1.5 天 |
| P1 | `trading_accounts` 与组合绑定；账户快照按账户；前端账户选择器 | 1 天 |
| P2 | SLTP 按账户分组；风控按账户；镜像/补单跟随 | 1.5 天 |
| P3 | 记录/对账单按账户；自动对账任务 + 告警 | 1 天 |
| P4 | 端到端演练：模拟账户先跑通，再真账户 100 股探针 | 0.5 天 |

## 十、开关与回滚

- 后端 `MULTI_ACCOUNT_ENABLED`（默认 false）；前端 `VITE_MULTI_ACCOUNT`（默认 false）。
- 关闭开关 = 单账户老路径；新增列保留、不删数据，回滚零成本。

## 十一、验收标准

1. 两个账户同时各下 100 股：各自柜台委托一致、`orders.broker` 正确、互不串户。
2. 止损只卖归属账户的可卖量；构造「同标的两账户共持」用例，验证零跨账户卖出。
3. Agent 对账单按账户分开，合计与系统账本一致。
4. 关闭开关后行为与 2026-11-06 完全一致（回归用例）。

## 十二、风险与未决

1. **QMT passorder 不落地**（当前阻塞）：多账户前必须先让 QMT 真能下单（或明确 QMT 只作沙盘）。
2. TDX 无历史成交/明细接口 → 自动对账只能做到「委托 + 资金变动」级。
3. 账户快照新鲜度与 fail-closed 阈值需按实测标定（避免盘中误禁单）。
4. 多账户下「同标的多 agent 共持」的归属计算复杂度上升，需要专门用例覆盖。
