# 训练管线严格化升级 · 前后端规划（2026-11-20）

> 基线：`docs/模型训练管线升级_规划_20261109.md`（Phase 0 已落地：标签变换、rank loss、三棵树参数）。
> 本规划只覆盖**尚未落地**的部分 + 2026-11-19/20 新查出的缺陷。
> 目标不是「IC 好看」，而是训练产出的每个模型都满足四条：**可审计、可成交、可复现、可比**。
> 对标口径：比机构常规更严（PIT + 可成交 + 多重检验 + 单轴实验 + 晋升闸）。

## 2. 工作包（前后端分列）

### WP1 · 输入可审计（P0，1.5 天）

**后端**
- `admin_training_utils._resolve_quantdb_factor_payload`（已完成 422 闸）补 metadata：
  - `requested_features_original`（请求原文，100）
  - `resolved_features`（目录解析后，88）
  - `dropped_features: [{name, reason, catalog_version}]`
  - `lineage: {git_commit, image_digest, catalog_versions, data_fingerprint, seed, config_hash}`
- 发布期校验：`publish_catalog_version` 增加 enabled 映射的 `source_column` 必须存在于字段注册表（`is_present=true`），否则 409 并列出。
- 结果归一化 `_build_default_metadata` 不再用「过滤后」数量冒充 `requested_feature_count`。

**前端**
- 训练结果页顶部：`请求 100 → 解析 88 → 入模 34` 三段漏斗；有 dropped 时红色告警条，列出特征名与原因。
- 新增「血缘」卡片：git commit、镜像 digest、目录版本、数据指纹、seed、config hash（一键复制）。

**验收**：构造一个含陈旧映射的假目录 → 提交被 422；伪造一份带 dropped 的 metadata → 前端红条可见。
**Kill**：任何降级路径仍能不带 dropped 记录完成训练。

### WP2 · 严格评估器（P0，4~5 天，最高优先级）

**后端**
- **实现位置：应用容器内的后置评估任务**（不改进训练镜像，避免镜像重建与两套口径）：
  - 训练回调完成后触发 `strict_eval_service`，读 `/data/training_jobs/<run>/pred.parquet` + `daily_forward` + `trade_mask` + `index_daily`，产出 `strict_report.json`，写回 job result / 新表 `qm_training_strict_reports`。
  - 训练容器内可选再调一次同一函数做即时反馈；首版只做应用侧。
- 评估器口径：
  - 信号 t 日收盘；买入 t+1 开盘（可选 VWAP）；卖出 t+1+N 收盘；N = 标签 horizon。
  - 可成交：ST（PIT）、停牌、涨停买不进、跌停卖不出顺延、次新、`trade_mask`。
  - 成本：0.15% / 0.25% / 0.40% 三档；容量：单票 ≤10% 当日成交额；参与率分布。
  - 指标：净 Top-N（20/50/100/200/500）年化、MDD、月度胜率、换手、超额（vs HS300/ZZ1000）。
  - 显著性：HAC t（Newey-West, lag=h）、block bootstrap 95% CI。
- 与现有 `gates` 合并成统一 `evaluation` 块；晋升闸读取该块。
- 统计函数复用 `backend/scripts/eval/stat_tools.py`（已有 PSR/DSR、PBO-CSCV、block bootstrap、成本敏感性、regime split），**不要另写一套**。
- 研究脚本 `feature100_tune2025.py` 的口径固化为金样，评估器首版必须复现同数字（±0.2pp）。
- **存量回填**：对 `mdl_cn_train_20261119100344`、`mdl_cn_train_79_t10_2010_20261119`、`mdl_cn_train_20261119114538` 三个模型补跑 strict_report，作为后续 A/B 的基线。

**前端**
- 结果页新增「严格评估」Tab：净 Top-N 表（三档成本 × 五档 N）、月度热力图、换手/容量、HAC t、PBO/DSR、通过/不通过徽标。
- 同 Tab 展示现有 `gates`（置换 p、残差 IC、随机批、h 曲线）与 `drift` 摘要——这两块数据已经在产物里，只是前端没接。
- 默认折叠，避免信息过载；不通过项置顶。

**验收**：同一份 `pred.parquet` 在评估器与研究脚本上净 Top20 差异 ≤0.2pp；月度数字逐月对齐。
**Kill**：评估器无法复现金样 → 不上晋升闸。

### WP3 · 可交易训练样本 + 样本权重（P1，3 天）

**关键设计**：截面 rank 标签仍在**全市场**算，避免改变目标分布；不可交易样本以 `sample_weight=0` 进入训练。这样既不让模型学买不进的票，又不改变排序基准。

**后端**
- `docker/training/data/loading.py` + `train.py`：
  - 新配置块 `sample_weight: {tradeable_mask: true, st: true, suspended: true, new_listing_days: 60, time_decay_half_life_days: 0|730}`。
  - 可交易判定复用现成 `trade_mask.parquet`（`/data/quantdb/5_technical_derived/trade_mask/`，研究回测已在用）+ `st_pit_cache`。
  - **镜像布局注意**：训练容器只有 `docker/training/`，拿不到 `backend/shared/tradability.py`；逻辑要在 trainer 内实现，或把共享模块 COPY 进训练镜像（不推荐，两处口径漂移）。
  - `sample_weight` 贯通三个 GBDT trainer 与 DL trainer；权重统计写入 metadata（有效样本占比）。
- 缺数据时 fail-closed：`trade_mask` 缺日期 → 报错而不是静默全 1。

**前端**
- 训练页「样本卫生」区：可交易过滤开关、次新天数、时间衰减半衰期；提交前展示「预计有效样本占比」。
- 结果页展示权重统计与过滤前后样本数。

**验收**：同模型 A/B（权重关 vs 开）IC 与净 Top20 均出；权重开关不改变标签分布（校验 rank 均值/标准差）。
**Kill**：权重开启后净 Top20 在 2026 段下降且 IC 掉 >20% → 回退为默认关。

### WP4 · 多种子 / 集成编排（P1，2 天）

**后端**
- 新任务模式：一个 run 内跑 K=3 个 seed（42/7/2024），pred 秩平均；注册为单个 ensemble 模型，metadata 记 `seeds[]` 与离散度。
- 或先做「3 个独立 run + merge 任务」，避免改动训练主流程；推荐后者（可回滚）。
- 离散度指标：各 seed 的 RankIC、净 Top20 的均值/标准差/极差。

**前端**
- 训练页 seed 数与 seed 列表；结果页「种子稳定性」卡片（IC 与净 Top20 的离散度）。
- 模型管理页对 ensemble 模型显示成员 seed。

**验收**：3 seed 的 IC 标准差 < 单 seed 均值的 15%；ensemble 样本外净 Top20 ≥ 单 seed 中位数。
**Kill**：ensemble 在 2026 段不如最好单 seed → 只保留离散度报告，不做集成。

### WP5 · 训练页实验化（P1，2 天）

**前端**
- 目标函数下拉：`regression / binary / rank_xendcg / lambdarank`（rank 两项带说明与互斥提示）。
- 高级参数：seed、bagging_seed、feature_fraction_seed、metric。
- 「实验标签」输入（如 `axis=loss/rank`），提交时写入 payload。
- 配置 diff 预览：与所选基线 run 的差异字段高亮。

**后端**
- 校验 rank loss 与 quantile/optuna 的互斥（trainer 已跳过，但需在提交期 422 说明）。
- 日志输出组数、每轮 ndcg/rank_ic。

**验收**：训练页可一步提交 rank_xendcg；结果页显示 objective/metric 与组数。
**Kill**：无。

### WP6 · A/B 对比与晋升闸（P1，2 天）

**后端**
- `GET /api/v1/models/training-runs/compare?ids=a,b,c`：返回同口径 strict_report、配置 diff、单轴判定。
- 晋升闸：模型 `deploy_to_production=true` 前必须满足：
  1. strict_report 在 0.25% 成本下净 Top20 > 0；
  2. 审计（WP7）通过；
  3. 配置 diff 相对基线仅一个轴（或显式标注多轴）；
  4. 影子盘 ≥2 周（后续）。

**前端**
- 对比页：2~5 个 run 并排，差异字段高亮；同口径指标差值着色。
- 模型详情页显示晋升状态与阻断原因。

**验收**：任意两个 run 可对比；多轴 diff 时红色提示「不构成严格 A/B」。
**Kill**：无。

**后端**
- 审计服务 `backend/services/engine/training/pit_audit.py`（**编排已有工具，不重写**）：
  - 财务 PIT：复用 `backend/scripts/audit_factor_pit.py` + `financial_pit_panel.py`（公告日/重述）。

## 4. 全局验收与 Kill Criteria

| 闸 | 标准 | 不过的后果 |
|---|---|---|
| 输入完整 | 请求特征 = 解析特征 = 入模特征，或显式记录 dropped | 阻断训练 |
| 可成交 | 训练/评估同一套 mask | 阻断晋升 |
| 净收益 | 测试段净 Top20 在 0.25% 成本下 >0 | 不可晋升 |
| 显著性 | HAC t ≥ 2，PBO < 0.5，DSR > 0 | 标记「描述性」 |
| 稳健性 | 3 seed 方向一致；月度胜率 ≥ 55% | 不可晋升 |
| 审计 | PIT/退市/成分/泄漏五项全过 | 不可晋升 |
| 可复现 | 同一 config hash 重跑 pred 秩相关 ≥0.999 | 修复后重跑 |

## 5. 测试计划（TDD）

- **后端单元**：发布期校验、metadata 归一化、strict_eval 纯函数（成本/涨跌停/容量/HAC）、sample_weight、seed 合并。
- **金样**：`backend/tests/fixtures/strictReportGolden.json`（由 `feature100_tune2025.py` 产出），评估器与前端展示都读它。
- **集成**：小样本 fixture 走完「提交 → 训练 → strict_report → compare → 晋升闸」。
- **前端**：vitest 覆盖漏斗/对比/diff 工具函数；Playwright 覆盖训练结果页与对比页关键流。
- **回归**：现有 90+ 训练相关测试全绿；新增闸默认开启，旧行为通过 `allow_missing_features` / `strict_eval.enabled=false` 显式回退。

---

## 6. 风险

1. **口径漂移**：严格评估器与研究脚本两套实现 → 必须金样锁定，首个版本只允许一套。
2. **样本权重改变标签分布**：rank 标签仍按全市场算，只改权重；A/B 不通过就默认关。
3. **前端信息过载**：严格报告默认折叠，只把「不通过」置顶。
4. **训练镜像重建窗口**：与「在训模型不被打扰」冲突 → 训练器改动排在没有长任务的时间窗。
5. **历史模型不可比**：新评估器上线后，旧模型没有 strict_report → 对比页标注「无严格报告，不可作为基线」。

---
