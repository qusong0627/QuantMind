# 资讯中心 2.0 — 设计与实施（2026-11-18）

> 目标：把 2026-11-18 新闻研究（`data/news_intel/20261118/REPORT.md`、
> `NEXT_RESEARCH_SECTION.md`、`PRIOR_CONCLUSIONS_DETAILED_20261118.md`、`STOCK_PROFILES.md`、
> `SECTOR_PROFILES.md`）落成**可读、可排序、可下钻**的资讯界面，而不是把十几个标签堆在每行。
>
> 一句话：**一条新闻只回答一个问题——它现在改变什么；其余都收进「依据」。**

---

## 0. 为什么是 2.0

现有资讯面（`NewsPanel` + 个股 `NewsTab`）的问题：

1. **标签太多、权重太低**：情绪、来源可信度、时段、3 个事件标签同时出现在一行，
   读者要先做一次「标签仲裁」才知道该不该看。
2. **口径互相打架**：`report_match.py` 把「财联社」当高质量源，11-18 研究实测
   财联社电报 adj DID **-262bp**；把「人民日报」当反向源，研究实测 **+171bp**。
   同一篇新闻在不同页面得到相反的先验。
3. **没有决策层**：研究里唯一通过决策回测的是
   `硬利空 + pre5>5% → T+1 回避`（+186.8bp/事件，t=2.81），其余是「不追/观察」；
   现有界面全都没有体现。
4. **没有个股/板块的「全部新闻」入口**：个股只有标题 LIKE 的 15 条；板块只有
   `industries` 过滤，没有板块新闻面。
5. **模型推理与新闻割裂**：每日推理榜单能看到分数，看不到「这只票今天有什么消息」。

2.0 的答案：**少标签、重权重、按研究结论排序、把证据折叠**。

## 1. 设计原则

| # | 原则 | 落地 |
|---|---|---|
| 1 | 一条新闻一个主标签 | 行内只显示 `决策等级 + 一句人话`；标签进「依据」抽屉 |
| 2 | 权重优先 | 默认按 `weight` 排序，时间只做 tiebreaker；可按时间切换 |
| 3 | 分层不混用 | L1（代码命中）与 L2（标题主体）在视觉上区分；L2 永远不冒充 L1 |
| 4 | 展示面禁买卖词 | 用「回避 / 不追 / 观察 / 信息」，不出现「买入 / 卖出 / 减仓」 |
| 5 | 研究结论可见 | 板块页/个股页固定展示「本页读法」卡（来自研究规则，不是 LLM 生成） |
| 6 | 缺失不猜 | pre5 缺失 → INFO；来源未知 → 中性先验；数据过期 → 显式 `stale` |
| 7 | 可回滚 | 新路由独立；`/rss-news` 一键切回旧 `NewsPanel` |

## 2. 信息架构

`/rss-news` 由「RSS 信息流」升级为「资讯中心」，五个视图：

```
资讯中心
├── 每日推理   ← 默认落地页（模型推理 × 新闻）
├── 板块雷达   ← 概念/行业新闻热度、利空发酵、板块新闻流
├── 个股档案   ← 一只票的全部新闻 + 新闻结构 + 规则化读法
├── 我的订阅   ← 订阅个股置顶、未读、合并动态
└── 全库信息流 ← 旧 NewsPanel 原样保留（高级筛选/源管理）
```

底部导航仍复用现有 `rss-news` 槽位，只把 label 从 `RSS信息流` 改为 `资讯中心`；
不新增导航项，避免动 `FloatingNavBar` 的分组与 `DashboardTab` 联合类型。

### 2.1 每日推理（Daily Inference）

三栏：

- **左栏（列表）**：日期 + 模型（默认模型预选）+ 榜单长度（50/100/200）。
  行 = 名次、名称/代码、分数位置条、Δ名次、新闻标记（今日条数 / 最高权重标签）。
- **中栏（选中票）**：
  - 「今日新闻决策」：按权重取前 6 条，行内只有主标签 + 标题；
  - 「近 30 日重要新闻」：按权重取前 10 条；
  - 空态：明确写「今日无主体新闻」，不拿中性稿凑数。
- **右栏（上下文）**：模型位置（`截面第 N / 靠前`）、7/30 日新闻条数、
  风险 overlay（投机热度分位）、`打开个股档案` / `订阅置顶`。

数据：`GET /api/v1/models/default` → `GET /api/v1/models/inference/latest?model_id=`
→ `GET /api/v1/models/inference/runs/{run_id}`；新闻侧只调一次
`GET /api/v1/news-intel/stocks/summary?codes=...`。

### 2.2 板块雷达（Sector Radar）

- 顶部三条读数：`概念利空发酵`、`新闻热度`、`风险密度`（全部来自研究口径）。
- 左：板块列表（新闻数、利空占比、风险数、投机占比、5 日变化）。
- 右：选中板块
  - 新闻流（权重排序，复用同一 `NewsTimeline`）；
  - 龙头股（板块新闻命中次数）；
  - **读法卡**：固定引用研究结论——
    「板块利好发布前 30 分钟已涨 18~21bp，发布后无延续 → 不追」；
    「概念板块利空 post5 -2.3bp / post30 -7.3bp → 坏消息发布后才发酵」。
- 数据：`GET /api/v1/news-intel/sectors`、`/sectors/{code}`。

### 2.3 个股档案（Stock Dossier）

- 头部：名称/代码、最新价与涨跌、模型位置（只说位置）、新闻热度。
- 左：筛选（30/90/全部、全部/重要/风险/投机、权重/时间排序）。
- 中：新闻时间轴 —— 日期槽 + 3px 权重条 + 标题 + 一个主标签 + 元信息。
- 右：
  - `新闻结构`：7/30/90 日条数、方向结构、决策等级分布；
  - `风险`：critical/high 按类型计数、投机条数；
  - `读法`：来自 `STOCK_PROFILES.md` 的规则化读法（例如
    「避雷：硬利空 + pre5 2~5%，历史同格 -129bp」）。
- 数据：`GET /api/v1/news-intel/stocks/{code}/news`、`/profile`。

### 2.4 我的订阅（Subscriptions）

- 订阅 = 用户级「某只股票的新闻置顶」。
- 顶部：置顶股票（按 `sort_order`），显示今日/近 7 日条数、最高权重标签、未读点。
- 下方：订阅合并动态（按权重，置顶股票优先）。
- 操作：`订阅` / `取消` / `置顶` / `取消置顶`。
- 数据：`/subscriptions` CRUD + `/feed`。

## 3. 权重模型（研究驱动，落在后端纯函数）

新增 `backend/shared/news_intel_rank.py`，输入一条 `(article, stock)` 的原始证据，
输出 `weight 0..100`、`importance`、`primary_label`、`reasons`。

### 3.1 决策等级（复用 `news_decision.decide`）

| 条件 | 等级 | 展示语 |
|---|---|---|
| 硬利空 & pre5>5% | P0 | `硬利空 · 高位` |
| 硬利空 & 2%<pre5≤5% | P1 | `硬利空 · 中位` |
| 硬利好/泛利好 & pre5>5% | P2 | `利好 · 高位（不追）` |
| 软利空 & -2%≤pre5≤5% | WATCH | `软利空 · 反弹区间` |
| L1 & 利好 | WATCH | `L1 利好 · 观察` |
| 其他 | INFO | `信息` |

**缺失 pre5 → INFO**，不猜。

### 3.2 权重

```
base = {P0:100, P1:82, P2:68, WATCH:45, INFO:12}
tier:        L1 +12 / L2 +8 / L3 0 / L4 -4
risk_level:  critical +10 / high +5
category:    硬利空 +6 / 硬利好 +4 / 泛利空 +4 / 软利空 +2 / 其他 0
layer:       0 +4 / 1 0 / 2 -6 / ≥3 -18      # 转载层越深越差
is_dup:      -12
aggregator:  -25
source_quality: round(sq * 8)                # -8..+8
is_speculative: -8
age:         ≤1d +6 / ≤3d +3 / ≤7d 0 / >7d -8
clamp 0..100
```

`importance`: ≥75 `high`、≥45 `medium`、其余 `low`。

> 权重只用于**排序与视觉强调**，不产生任何交易动作；决策等级本身来自研究回测。

### 3.3 噪声与守卫（复用现有实现，不另起一套）

- `news_tagging.article_is_noise`（采购/公告体）
- `news_tagging.subject_is_confirmed`（媒体名/通用词同形）
- `news_tagging.tag_is_negated`（否定句）
- `news_event_rules.validate_title`（关键词 + 公司名/代码 + 否定 + 研报评级）
- 聚合页/转载：`source_domain` 命中 Google News/热榜 → `aggregator`；
  同标题 6h 内只保留首发（`is_dup`）。

**退役**：新界面不再使用 `report_match.annotate_news_item` 的三套来源词表；
来源先验统一走 `news_event_rules.source_quality`（11-18 研究口径）。

### 3.4 精度守卫（实装时补的三条）

真实数据里最伤精度的不是「标签不够」，而是**事件落到了错的股票**：

1. **券商研报作者**：`[东吴证券]环保行业跟踪周报：…监管…` 会被上游打成
   `监管处罚`，挂到东吴证券头上。`is_research_report()`（作者前缀 + 研究词）
   → 中性/研报，不计个股事件。
2. **多票汇总稿**：`公告精选︱同宇新材：…` 的 enrichment 同时带
   `立案调查,中标` 和 12 只 ticker；不拦会给 12 只票同时打「硬利空」。
   `is_roundup()`（公告集锦/涨停复盘/收评）→ 中性/汇总。
3. **事件必须能在标题里落到这只票**：`category != 中性` 时要求
   `tier ∈ (L1,L2)` 且 `validate_title(title, code, name, category)` 为真；
   否则降为「提及」。这挡住了「板块复盘稿一荣俱荣、一损俱损」。
4. **硬风险优先**：同一篇稿同时带「业绩风险」「退市风险」时，按
   `硬利空 > 软利空 > 硬利好 > 治理利好` 取，不再按数组顺序取第一个。

## 4. 后端

### 4.1 新路由 `backend/services/api/routers/news_intel.py`

前缀 `/api/v1/news-intel`，整组 `Depends(get_current_user)`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/overview?days=1` | 首页读数：全市场新闻量、风险数、投机数、板块前三 |
| GET | `/stocks/{code}/news` | 个股全部新闻（分页、权重/时间排序、类型筛选） |
| GET | `/stocks/{code}/profile?days=90` | 新闻结构 + 风险 + 规则化读法 |
| GET | `/stocks/summary?codes=...&days=7` | 批量摘要（每日推理榜用） |
| GET | `/sectors?type=concept&days=5&limit=60` | 板块热度列表 |
| GET | `/sectors/{code}?days=5&limit=40` | 板块新闻流 + 龙头股 + 读法 |
| GET | `/subscriptions` | 我的订阅 |
| POST | `/subscriptions` | 订阅 `{code,name,pinned}` |
| PATCH | `/subscriptions/{code}` | 置顶/取消置顶/排序 |
| DELETE | `/subscriptions/{code}` | 取消订阅 |
| GET | `/feed?limit=50` | 订阅合并动态（置顶优先、权重排序） |

### 4.2 数据来源（不建新宽表、不跑回填）

- 文章：`news_article_enrichment`（title/tickers/event_tags/sentiment/entity_sentiments）
  `JOIN huntly_publish_index`（发布时间 + source_domain）。
- 个股过滤：`tickers @> ARRAY[code_suffix]`；L3/L4 不参与个股决策。
- pre5：`news_pre5.pre5_from_frame`（DuckDB 读 QuantDB 日线 + 一级行业），
  进程内按日缓存；缺失 → INFO。
- 板块成员：`2_base_sector/sector_concept/sector_members.parquet`，进程内按 mtime 缓存。
- 模型推理：复用 `/models/default`、`/models/inference/latest`、`/models/inference/runs/{run_id}`。
- 订阅：新表 `qm_news_subscription`（自愈 DDL；`db_init.sql` 同步加）。

### 4.3 性能与降级

- 个股新闻：单票 90 天通常 100~3,000 行；SQL 限 2,000 行后在 Python 计算权重。
- 板块热度：只取窗口内 `tickers/event_tags/sentiment_label/published_at/domain`
  五列，Python 聚合；进程内缓存 300s（键含 date/window）。
- 任何下游失败（pre5 缺失、板块成员缺失、Huntly 不可达）都返回
  `available: false` + `reason`，**不 500**。
- 所有时间戳输出带 `Z`；`as_of` 明确标注。

### 4.4 订阅表

```sql
CREATE TABLE IF NOT EXISTS qm_news_subscription (
  id BIGSERIAL PRIMARY KEY,
  tenant_id TEXT NOT NULL DEFAULT 'default',
  user_id TEXT NOT NULL,
  symbol TEXT NOT NULL,
  name TEXT,
  pinned BOOLEAN NOT NULL DEFAULT TRUE,
  sort_order INTEGER NOT NULL DEFAULT 0,
  last_read_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (tenant_id, user_id, symbol)
);
```

## 8. 边界与 Do-Not-Redo

- 新闻层不产生买入信号；界面不出现「买入/卖出/减仓」。
- L2 不升级为 L1；板块成员是当前快照非 PIT，界面固定披露。
- 不展示「前 20%/后 20%」这类分位话术；只说「靠前/居中/靠后」。
- 不把「新闻量」当利好：研究里 `n_articles/n_sources` 的 20 日 IC 是负的。
- 不追板块利好；板块利空（尤其概念）才是发布后继续发酵的一类。
- 不做「看到利好就买」的任何入口或文案。

**板块归属口径（实测修正）**

板块新闻**按标题命中板块名**归属，不按成分股 tickers。按成员映射会把
「江西宜春：脱胎漆器…」这种只要提到某只成分股的稿子算进「人工智能」，噪声远大于信号。
`DeepSeek概念 → DeepSeek`、`机器人概念 → 机器人`；MSCI 成份/近期新低/大盘股/百元股
等风格板块默认过滤（`include_style=true` 可看）。板块级方向优先用 enrichment 事件标签，
没有标签才用文章情绪；只有情绪、没有硬事件时标签是「板块偏空 · 观察」，
