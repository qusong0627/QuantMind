# 行情扫描与机会发现设计方案（全市场扫描 · 机会池 · 质量回填）

> 版本：v1（2026-09-15）　配套：`docs/统一交易栈_设计方案.md`（v3）、`docs/评估与打分体系_设计方案.md`
> 目标：建立"**扫描行情找机会**"的系统化能力——全市场多路扫描 → 机会池 → 交给策略决策。机会发现与交易决策严格分离：**扫描器只负责"发现+评分+呈现"，买不买由策略决定**。

---

## 一、三层漏斗（机会 ≠ 交易）

```
全市场 5000+                    机会池（候选 N 只）              策略决策             持仓
┌──────────┐   扫描+评分   ┌──────────────   策略规则   ┌──────────┐   执行   ┌──────┐
│ 多路扫描器 │ ──────────→ │ 观察池→候选池 │ ─────────→ │ 目标组合  │ ─────→ │ 持仓 │
└──────────┘   去重/冷却   └──────────────┘   风控+仓位   └──────────┘          └──────┘
      ↑                          ↓
  行情/信号/事件/异动        机会质量回填（T+H 验证 → 扫描器打分）
```

铁律：**扫描结果不能直接下单**——必须经策略（Strategy Spec）与风控；每笔交易可回溯到"哪个扫描器在哪天发现了它、理由是什么"。

## 二、机会来源：多路扫描器（Scanner SPI，可插拔）

```python
class Scanner(Protocol):
    id: str; name: str; market: str
    frequency: str          # 盘后 | 盘前 | 盘中-快照 | 盘中-事件
    scope: str              # 全市场 | 热集 | 事件触发
    def scan(self, ctx) -> list[Opportunity]: ...
```

| # | 扫描器 | 数据/方法 | 频率 | 现状/来源 |
|---|---|---|---|---|
| 1 | **模型信号扫描** | 推理分数 rank 分位（现有主链路） | 盘后 | ✅ 已有（就是现状选股） |
| 2 | **技术形态扫描** | 形态规则库（涨停回马枪/多方炮/W底/碗口/仙人指路…） | 盘后+盘中 | 移植 KHunter 13 策略 + selector 碗口/B1（规则层直接可用，见框架调研） |
| 3 | **资金流扫描** | 主力/大单净流入、北向、龙虎榜 | 盘后 | 🟡 数据有（北向/龙虎榜数据集），未系统化 |
| 4 | **事件扫描** | 新闻/公告/研报 → FinBERT+LLM 分级 | 盘中分钟级 | 🟡 FinBERT 已有，事件结构化待建（LLM 方案 §三） |
| 5 | **异动扫描** | 量比/涨速/封板开板/大单/盘口突变 | 盘中 3s |  L2 阶段强化（L2 方案 §五） |
| 6 | **板块联动扫描** | 行业 RST、龙头带动、涨停梯队 | 盘后+盘中 |  行业数据有，联动逻辑待建 |
| 7 | **反转/超跌扫描** | 超跌反弹、破净、极端分位 | 盘后 | ❌ 易加（数据齐全） |

扫描器**注册即生效**（与策略注册表同机制）；每个扫描器独立开关、独立打分、独立被评估（§五）。

## 三、统一机会对象与评分

```jsonc
{ "id": "opp_...", "ts": "2026-09-16T10:23:00+08:00", "market": "CN",
  "symbol": "600036.SH", "sources": ["model_signal","pattern:duofangpao"],  // 多扫描器命中合并
  "strength": 0.87,            // 扫描器内强度（归一 0..1）
  "score": 82,                 // 汇总分（跨扫描器可比，接评估体系分制）
  "horizon": "T+1..T+5",       // 机会有效期（过期作废）
  "evidence": { "signals": {...}, "pattern": {...}, "events": [...] },       // 证据链
  "expiry": "...", "state": "watch|candidate|chosen|expired" }
```

- **合并与去重**：同标的多扫描器命中 → 合并 sources、分数加权（多源共振加分）；同源重复 → 冷却期（N 日内不重复报）。
- **新鲜度衰减**：机会分数随时间衰减（与信号半衰期同口径），过期自动出池。
- **排序**：score 降序 + 行业分散约束（同行业限量，防"一屏全是同一个板块"）。

## 四、扫描引擎架构（性能）

| 模式 | 范围 | 引擎 | 目标性能 |
|---|---|---|---|
| 批扫描（盘后） | 全市场 | polars/DuckDB 向量化 + 多进程 | 全市场全扫描器 **< 60s** |
| 盘前扫描 | 全市场（用昨收+今日信号） | 同上 | < 30s |
| 盘中扫描 | 热集（持仓+候选+异动） | 内存增量（L2 阶段：快照节拍） | 每轮 **< 1s**（3s 节拍内） |
| 事件扫描 | 事件触发 | 事件驱动单标的 | < 1s |

扫描器实现纪律：**纯函数式**（输入数据快照 → 输出机会列表），不碰账本、不下单、无副作用——可回放、可单测、可并行。

## 五、机会质量回填（扫描器也要被评估）

每个机会在 T+H 后自动回填：

| 指标 | 说明 |
|---|---|
| 命中率 | 机会标的 T+H 超额收益 > 0 的比例 |
| 盈亏比 / 平均超额 | 按来源分桶 |
| IC | 机会分 vs 实际收益的秩相关（分数是否真有区分度） |
| 增收贡献 | 该扫描器引入的机会，最终被策略采纳并盈利的贡献 |

输出：**每个扫描器的评分卡（接评估体系）** → A/B/C/D → 差的扫描器自动降权/停用建议；好的加权。
这条闭环是"找机会能力"持续进化的机制——**没有回填的扫描器等于装饰**。

## 六、机会呈现（交易台）

- **今日机会**面板：分来源分组、分数排序、证据链下钻（信号/形态图/事件原文）、一键"加入候选池"
- **盘中机会流**（P6 起）：实时滚动，异动/事件即时推送（钉钉/前端红点）
- **机会池**页：观察池/候选池管理（进出规则、过期、人工置顶/拉黑）
- 与调仓计划衔接：候选池 → 策略 → 当日的"调仓计划"（人工可审）
