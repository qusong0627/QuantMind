## 2. 目标

1. **恢复入口**：模型管理多选 ≥2 个模型 → 融合为新的「融合模型」，全程可审计。
2. **必产预测**：融合模型创建即进入日更推理名单（`qm_model_inference_settings`），每日出分落 `engine_signal_scores`（`script_v1_<fused_id>` 桶）+ `pred.parquet`，与普通模型同等人格。
3. **机构级权重**：滚动 ICIR + 多样性惩罚 + 样本量收缩（向 1/N 先验收缩）+ 单成员上限 + 近似重复剔除；无前视（收益已实现才计入）；权重快照落盘 + 审计流水；周更 + 最小变更阈值防抖。
4. **创建即有证据**：创建前 OOS 回放（融合 vs 全体成员），低于成员中位数即红字警告。

## 3. 权重引擎（默认策略 `icir_shrunk`）

纯函数模块 `backend/shared/fusion_weights.py`，输入 = 各成员日度已实现 rank_ic 序列 + 成员间截面分相关矩阵；输出 = 权重 + 逐成员诊断。

```
1) 有效样本：n_i 天（数据适配层按 as_of - h_i 截断，防前视；见 §4）
2) ICIR_i = mean(ic)/std(ic)；n_i < MIN_DAYS(20) 的成员不参与 ICIR 倾斜
3) 多样性惩罚：pen_i = 1 / (1 + mean_{j≠i} max(C_ij, 0))
4) 原始分：raw_i = max(ICIR_i, 0) * pen_i；全员 ≤0 → 等权兜底
   （兜底 warning 按根因区分：all_insufficient_days_fallback_equal /
   all_icir_nonpositive_fallback_equal —— 新融合模型常见「样本不足」与
   「全员 ICIR 非正」是两个完全不同的信号，不可混为一谈）
5) 收缩（向 1/N 先验）：λ_i = n_i / (n_i + K)，K=60
   w_pre_i = λ_i * normalize(raw)_i + (1 - λ_i) * (1/m)
6) 阈值清理必须在封顶**之前**：w < 0.02 → 0 并重归一（先封顶会把
   该清理掉的碎屑权重按比例放大给其余成员）
7) 单成员上限：**有效上限 = max(0.40, 1/存活成员数)** —— 2 成员时允许
   0.5/0.5 这类天然均分，MAX_WEIGHT=0.40 只在成员数 ≥3 时真正收口；
   超出部分按未封顶成员 w_pre 比例再分配（水位填充，迭代≤10）
8) 硬去重：C_ij > 0.98 且 (ICIR, n) 低者 raw 清零（reason="duplicate"）
9) 输出 diagnostics：ic_mean/ic_std/icir/n_days/pen/raw/w_pre/w_final/drop_reason
```

- `equal`：1/m（先验兜底与对照）。
- `manual`：用户输入归一化（保留，供专家覆盖）。
- 旧 `recent_ic` 废弃（映射到 `icir_shrunk`）。

## 4. 数据适配（`backend/services/engine/inference/fusion_quality.py`）

- **成员 IC 序列**：从 `engine_signal_scores` 分数桶（`feature_version='script_v1_<model_id>'`）+ QuantDB `daily_forward`（qfq 前复权）已实现收益现场回算 rank_ic。
- **防前视 = QuantDB 分区自然截断**：标签用 `daily_forward` 的已落盘分区计算 —— as_of 之后根本没有分区文件，未来收益天然不可得，无需额外截断逻辑（比「窗口右端截 h_i」更强：数据面本身就是时间闸门）。
- **成员相关性**：同一批同日截面的两两 Spearman（`pairwise_corr`）。
- **OOS 回放评估**：生产模板同款 L1（截面 rank 百分位）+ L3（Σw·rank/Σw，缺省 1/n）回放成员历史分 → rank_ic/ICIR vs 成员中位/最优（创建前预览 + 创建后落 `fusion_eval.json`）；不含 L4 共识调节（那是执行期调节，回放保持纯线性口径）。

## 5. 产物与人格

融合模型目录（`models/users/{tenant}/{user}/[market/]mdl_{mkt}_ensemble_{ts}_{hash}/`）：

```
ensemble_config.json   v2：members[]/weight_strategy/fusion_strategy/constraints/version=2
weight_snapshot.json   {as_of, weights, diagnostics, sample_days, shrink_lambda}
weight_history.jsonl   审计流水（每次刷新一行）
fusion_eval.json       OOS 回放结论
metadata.json          is_ensemble=true, model_type=ensemble, market/horizon 汇总
inference.py           ensemble 模板（runner 每次推理前强制同步）
```

- **创建即写 `qm_model_inference_settings(enabled=TRUE)`** ←「预测能力」的核心修复；UI 可关。
- **数据面继承（2026-10-09 E2E 后补）**：`metadata.data_source / quantdb_dir(pin) /
  factor_source / factor_schema_hash / factor_field_sources` 一律**从成员 metadata
  多数票继承**（平票倾向 quantdb_factors；分歧落 `data_plane_warnings` 且日志可见）。
  历史缺陷：硬编码 `data_source="parquet"` → runner 路由到 feature_snapshots
  （本机停更 2026-08）→ 融合模型「能推理但读陈旧数据」，与成员（quantdb_factors）
  完全脱节。模板侧 `load_day_data` 按自身 metadata 分派：quantdb 直读
  （pin 目录 + `assert_ready` 漂移只警告 + `read_day` 按名取数）优先，parquet 布局兜底。
- **成员权重定位（2026-10-09 二修）**：成员 metadata 的 `model_file` 记的是
  per-algorithm 名（`model_nativetft.pth`），磁盘上落的是通用名 `model.pth`；融合
  模板原按扩展名列表盲搜且 `*.pkl` 排最前 → 先命中 61MB 的 `pred.pkl`（预测结果
  DataFrame），既分类不出 `__dl_member__` 也崩在 `predict()`，DL 成员被静默跳过
  （E2E 实锤：融合只出 LGB 成员覆盖数 3219，成员侧仅 stderr 一行警告）。修复 =
  口径对齐 `inference_parquet._resolve_model_path`：声明名对不上先试**同后缀通用名**
  （`model.<ext>`），盲搜按权重白名单（pred*/result/config 等训练产物永不入选），
  多候选显式警告取 `model.*`。
- 估值/评估中心按 `ensemble` kind 展示（`eval_scores.py` 已预留标签）。

## 6. 推理数学（模板升级，向后兼容）

每成员分 → 截面百分位 `rank_pct`（保留）→ 按 `weight_snapshot.json` 加权平均（缺快照回退 config 权重 → 等权）→ `consensus` 统计。可选 `trimmed_rank`（截尾均值抗离群成员）。成员 DL 委派、成员脚本同步、市场透传逻辑不动。

`weight_snapshot.json` 读取兼容 v1 扁平 / v2 嵌套（`_parse_snapshot_weights`：v2 只认
`weights` 段，绝不把 version/as_of 当权重解析后静默回退静态权重）。数据侧
`load_day_data` 按**本模型 metadata** 分派数据面（quantdb 直读 / parquet 兜底，
口径与成员模板 `inference_parquet.load_date_data` 同源；过滤不可交易行含 is_st）。

## 7. 权重刷新（beat）

`refresh_fusion_weights`（每日 22:30，实际周更节律）：扫全部 `is_ensemble` 模型 → 拉成员 IC（含缺口回算）→ 引擎计算 → 与现快照比对，最大权重变动 < 0.02 则不落盘（防抖）→ 原子写 `weight_snapshot.json` + append `weight_history.jsonl`。

> 实现注记（2026-10-10，P2-4 `23789a68`）：实现于 `backend/services/engine/inference/fusion_refresh.py`。扫描判据收紧为**两条并列**（`is_ensemble=true` **且**带 `source_model_ids`——训练管线落库的 stacking 模型也带 `is_ensemble=true`，没有 weight_snapshot 可刷）。**写入面纪律**：刷新是写入面不是预览面——证据不可得/成员解析失败绝不降级等权重算写盘（那等于把等权当「重算结果」静默改生产权重），跳过留原因下 tick 重试；manual（用户意图）/equal（无参可变）跳过。
