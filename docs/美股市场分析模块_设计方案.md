# 美股市场分析模块（QuantUS Market Analysis）设计方案

> 目标：为 QuantUS（美股）建立与「港股市场分析」平级的独立市场分析模块。
> 结构对标港股，**内容按美股量化实际会看的数据重新设计**（不是把港股面板照搬换数据源）。
> 只依赖本地 QuantUS parquet，无外部实时行情依赖。

---

## 一、结论先行

1. **架构照抄港股**：后端 `backend/services/api/market_analysis_us/`（独立市场目录）+ 复用
   `market_analysis_shared/`（零改动）；前端 `electron/src/features/market-analysis-us/`。
   接线只需动 3 个文件：后端 `api/main.py` 各 1 行 import/include_router，前端 `App.tsx`
   1 行 lazy import + 1 处三分支判断。
2. **但内容不照抄**：美股的「南向资金 / CCASS 席位 / AH 比价」没有对应物。美股量化真正会看的
   是：**市场宽度（MA50/200、52 周新高新低、A/D 线）**、**财报季超预期**、**分析师升降级与
   目标价**、**内部人交易与机构持仓**。这四块数据本地全部齐备且质量高，构成本模块的差异点。
3. **两块港股有、美股没有的**：期权（只有 call + 单到期日 + 单快照，做不了 PCR / IV Rank）、
   宏观（数据停更在 2025-09）。本方案**明确不做**，避免做出来是废面板。
4. **发现 3 个必须先修的数据链路缺陷**（§四），其中 valuation 面板当前是坏的（2026-08-28 起
   全 NULL），根因已定位到具体代码行。
5. **可维护性是硬要求**，因此后端 feed **按域拆包**，不重复港股那个 1964 行单文件的做法。

### 2.2 港股模块可复用的部分

### 2.3 页面骨架模式（照港股 1:1 抄）

`MarketAnalysisHkPage.tsx` 的工程模式已验证可用，直接沿用：

- Tab 为**手写按钮组**（非 antd Tabs），`NAV_TABS` 数组定义 id/label/icon
- 数据加载：`useState` + `useCallback` + `useEffect`，无 SWR / React Query
- 子面板**各自取数**，父页面只传核心三件套（indices/breadth/heatmap）
- 刷新：`POST /refresh` 同步返回后重新 `loadCore()`（SSE 端点后端有、前端未消费）
- 空态：`EmptyHint({text, loading})`；错误：`message.error`
- 样式：Tailwind 原子类；**中文界面**

## 三、模块内容设计（美股量化看什么）

### 3.1 Tab 规划（7 个，每个 Tab ↔ 一个后端 feed 模块，1:1 便于维护）

| # | Tab | 核心内容 | 数据来源 | 优先级 |
|---|-----|---------|---------|--------|
| 1 | **大盘脉搏** | 5 大指数卡（标普/纳指100/纳指/道指/费半）、市场温度计（涨跌家数 / 上涨占比 / 中位数涨幅 / ±5% 异动）、GICS 11 板块热力图、赚钱效应榜 | `index_daily`、`daily_forward`、`sector` | P1 |
| 2 | **市场宽度** | % 站上 MA50 / MA200、52 周新高/新低家数、A/D 累计线与 20/60 日走势、涨跌幅分布直方图、距 52 周高点距离榜 | `daily_forward`（250 日窗口自算） | P1 |
| 3 | **板块轮动** | GICS 11 板块 × 1/5/20/60 日收益、相对标普强弱（RS）、板块内上涨占比、板块领涨股、板块估值中位数 | `sector` + `daily_forward` + `f10` | P1 |
| 4 | **财报超预期** | 未来 30 天财报日历、近期已披露+超预期幅度榜、EPS/营收预期增速、PEAD 候选（超预期 × 近期动量） | `4_analyst/{calendar, earnings_dates, earnings_history, earnings_estimate, revenue_estimate}` | P2 |
| 5 | **分析师动向** | 评级升降级流水（含目标价变更）、目标价隐含空间榜、评级分布迁移、覆盖机构数变化 | `4_analyst/{upgrades_downgrades, analyst_price_targets, recommendations}` | P2 |
| 6 | **资金与筹码** | 内部人净买入/净卖出金额榜、集群买入信号、机构持仓增减榜、分红除息日历、近期拆股 | `4_analyst/{insider_transactions, mutual_fund_holders, major_holders}`、`3_financial_data/{dividend, splits}` | P2 |
| 7 | **估值主题** | 高股息 / 低 PE / 低 PB 三榜、市值分层（mega/large/mid/small）、距 52 周高低位置、行业估值温度计 | `2_base_sector/f10`（快照） | P3 |

**美股 vs 港股的口径差异（必须在页面标注，避免用港股习惯误读）**

| 维度 | 港股口径 | 美股口径 |
|------|---------|---------|
| 涨跌停 | 无 → 快涨快跌取 ±5% | 无涨跌停（有 LULD 熔断）→ 异动同样取 ±5%，但**含义是统计异动而非涨停** |
| 行业体系 | 恒生行业 | **GICS 11 大类 + 细分 industry**（`sector/{SYMBOL}.parquet`） |
| 资金穿透 | 南向持股 + CCASS 席位 | **内部人交易（SEC 强制披露）+ 机构持仓（13F 口径）** |
| 两地联动 | AH 对应股 | **无对应物** → 换成「相对标普强弱（RS）」 |
| 板块宽度 | 无 | **% above MA / 52 周新高新低 / A/D 线**（美股量化招牌指标） |
| 财报 | 无 | **财报日历 + 超预期 + PEAD**（美股事件驱动核心） |
| 指数成交额 | 指数卡含成交额 | **`index_daily.amount` 恒为 0**（实测 5 个指数全 0）→ 指数卡不显示成交额；量能改用 `volume`，但 **`SOX.US` 的 volume 也是 0** → 前端须按「缺失则隐藏」处理，不能渲染成 0 |

### 3.2 明确不做的（数据源限制，做了也是废面板）

| 项 | 原因（实测） |
|----|-------------|
| 期权 PCR / IV Rank / 期权链 | `4_options` 486 个文件合计仅 1.5 万行：**只有 call、每股只有 1 个到期日、只有单快照无历史** |
| VIX / 恐慌指数 | `index_daily` 只有 5 个指数（SPX/NDX/IXIC/DJI/SOX.US），**没有 VIX** |
| ETF 资金流（SPY/QQQ…） | 标的池是标普500 + 纳指补充，**一只 ETF 都没有** |
| 宏观面板 | `macro_usa.parquet` **数据停在 2025-09**（同步脚本约一年没跑） |
| 基本面因子 | `l1_factors` 的基本面列（pe/pb/roe/mv 等）被 `update_market_features.py:263` 显式填 0，属设计如此 |
| 季度盈利趋势 | 财务三表**只有年报，无季报** |

> VIX 的替代：用标普已实现波动率（20 日年化，自算）+ 市场宽度做恐慌度代理，页面命名上不叫 VIX。

### 3.3 标的池与覆盖度（页面需标注）

- 标的池：标普500 权重股 + 纳指补充，**约 517 只**（非全市场），来源 `rd_agent/data_pipeline/us_data.py` 的 `SP500_FULL + NASDAQ_EXTRA`
- 日线：517 只 / 232 万行 / **2001-01-02 起** / 最新分区 `2026-09-10`
- 行业分类覆盖 516 只（GICS 11 类：Technology 82、Industrials 67、Consumer Cyclical 62、Financial Services 61、Healthcare 57…，29 只 sector 为空）
- 分析师类数据覆盖 482-498 只（最完整的一块）

## 五、技术设计

### 5.1 后端目录结构（按域拆包 —— 对港股单文件巨石的可维护性改进）

```

├── router.py            # ~250 行：端点定义（REST + SSE 刷新），只做参数校验与 to_thread 转发
├── feed/
│   ├── __init__.py      # 统一出口 + clear_cache_us()
│   ├── base.py          # 数据目录解析、DuckDB 连接、单日/区间读取、交易日、名称映射、缓存包装
│   ├── indices.py       # Tab1 指数脉搏
│   ├── breadth.py       # Tab1 温度计 + Tab2 宽度（MA50/200、52周高低、A/D 线、分布）
│   ├── sectors.py       # Tab1 热力图 + Tab3 板块轮动 / 板块内宽度 / 板块估值
│   ├── earnings.py      # Tab4 财报日历 / 超预期 / 预期增速 / PEAD
│   ├── analysts.py      # Tab5 评级升降级 / 目标价 / 评级分布
│   ├── holdings.py      # Tab6 内部人 / 机构持仓 / 分红拆股日历
│   └── valuation.py     # Tab7 估值榜 / 市值分层 / 52周位置

```

每个域模块 150-300 行，函数单一职责（`get_xxx()` 纯数据返回 dict/list），可单测。
`base.py` 是唯一与 parquet 目录耦合的地方 —— 换数据源只改一个文件。

### 5.2 数据访问与性能约束（**必须遵守，否则页面会卡死**）

1. **单日/近 N 日截面禁止全 glob**：`daily_forward` 有 6571 个分区，对 `dt=*/data.parquet` 做
   全通配会被 DuckDB 的 hive `dt` 列遮蔽问题拖到**每批全扫（实测 5.5 分钟/6 日）**。
   一律走精确分区路径 `dt=YYYYMMDD/data.parquet`（单日 0.04s）。
2. **全量小文件一次读入 + 进程内缓存**：`sector/`、`f10/`、`4_analyst/*` 各约 500 个小文件，
   用 `read_parquet('dir/*.parquet')` 一次读全市场再缓存，**不要每请求重读**。
3. **长窗口（250 日）** 按需拼接分区文件列表，不读全history。
4. **复权口径**：`daily_forward` 是**原始未复权价**（yfinance `auto_adjust=False`），
   且 `amount` 是**美元原始成交额**（无换算系数，与 QuantDB 的「股/万元」口径不同）。
   - 涨跌幅取 close-to-close，对拆股/大额分红造成的 >±100% 异常做裁剪（对齐港股既有口径）
   - 市场/板块级聚合一律用**中位数**（对异常稳健），个股排名叠加裁剪
   - 拆股用 `3_financial_data/splits` 事件检测，不做事后全量复权重建（列为可选增强）
5. **NaN 安全**：所有数值经 `display.safe_float` / `pct` 出口，前端再做一次防御
   （历史事故：`null.toFixed` 导致整页白屏）。

## 十、为什么这样设计（可维护性说明）

1. **独立市场目录 + 共享层**：沿用港股已验证的两层结构，新市场不污染现有模块
2. **后端按域拆包**：港股 1964 行单文件 → 美股 8 个 150-300 行模块，每个域可独立单测与迭代
3. **一个 Tab ↔ 一个 feed 模块 ↔ 一组端点**：改一个面板只碰一个文件，心智负担恒定
4. **前端组件提升而非复制**：`ShenwanHeatmapChart` / `shared/ui.tsx` 提升到跨市场共享目录并 re-export，避免三份副本漂移
5. **口径集中声明**：后端 `README.md` 记录单位/复权/阈值口径，与 `market-analysis-hk/README.md` 同构，后来者照着读
6. **数据源限制显式化**：不做的部分写清楚原因，防止后人重复踩坑（如"为什么没有期权面板"）
