# CCASS 数据口径审计与修复（2026-11-13）

> 范围：`quanthk/2_base_sector/ccass_top50` 原始数据、`6_ml_datasets/ccass_factors`
> 派生因子、港股夜链任务与复权因子链。结论按「可复现、可回滚、可质检」交付。

## 1. 数据是什么

| 项 | 口径 |
|---|---|
| 来源 | HKEX「中央结算系统持股纪录查询」（`searchsdw_c.aspx`） |
| 粒度 | 每只股票 **持股量最大的前 50 名 CCASS 参与方**（按持股量降序截断） |
| 行语义 | 某参与方（券商/托管行/结算机构）在该股票上的**代客持股**，不是机构自营 |
| 数量 | `holding_quantity`，单位=股 |
| 百分比 | `holding_percentage`，占**已发行股份**（HKEX 两位小数），不是占流通股 |
| 历史 | 2024-11-22 起（首个分区仅 236 只，实际完整起点 2024-11-25） |

参与方 ≠ 机构：HSBC C00019、花旗 C00010、渣打、中银香港是托管行（客户合计）；
富途 B01955、耀才、盈透是零售券商；中银国际、海通、招商、中信、高盛、UBS、
大摩是券商（自营+客户混合）。研究结论只能写到「某券商/托管行客户合计」这一层。

南向对账：CCASS 的 ChinaClear 两席位（A00003+A00004）持股与 `hsgt_south`
一致——939 只重叠、250 只完全相等、相对差中位 0.1%。

## 2. 已修复的错误（逐条）

### 2.1 百分比跨期单位不一致
2024-11-22 ~ 2025-12-12 的分区里，`holding_percentage` **同一天混用两种单位**：
≥1% 的行存小数（0.3633），<1% 的行存百分点（0.94）。典型股票 top50 合计
中位 **8.3**（应为 0.83）。

修复：`backend/shared/ccass_top50.repair_percentages()` 逐股票日估计总股本
（取 pct≤100% 的前 3 大持仓的 `qty/pct` 中位），逐行判定小数/百分点；
整日全判小数但合计 >105% 时整体 /100。修复后全库 stock-day 合计中位 0.81。

### 2.2 4 列布局把持股量当百分比
HKEX 对少数股票（0884/1801/2269/4332–4338 等）**不返回百分比列**。旧解析
`len(cols)>4` 判断失败后 fallback 到持股量：带逗号的数 → NaN → 写成 0；
少于 1000 股 → 数量/100（990 股 → 9.9%）。

修复：爬虫改为**按表头取列**，取不到百分比就是 `None`；落库层不再
`fillna(0)`，>100% 一律 NaN；无法判定的行若有可靠总股本锚则按
`qty/issued` 折算，否则保持 NaN（**绝不填 0**）。参考股本必须 ≥ 当日最大
持仓，否则视为过期/损坏并拒绝。

### 2.3 节假日重复分区
yfinance 日历把 2026-01-01、春节（02-17/18/19）、复活节（04-03/06/07）、
端午（06-19）当交易日；HKEX 对非交易日返回上一交易日快照，形成 8 个与前一日
逐行相同的分区。

修复：
- 交易日改从 `index_daily`/`daily_forward` 分区读取（行情链实际口径）；
- 已存在的 8 个假日分区移到 `2_base_sector/ccass_top50_quarantine/`（移动不删除，
  `manifest.jsonl` 记账）；
- 同步新增**重复快照指纹**：与上一交易日 99.9% 行同值即判重复并隔离；
- 新增分区写 `qc.json` 侧车（行数/股票数/缺失百分比/合计分位）。

### 2.4 CCASS 因子构建 OOM（`ccass_factors` 停更根因）
旧实现把 493 个分区（6,500 万行 × 5 列）全读进 pandas，峰值打爆 celery
容器 12G 硬限，worker 被 SIGKILL；港股夜链死在该步骤，Yahoo 元数据段永远
跑不到（财务/分析师/F10 停在 8~9 月）。

修复：
- `build_ccass_factors()` 改为**逐分区流式**：单日读入 → 聚合 → 落盘，
  内存 O(单日 + 股票数×20)；
- `build_participant_flows()` 同样流式输出机构级日频流水；
- 夜链的 `_refresh_signal_datasets()` 改为**子进程 + RLIMIT_AS（默认 6G）**，
  OOM 关在子进程，父任务继续跑 Yahoo 段；
- 因子填充调度（04:30）登记 `ccass_participant_flows`，落后才建。

### 2.5 南向对账口径（A 席 vs hsgt_south）
旧对账用「CCASS A 席全量 ÷ hsgt_south 全量」：CCASS 只披露 top50，2026-11-12
有 86 只股票的中国结算席位排在第 50 名之外，比例被凭空拉低到 0.9696，触发
±2% 数据质量门。修复：**按两边都可见的股票交集**计算，并保留覆盖率门
（交集 ≥ 南向股票 90%）。交集口径比值 ~1.000，`evidence.reconciliation`
与测试同步改为交集口径。

### 2.6 抓取中的半成品分区被当成最新（2026-11-14 补）
夜间 CCASS 同步按批次落盘；最新分区在抓取中可能只有 598/2,745 只（11-13
实测）。`quanthk_feed` 原先直接取最后一个分区，页面/接口会显示「无持仓」。
修复：`_drop_incomplete_tail` 以最近 5 个分区的最大股票数为峰值，尾部低于
80% 峰值的分区视为半成品；`get_ccass_holding` / institutional overview /
分类覆盖率测试统一走完整分区。

### 2.7 复权因子链停更（daily_backward 实际只到 2026-05-08）
旧实现依赖 akshare `stock_hk_hist`（东财）取 `preclose`。2026-11 实测该端点对
容器 IP 返回 `RemoteDisconnected`，每晚增量全部失败；`daily_backward` 8-28 之后
的分区只有约 130 只（其余标的停在 5-08）。另外东财 `preclose` 是昨收，不含现金
分红，复权链会漏股息。

修复（`quanthk_adjust_factor.py` 重写）：
- 复权比例改取 Yahoo `Adj Close / Close`（按分红/拆股阶跃，非行动日实测完全
  稳定），以既有因子文件在重叠日的值做比例锚，历史段不变、只续新日期；
- 原始 OHLCV 复用本地 `daily_forward`（Sina），不重复抓行情；
- 从「最后一个完整覆盖的 daily_backward 分区」之后增量重写（当前 2026-05-09
  起），批量 Yahoo 下载（80 只/批）+ ffill 对齐，缺 Yahoo 的标的按最后因子
  常数延展并记账；
- 仍并入港股夜链（`HK_ADJUST_FACTORS_ENABLED` 默认开，子进程 + 2400s 预算），
  失败不影响 Yahoo 元数据段。

## 3. 机构级研究数据集

新增 `quanthk/6_ml_datasets/ccass_participant_flows/dt=YYYYMMDD/data.parquet`，
每行 = 某股票 × 某参与方 × 交易日：

| 列 | 含义 |
|---|---|
| `participant_group` / `participant_group_name` | 规范分组（HSBC 多实体、ChinaClear 多席位合并） |
| `pct_type` | `cust` 托管行 / `brok` 券商 / `csc` 中国结算（南向） |
| `holding_quantity` / `holding_percentage` | 当日在 top50 内的持股（修复后百分比） |
| `prev_qty` / `delta_qty` | 与上一交易日对照；**entry/exit 为 NaN** |
| `entry_flag` / `exit_flag` | 进入/掉出 top50；掉出 ≠ 清仓，进入 ≠ 新建仓 |
| `top50_streak_days` / `top50_days_total` | 连续/累计在榜天数（持久性过滤） |
| `stock_flow_net` / `stock_flow_gross` | 仅连续席位的净流/毛流 |
| `stock_net_over_gross` | 净/毛比；很低说明当日主要是过户/转移 |
| `stock_entry_qty` / `stock_exit_qty` | 边界进出量（单列，不混入净流） |
| `adv20_volume` / `adv20_amount` | 前 20 个交易日均量/均额（不含当日） |
| `delta_over_adv20` | 席位变动 / 前 20 日均量 |
| `corporate_action_flag` | 隐含股本变动 >5% 的股票日（拆股/送股/配股/大额转仓） |

必须遵守的研究纪律：
1. 只用**连续在榜**席位的 `delta_qty`；entry/exit 按缺失处理；
2. 先用 `top50_streak_days ≥ 20` 过滤持久席位；
3. `corporate_action_flag=True` 的股票日不用 delta；
4. 单日噪声大，用 5/20 日累计净流；
5. 前向收益用复权后的 `daily_backward`，按 T+1 可买口径；
6. 先做随机/安慰剂基线，单席位 IC 与随机无异则只做描述性资金流。

## 4. 运行与回滚

```bash
# 历史修复（默认 dry-run；--apply 写回并备份原百分比列）
python backend/scripts/quanthk_ccass_repair.py --dry-run
python backend/scripts/quanthk_ccass_repair.py --apply
# 回滚百分比列
python backend/scripts/quanthk_ccass_repair.py --restore --apply

# 重建派生数据集（流式，分钟级）
python backend/scripts/build_ml_signal_datasets.py --dataset all

# 复权因子链（增量）
python backend/scripts/quanthk_adjust_factor.py
```

备份/隔离目录：
- `2_base_sector/ccass_top50_pct_backup/dt=*/data.parquet`（原百分比列，228MB）
- `2_base_sector/ccass_top50_quarantine/dt=*`（8 个节假日重复分区）
- `2_base_sector/ccass_top50_repair_manifest.json`（逐分区修复前后 QC）

## 5. 验收口径

- 全库 stock-day 百分比合计：中位 ~0.81，p99 < 1.0，**无 >105% 的伪造值**
  （允许极少数真实数据异常，由 `ca_pct_bad_sum` 标记并让 pct 特征置空）；
- `holding_percentage` 无 0 值（缺失统一 NaN）；
- `ccass_top50` 分区日期全部 ∈ 行情交易日；
- `ccass_factors` / `ccass_participant_flows` 最新日期 = `ccass_top50` 最新日期；
- 港股夜链 `signal_datasets` 子进程返回 `status=ok`，不再出现 WorkerLost。
