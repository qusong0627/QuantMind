# 训练目标契约（Target Contract）使用说明

> 版本：v1.0 · 2026-11-24
> 详细实施计划：`docs/训练目标体系_W0-W6_机构级实施细案_20261124.md`
> 适用：训练页 / `/api/v1/models/run-training` / 13 个 per-model 入口 / 滚动重训

## 1. 一句话

训练目标不再是一组散落的平铺字段，而是**注册表里版本不可变的目标定义**：
训练请求只引用 `target_ref {id, version}`，可选的 `label_overrides` 受白名单约束；
API 把冻结 spec + sha256 写进 config，训练容器重新校验后才开始训练。

## 2. 目标定义（LabelTargetSpec）

| 字段 | 说明 |
|---|---|
| `target_id` / `version` | 身份；同一版本内容永不修改，改口径必须升 version |
| `market` | 必须与 `context.market` 一致 |
| `family` | P1：`forward_return` / `classification_binary` / `quantile_return` |
| `mode` | 与 family 匹配：regression / classification / quantile |
| `horizon_days` | 1–30 个交易日 |
| `entry` | `lag_days` 固定为 1（A 股 T+1 治理锁）；`price` = open/close |
| `exit` | P1 固定 close |
| `transform` | rank / zscore / raw / top_tail / size_excess_rank / size_excess_zscore |
| `transform.top_pct` | 仅 top_tail 可非 0.2 |
| `transform.drop_extreme_pct` | 仅 forward_return + rank/zscore/raw 可 >0 |
| `label_contract_version` | 当前 1；容器拒绝未知版本 |

**覆盖白名单**：
- `forward_return`：horizon_days、label_transform、label_top_pct、label_drop_extreme_pct
- `classification_binary`：horizon_days
- `quantile_return`：无（分位水平固定）

**状态机**：`draft → active → deprecated`；新训练只能引用 active；同 hash 的历史重训可显式放行 deprecated——重训/滚动配方会带 `target_ref + label_overrides + expected_target_hash`，API 只在覆盖后 hash 逐字节一致时放行。

## 2.1 重训复现

模型 metadata 记录 `target_id/target_version/target_hash/target_base_hash/target_spec/target_overrides`。
滚动配方/「重新训练」只发这三件：`target_ref`、原训练实际 `label_overrides`、`expected_target_hash`；
API 应用覆盖后重算 hash，不一致直接 `target_hash_drift` 422，避免“重训悄悄换口径”。
`expected_target_hash` 也是 deprecated 目标的唯一放行凭证（必须与覆盖后 spec 完全一致）。

## 4. 接口

```
GET  /api/v1/models/training/capabilities           # 能力矩阵（只读）
GET  /api/v1/models/training/targets?market=CN&status=active
GET  /api/v1/models/training/targets/{id}/{version}
POST /api/v1/admin/models/training/targets          # 创建 draft（管理员）
POST /api/v1/admin/models/training/targets/{id}/{version}/activate
POST /api/v1/admin/models/training/targets/{id}/{version}/deprecate
```

提交请求示例：

```json
{
  "model_type": "lightgbm",
  "target_ref": {"id": "cn_ret_5d_open_rank", "version": 1},
  "label_overrides": {"horizon_days": 10},
  "...": "其余字段照旧"
}
```

旧请求不带 `target_ref`：API 合成 `legacy` spec，config 键集合与训练行为不变；
metadata 记录 `target_id=legacy` 与合成 hash，便于追溯。

## 5. 容器自校验与标签诊断

- `label.target_id` 存在时：`target_spec` 必须可解析、`target_hash` 必须匹配、
  平铺字段必须与 spec 一致、`label_formula` 不允许 `=` 覆盖；任一不符 abort。
- 训练前标签诊断：
  - NaN 率 > 50% → `target_label_incomplete`
  - 分类正类率 < 1% 或 > 99% → `target_label_degenerate`
  - 每日有效标签 < 50 → `target_label_cross_section_too_small`
  - top-tail 实际比例偏离目标 > 50% → `target_label_tail_unstable`
  - test 尾部标签不完整 → 仅 warning
- 开关：`QM_TARGET_CAPABILITY_GATE=strict|warn|off`（默认 strict）、
  `QM_LABEL_DIAGNOSTIC_GATE=strict|warn|off`（默认 strict）；实际值写入
  metadata `contract_flags`。

## 6. 上线与回滚

### 上线顺序
1. 发布 `backend/shared/db_migrations/upgrade_v1.1.9.sql`（API 启动自动执行；幂等，可连续跑两次）。
2. API 镜像（含注册表/提交解析/硬闸）；先 `QM_TARGET_CAPABILITY_GATE=warn` 观察。
3. 训练镜像（含容器校验/标签诊断）；跑 `QM_TRAIN_VALIDATE_ONLY=1` 冒烟：
   - legacy：`backend/tests/fixtures/w3_legacy_config.yaml`
   - registry：`backend/tests/fixtures/w3_registry_config.yaml`
   期望日志含 `TARGET_CONTRACT_OK` 且退出 0。
4. 前端构建（能力驱动目标面板）。
5. 无异常后切 `strict`，重启 API。

### 冒烟命令

```bash
QM_TRAIN_VALIDATE_ONLY=1 python /app/train.py --config /app/backend/tests/fixtures/w3_registry_config.yaml
```

### 回滚
1. `QM_TARGET_CAPABILITY_GATE=warn`、`QM_LABEL_DIAGNOSTIC_GATE=off`，重启 API。
2. 回滚 API / 前端 / 训练镜像；DB 表保留，不 DROP。
3. 若 cache key 已包含 target_hash：回滚后旧缓存可能重新命中；Runbook 要求
   回滚时清空训练缓存目录（`QM_TRAIN_CACHE_DIR` 指向的目录）。

### 审计查询

```sql
SELECT action, detail->>'code' AS code, count(*)
FROM qm_label_target_audit
WHERE action = 'blocked_resolve' AND at > now() - interval '24 hours'
GROUP BY 1, 2 ORDER BY 3 DESC;
```

## 7. 已知边界

- P1 不做：分类阈值/死区/类权重、中性化、成本后标签、三重障碍、外部标签列、
  多 horizon 联合；这些在 P2/P3，必须先过 PIT/覆盖率/标签自相关审计。
- `label_formula` 仅保留 legacy 兼容；带 `target_ref` 时禁止 `=` 覆盖。
- 历史模型不批量改写 metadata：读取时 lazy 合成 legacy spec/hash。
