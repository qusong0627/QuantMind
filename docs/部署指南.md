# QuantMind 部署指南

> 适用 **OSS 开源版**（单容器架构，所有后端服务运行在 `quantmind` 一个容器内）。
> 推荐系统：**Ubuntu 24.04 LTS**（部署脚本依赖 apt 与 systemd，同时兼容 22.04）。

***

## 一、前置要求

| 项目       | 最低要求                 | 推荐配置                                 |
| -------- | -------------------- | ------------------------------------ |
| CPU / 内存 | **4 核 / 8 GB**       | 8 核 / 16 GB 以上                       |
| 磁盘       | **100 GB**           | 200 GB+（Qlib 数据、模型与 PostgreSQL 业务数据） |
| 系统       | **Ubuntu 24.04 LTS** | 全新系统，root 或 sudo 权限                  |
| 网络       | 可访问 Gitee            | 可访问 Docker Hub（脚本已内置镜像加速）            |

**模型训练（可选）**：

* **本机 CPU / GPU**：最低约 **8 核 / 64 GB**；本地 Docker 训练默认走 CPU。仅做回测 / 推理 / 投研分析无需 GPU。
* **推荐：AutoDL 远程 GPU**：普通服务器当协调机，训练进程跑在 AutoDL Python 实例上（免嵌套 Docker）。步骤见 **第十一节**。

**端口占用清单**（部署前确认未被占用）：

| 端口                            | 服务                          | 说明                   |
| ----------------------------- | --------------------------- | -------------------- |
| 8000                          | API 网关                      | 用户认证、策略管理、数据平台       |
| 8001                          | Engine                      | Qlib 回测、AI 策略生成、模型推理 |
| 8002                          | Trade                       | 订单管理、持仓、风控           |
| 8003                          | Stream                      | 实时行情、WebSocket 推送    |
| 5432 / 6379                   | PostgreSQL / Redis          | 数据库与缓存               |
| 8088（可选）                      | QwenPaw                     | QuantBot AI 助手控制台    |
| 8004 / 8090 / 1200（可选） | 数据网关 / Huntly / RSSHub | 扩展服务                 |

## 二、运行环境与部署方式选型

### 2.1 运行环境推荐

| 环境                                    | 推荐度    | 说明                                                      |
| ------------------------------------- | ------ | ------------------------------------------------------- |
| **Linux 服务器 / VPS**                   | ✅ 强烈推荐 | 生产首选，性能与稳定性最佳                                           |
| **WSL2（Windows 子系统 Linux）**           | ✅ 推荐   | Windows 用户最佳选择，跑原生 Ubuntu                               |
| **虚拟机（VMware / VirtualBox + Ubuntu）** | ✅ 推荐   | 环境隔离干净，适合测试验证                                           |
| **Docker 桌面版（Windows / macOS）**       | ❌ 不推荐  | 资源开销大、嵌套容器易出问题；OSS 部署脚本面向 Linux 原生 Docker，请改用 WSL2 或虚拟机 |

> 统一在 **Ubuntu 24.04 LTS** 下部署。

### 2.2 部署方式

| 方式               | 命令                         | 适用场景                                       |
| ---------------- | -------------------------- | ------------------------------------------ |
| **完整一键部署（主推）**   | `deploy/full-deploy.sh` | 从 CDN 下载**完整业务数据 + 预训练模型 + 镜像包**，开箱即用、生产就绪 |
| **完全手动部署**       | 见第五节                       | 需要自定义目录、端口或渐进式安装                           |
| **AutoDL GPU 训练节点** | `deploy/autodl/setup-autodl-native.sh` | 已有主节点后，把模型训练卸到 AutoDL 显卡实例（见第十一节） |

> **主推完整一键部署脚本**：自带完整的业务数据与模型（PostgreSQL 业务数据备份、Qlib 回测数据、预训练模型与 QwenPaw 持久化数据），从 CDN 下载校验后一次性恢复，部署完即可登录体验，无需另行准备数据。手动部署完成后需按下方「数据准备」补充 QuantDB 数据（或使用网盘离线包）。两种方式最终都通过 `docker compose` 管理服务，可互相切换升级。

## 三、数据准备（QuantDB 在线同步 / ModelScope 离线包）

> 「完整一键部署」已内含基础业务数据，可跳过本节；手动部署或需要补齐历史数据时按本节准备。

系统正常运行需基础量化数据，二选一：


* **ModelScope 离线数据包**：<https://www.modelscope.cn/datasets/qusong0627/LightGBM_Alpha300> ，内含 **QuantDB 数据**；部署完成后请到【管理后台】→【数据管理】点击【初始化数据】拉取，或手动解压到 `/opt/quantmind/data/quantdb`（宿主机路径，容器内映射为 `/data/quantdb`）。

## 四、完整一键部署（主推：从 CDN 下载完整后端 + 基础业务数据）

适合新服务器首次部署：从 CDN 拉取约 5GB 的镜像 + 业务数据 + 数据库备份完整包，下载校验后一次性恢复，部署完即可登录体验，无需另行准备数据。

```bash
curl -fsSL https://gitee.com/qusong0627/QuantMind/raw/master/deploy/full-deploy.sh | sudo bash
```

### 可配置环境变量

| 变量                               | 默认值                                    | 说明                       |
| -------------------------------- | -------------------------------------- | ------------------------ |
| `QUANTMIND_OFFLINE_BASE_URL`     | `https://www.quantmindai.cn/downloads` | 完整部署包 CDN 地址               |
| `QUANTMIND_MANIFEST_SHA256`      | 空                                      | SHA256SUMS 清单校验值（安全加固可选） |
| `QUANTMIND_DOCKER_MIRROR`        | 内置加速地址                                 | Docker Hub 镜像加速          |
| `QUANTMIND_PROJECT_DIR`          | `/opt/quantmind`                       | 部署目录                     |
| `QUANTMIND_REF`                  | `master`                               | 代码分支/tag                 |
| `QUANTMIND_REPLACE_QLIB`         | `false`                                | 覆盖已有 Qlib 数据（谨慎）         |
| `QUANTMIND_REPLACE_DATABASE`     | `false`                                | 覆盖已有 PostgreSQL 业务数据（谨慎） |
| `QUANTMIND_REPLACE_QWENPAW_DATA` | `false`                                | 覆盖 QwenPaw 持久化卷（谨慎）      |
| `QUANTMIND_SKIP_ANALYSIS_TOOLS`  | `false`                                | 跳过 parquet 分析工具安装        |

示例（自定义 CDN + 校验清单）：

```bash
QUANTMIND_OFFLINE_BASE_URL=https://your-cdn.example.com/downloads \
QUANTMIND_MANIFEST_SHA256=<sha256> \
sudo -E bash deploy/full-deploy.sh
```

### 国内网络加速（构建前可覆盖）

* **Docker 镜像加速**：脚本自动写入 `/etc/docker/daemon.json`（默认 `https://vmx3wfa8ih592aat3z.xuanyuan.run`），可用 `QUANTMIND_DOCKER_MIRROR` 覆盖；
* **pip 源**：构建 `quantmind` 镜像默认使用清华源，可用 `QUANTMIND_PIP_MIRROR` / `QUANTMIND_PIP_TRUSTED_HOST` 覆盖；
* **apt 源**：镜像内部 `apt` 默认使用阿里源（`mirrors.aliyun.com`）。

### 脚本执行内容（8 步）

1. 安装系统依赖与 Docker / Compose，配置镜像加速；
2. 从 CDN 下载离线包并做 SHA-256 全量校验（已下载且校验通过的包自动复用，支持断点重跑）；
3. 导入 Docker 镜像（含 `quantmind-oss`、`quantmind-data-gateway`、`quantmind-dashboard`、`agentscope/qwenpaw` 等 9 个镜像；`rsshub` 因历史镜像损坏已从包内剔除，部署时在线拉取）；
4. 拉取最新代码（支持 Compose/Dockerfile 受控覆盖层）；
5. 恢复业务数据、模型与 Qlib 数据（含 FinBERT 中文金融情绪模型）；
6. 恢复 PostgreSQL 业务数据（已有数据默认保留）；
7. 恢复 QwenPaw 四个持久化卷（data / secrets / backups / shared）；
8. 构建启动全部服务，并**自动配置 QwenPaw 运行时**：在 QwenPaw venv 中安装 `reportlab`（清华/阿里镜像源三级回退），并将宿主机 `docker` CLI 复制进 QwenPaw 容器使 QuantBot 可 `docker exec quantmind` 执行取数脚本。

> 已有数据默认保留：Qlib 数据、PostgreSQL、QwenPaw 卷均做存在性检测，重复执行安全。
>
> 部署完成后建议按 **第十节「部署后依赖检查」** 快速确认 PyTorch 是否随镜像就绪（RSS 情绪识别依赖），详见《[RSS情绪识别FinBERT依赖安装说明](RSS情绪识别FinBERT依赖安装说明.md)》。

## 五、完全手动部署

### 1. 安装 Docker 与 Compose

```bash
sudo apt-get update -y
sudo apt-get install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker
docker compose version   # 验证
```

### 2. 克隆代码

```bash
git clone --depth 1 https://gitee.com/qusong0627/QuantMind.git /opt/quantmind
cd /opt/quantmind
```

### 3. 编写 `.env`

```bash
sudo tee /opt/quantmind/.env <<EOF
DB_HOST=db
DB_PORT=5432
DB_NAME=quantmind
DB_USER=quantmind
DB_PASSWORD=$(openssl rand -hex 24)
REDIS_HOST=redis
REDIS_PORT=6379
SECRET_KEY=$(openssl rand -hex 32)
JWT_SECRET_KEY=$(openssl rand -hex 32)
STORAGE_MODE=local
EOF
chmod 600 /opt/quantmind/.env
```

> `STORAGE_MODE=local` 为 OSS 版必需。其余变量（如端口覆盖 `QWENPAW_PORT`、`DASHBOARD_PORT`）见 `docker-compose.yml` 注释。

### 4. 构建并启动

```bash
cd /opt/quantmind
docker compose build quantmind        # 仅含 Python 依赖的镜像，通常一次构建
docker compose up -d                  # 启动全部服务
docker compose ps                     # 查看状态
```

可选扩展服务按需启动：

```bash
docker compose up -d qwenpaw          # QuantBot AI 助手
docker compose up -d ib-gateway       # IB Gateway（.env 配置 IB_ACCOUNT/IB_PASSWORD）
```

### 5. 健康检查

```bash
curl -f http://127.0.0.1:8000/health
curl -f http://127.0.0.1:8001/health  # Engine
curl -f http://127.0.0.1:8002/health  # Trade
```

### 6. 数据准备

与第三节「数据准备」相同（QuantDB API Key 在线同步或网盘离线包）。

## 六、更新与日常运维

### 一键更新

```bash
sudo bash deploy/update.sh                # 拉取最新代码并重建（不清除数据库与模型资产）
sudo bash deploy/update.sh --no-build     # 纯代码改动，跳过镜像重建
sudo bash deploy/update.sh --force        # 覆盖服务器未提交改动
```

更新流程为 5 步：同步代码 → 重建核心镜像 → 重启服务 → **数据库结构自检** → 健康检查。

数据库结构以 `backend/shared/db_init.sql` 为唯一入口，服务启动时幂等重放：新库直接按第 1~65 节建全，存量库由第 66 节（已合并原 `data/upgrade_v1.0.1 ~ v1.0.8`）补齐缺失列 / 约束并做数据订正。`data/upgrade_*.sql` 仅用于后续新增补丁，需保持幂等（重复执行无副作用），加新版本补丁时直接新增 `data/upgrade_vX.Y.Z.sql`，脚本会自动扫描执行。

### 手动更新（镜像 build 判断规则）

```bash
cd /opt/quantmind && git pull
# 纯代码改动（未新增 pip 依赖）：重启即可
docker compose restart quantmind quantmind-celery quantmind-celery-beat
# 新增了 requirements.txt 未收录的依赖 / 升级底层库：需要重建镜像
docker compose build quantmind && docker compose up -d
```

### 常用命令

```bash
docker compose ps                      # 服务状态
docker compose logs -f quantmind       # 主服务日志（api/engine/trade/stream 同容器）
docker compose logs -f qwenpaw         # QuantBot 日志
docker compose restart quantmind       # 重启主服务
docker compose down                    # 停止全部服务（保留数据）
docker compose down -v                 # ⚠️ 停止并删除数据卷（含 PostgreSQL 数据，谨慎）
```

## 七、QuantBot (QwenPaw) 初始化

QwenPaw 是基于阿里 QwenPaw 的量化 AI 助手（控制台 `http://<服务器 IP>:8088`）。服务启动后，把 QuantMind 技能与人格注入工作区：

```bash
cd /opt/quantmind
bash scripts/quantbot_init.sh                  # 全量：技能 + 人格
bash scripts/quantbot_init.sh --skills-only    # 只装技能（需宿主机有 zip 命令）
bash scripts/quantbot_init.sh --persona-only   # 只写人格（无需 zip）
docker restart qwenpaw                         # 使人格文件生效
```

* 技能源为仓库 `skills/` 目录（动态枚举含 `SKILL.md` 的子目录），脚本自动完成「删旧 → 上传技能池 → 广播到工作区」；

* 人格三件套来自 `config/qwenpaw/`（AGENTS.md 工作区规则 / SOUL.md 人格 / PROFILE.md 用户档案）；

* 完整说明与手工操作步骤见 [QuantBot 初始化指南](quantbot初始化指南.md)。

## 十、部署后依赖检查（RSS 情绪识别 / 模型推理）

部署完成后，建议确认关键运行依赖（PyTorch）是否随镜像就绪，否则新闻情绪识别会自动降级为词典法、部分模型推理不可用。

* **一键部署**：初始部署强制 CPU 版——`deploy/full-deploy.sh` 会在 `.env` 写入 `TORCH_DEVICE=cpu`（`docker-compose.yml` 的默认值也是 `cpu`），构建时安装 CPU 版 PyTorch，镜像小、构建快、无 GPU 依赖，通常无需额外操作。镜像内实际形态记录在 `/etc/quantmind/torch-device`。需要 GPU 时见下方 `deploy/enable-gpu.sh`。

* **离线部署 / 镜像异常 / GPU 机器**：推荐统一用模型依赖补齐脚本 `deploy/install-model-deps.sh` 按需安装 PyTorch（持久方案，重建镜像，重启不丢）；GPU 场景更推荐一键扩展脚本 `deploy/enable-gpu.sh`（含 GPU 直通与校验，可 `--cpu` 回退）：

```bash
# 在 /opt/quantmind 下执行
sudo bash deploy/install-model-deps.sh           # 安装 torch CPU 版（FinBERT 情感 / 多数推理，构建快）
sudo bash deploy/install-model-deps.sh --gpu     # 安装 CUDA 版 torch + 构建本地训练镜像，模型训练用上 GPU
sudo bash deploy/install-model-deps.sh --refine  # 只重建镜像，不自动重启服务

# GPU 一键扩展（推荐）：前置检查 → 写 .env TORCH_DEVICE=gpu → 开 compose GPU 直通 → 重建 → 校验
sudo bash deploy/enable-gpu.sh
sudo bash deploy/enable-gpu.sh --cpu             # 回退 CPU 版
```

> `--gpu` 需宿主机已装 NVIDIA 驱动 + nvidia-container-toolkit，并放开 `docker-compose.yml` 中 `quantmind` 服务的 GPU 直通（`deploy.resources.reservations.devices`，默认注释）。装完会用 `docker run --gpus all` 探针实测 `torch.cuda.is_available()`，若为 False 会打印排查指引。

* 相关专项文档：《[RSS情绪识别FinBERT依赖安装说明](RSS情绪识别FinBERT依赖安装说明.md)》——补充权重与验证 FinBERT 是否生效（`model_version` 是否带 `+finbert` 后缀）。

快速检查容器内是否已带 PyTorch：

```bash
sudo docker exec quantmind python3 -c "import torch; print(torch.__version__)"
```

能输出版本号即已就绪；报 `ModuleNotFoundError: No module named 'torch'` 则按上述脚本补齐。

## 十一、AutoDL 远程 GPU 训练节点

OSS 主节点（`quantmind` 容器）默认做 **CPU 训练**。家用电脑或无 NVIDIA 的云主机要把训练卸到 GPU 时，**不要把整套 QuantMind 装进 AutoDL**，只把 AutoDL 当训练 Worker：主节点编排、远端跑 `train.py`、产物拉回注册。

> 节点初始化脚本与字段说明另见仓库 [`deploy/autodl/README.md`](../deploy/autodl/README.md)。

### 11.1 架构

```text
Electron 模型训练页  →  主节点 Engine（quantmind 容器）
                         │  SSH + rsync
                         ▼
                   AutoDL Python 实例（有 GPU，通常没有 Docker）
                         │  直读 /root/autodl-fs/quantdb 因子 parquet
                         │  原生 python train.py
                         ▼
                   HTTP 回调 TRAINING_MASTER_HOST:8000
                         │  rsync 拉回 model.lgb / pred.parquet …
                         ▼
                   /data/training_jobs/{run_id}/  →  模型注册中心
```

| 角色 | 在哪 | 职责 |
| --- | --- | --- |
| **协调机 / 主节点** | 已部署 QuantMind 的 Linux 服务器 | 配节点、推送训练脚本与增量因子、拉产物、注册模型 |
| **训练节点** | AutoDL 控制台开通的 GPU 实例 | 装依赖、落 QuantDB parquet、执行训练 |

执行模式：

| `exec_mode` | 适用 | 说明 |
| --- | --- | --- |
| **`native_python`（推荐）** | AutoDL 官方 Python 镜像 | 实例本身是容器，**一般不能再套 Docker**。编排器 SSH 后直接跑 `/root/miniconda3/bin/python /root/workspace/train.py` |
| `ssh_docker` | 自备已装 Docker + nvidia-container-toolkit 的机器 | `docker run` 训练镜像；与多数 AutoDL 租户环境不兼容 |

代码（`train.py`、训练包、backend 直读子树）**不固化进 AutoDL 镜像**，每次开训由主节点 rsync。

### 11.2 开通 AutoDL 实例

1. 控制台选带 GPU 的 **PyTorch / Anaconda** 镜像（如 RTX 4090），系统盘够装 Python 依赖即可。
2. **数据放数据盘**：因子 parquet 必须在 `/root/autodl-fs/quantdb`（重启保留）。系统盘 `/` 关机可能被清空。
3. 记下 SSH：**主机** `connect.<区域>.seetacloud.com`、**端口**（控制台「SSH 指令」里 `-p` 后面的数字）、用户 `root`、密码或密钥。
4. **关机再开机后 SSH 端口经常会变**，必须同步改 `config/training_nodes.yaml` 的 `port`，否则表现为 `Connection refused`。

### 11.3 在 AutoDL 上初始化（免 Docker）

在 AutoDL 本机执行（不要在主节点执行）。

一键下载执行（推荐，无需先 scp）：

```bash
bash -c "$(curl -fsSL https://quantmindai.cn/gitea/qusong0627/QuantMind/raw/branch/master/deploy/autodl/quick-setup.sh)"
```

非交互示例（初始数据从魔搭 ModelScope 拉取，默认 **全量历史**、`l1_factors,l2_factors,l1_l2_factors`，可管道执行；`QUANTDB_API_KEY` 可选，仅编排器日常增量同步需要）：

```bash
AUTO_DL=yes \
  bash -c "$(curl -fsSL https://quantmindai.cn/gitea/qusong0627/QuantMind/raw/branch/master/deploy/autodl/quick-setup.sh)"
```

> 想缩小下载量：`AUTODL_DATASETS=l1_factors`（只 L1）或 `AUTODL_SINCE=2024-01-01`（只拉该日期后的 `dt=` 分区）。

或先上传再执行：

```bash
# 把仓库里的脚本拷上去，例如：
scp -P <端口> deploy/autodl/setup-autodl-native.sh root@connect.xxx.seetacloud.com:/root/
ssh -p <端口> root@connect.xxx.seetacloud.com
bash /root/setup-autodl-native.sh
```

脚本会：检测 Python / GPU；安装 `lightgbm`、`duckdb`、`quantdb-sdk` 等（pandas 钉 2.x）；创建 `/root/workspace` 与 `/root/autodl-fs/quantdb`；（可选）写入 QuantDB API Key；按需从**魔搭 ModelScope** 数据集 <https://www.modelscope.cn/datasets/qusong0627/LightGBM_Alpha300> 拉取训练 parquet（纯 HTTP，不需要 Key，可断点续传）。`QUANTDB_API_KEY` 为可选——仅编排器日常增量同步需要，初始数据不再依赖它；不填也可稍后手动上传 `6_ml_datasets/`。

验证：

```bash
set -a; . /root/workspace/.env; set +a
/root/miniconda3/bin/python -c "import lightgbm, duckdb, quantdb_sdk; print('deps OK')"
nvidia-smi
du -sh /root/autodl-fs/quantdb/6_ml_datasets
```

### 11.4 在主节点注册训练节点

1. 编辑 **`config/training_nodes.yaml`**（已 gitignore，含密码/密钥，禁止提交仓库）：

```yaml
nodes:
  - id: autodl-rtx4090
    name: "AutoDL RTX4090 (免Docker)"
    host: "connect.bjb2.seetacloud.com"   # 以控制台为准
    port: 27045                             # 以控制台 SSH -p 为准，重启会变
    user: "root"
    ssh_password: "<控制台密码>"             # 或 ssh_key: /root/.ssh/id_ed25519
    work_dir: "/root/workspace"
    exec_mode: "native_python"
    gpus: "all"
    quantdb_dir: "/root/autodl-fs/quantdb"
```

也可用桌面客户端 **后台管理 → AutoDL 节点** 写入同一文件。

2. 主节点 `.env` 增加训练回调地址（AutoDL 要能访问到协调机 API）：

```bash
# 协调机公网 IP 或专线地址，不要填 127.0.0.1 / 容器名
TRAINING_MASTER_HOST=x.x.x.x
```

密码登录时，**quantmind 容器内需要 `sshpass`**。改完 yaml / `.env` 后：

```bash
cd /opt/quantmind
docker compose up -d
# 纯 yaml 改动一般重启即可
docker compose restart quantmind
```

3. 连通性：后台「AutoDL 节点」点测试，或：

```bash
# 主节点容器内应能 SSH 到 AutoDL（端口以 yaml 为准）
docker exec quantmind python -c "print('ok')"
```

### 11.5 开训与产物

1. 桌面客户端 **模型训练**：选该 `node_id`（不要误选 `local`，除非本机真有训练镜像）。
2. 日志顺序大致为：同步 backend 子树 → 增量同步 `l1_factors` → 推送 `train.py` → 启动原生进程 → DuckDB 读因子 → 拟合 → 回调 HTTP 200 → 拉取产物 → 模型注册。
3. 成功后：`/data/training_jobs/{run_id}/` 有 `model.lgb` 等；模型中心出现 `mdl_…`，状态 `ready`。

**说明：**

* LightGBM / XGBoost 训练主要吃 **CPU + 内存**，不一定打满 GPU；深度学习任务才会用 CUDA。
* 编排器开训时仍会再跑 QuantDB parquet 增量同步（只同步模型实际的 `factor_source`，默认 `l1_factors`；**初始数据在 11.3 由魔搭 ModelScope 全量拉取 `l1_factors,l2_factors,l1_l2_factors`，日常增量走 QuantDB SDK**，两者独立）。AutoDL 上缺 `backend.scripts` 导致的 L1 OHLCV backfill 警告一般 **不影响直读因子训练**。
* 推理模板会 rsync 到 `{work_dir}/templates/inference_parquet.py`。

### 11.6 排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| SSH `Connection refused` | 实例关机或 **端口已变** | 控制台看新 `-p`，改 yaml `port` 后重启 `quantmind` |
| 节点检测失败 / 灰色开始训练 | 默认 `local` 或节点未 ready | 后台测连通；训练页选 AutoDL 节点 |
| 训练完成但页面停在「拉取产物」 | 前端未吃到完成态 | 刷新结果入库或到模型管理按 `mdl_…` 查找 |
| 回调失败 | `TRAINING_MASTER_HOST` 为空或 AutoDL 访问不到 | 填协调机公网 IP，放行 8000 |
| 因子行数为 0 | 代码口径或数据洞 | parquet / Qlib 层用后缀代码；确认 `quantdb_dir` 与 `6_ml_datasets/l1_factors` |
| 想整机把 QuantMind 装进 AutoDL | 无嵌套 Docker、无 systemd | **不推荐**；仅训练 Worker。若必须原生跑全栈，见技能文档 `skills/quantmind-deploy` 第 8b 节 |

## 十二、常见问题

### Q: Docker 镜像拉取失败？

```bash
# 手动配置镜像加速后重试
sudo tee /etc/docker/daemon.json <<EOF
{ "registry-mirrors": ["https://gpu34ekhgwm14ghgur.xuanyuan.run"] }
EOF
sudo systemctl restart docker
```

### Q: 部署中断了怎么办？

两个部署脚本都是幂等设计：直接重新执行同一命令即可。已下载且校验通过的包会自动复用，不会重复下载；已有业务数据默认保留。

### Q: 服务起不来 / 60 秒健康检查失败？

```bash
docker compose logs --tail 100 quantmind    # 先看主服务日志
docker compose logs --tail 50 db redis     # 常见原因：数据库未就绪、端口被占用
```

### Q: QuantBot 技能无法生成 PDF？

QwenPaw venv 缺 `reportlab` 或无 docker CLI（完整一键部署脚本已自动配置）。若仍缺失，手动修复：

```bash
docker exec qwenpaw /app/venv/bin/pip install -i https://pypi.tuna.tsinghua.edu.cn/simple reportlab
docker cp /usr/bin/docker qwenpaw:/usr/local/bin/docker && docker exec qwenpaw chmod +x /usr/local/bin/docker
```

### Q: 如何完全重置部署？

```bash
docker compose down -v                     # ⚠️ 删除数据卷（含所有业务数据）
sudo rm -rf /opt/quantmind                 # 或仅删除代码目录后重新部署
```
