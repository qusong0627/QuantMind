# 设计复盘与优化报告（对统一交易栈全套文档的评审）

> 版本：v1（2026-09-15）　对象：`docs/统一交易栈_设计方案.md` 及其配套 9 份文档
> 方法：从七个视角评审——消费者产品 / 可维护性 / 机构专业度 / 事故反推 / 成本规模化 / 合规 / 演进性。
> 产出：3 个结构性风险的判定 + 改进清单（每条落到具体文档）+ 修订后的路线图。

---

## 一、总体评价

**做对了的**：契约化（四契约）、粒度对齐、风控分层 fail-closed、共享"单一实现"纪律、用真实事故（12 个诊断 bug）反推设计。这套骨架是机构级的。

**三个结构性风险**（按严重度）：

| # | 风险 | 本质 | 触发条件 |
|---|---|---|---|
| 1 | **消费者规模化假设未验证** | 全套设计默认"一个专业账户"，实际是**数千普通用户 × 个性化策略**；计算/存储/LLM 的成本模型缺失，共享层与用户层的边界未定义 | 用户数上规模时成本爆炸 / 体验劣化 |
| 2 | **可维护性"有制度无抓手"** | 写了"单一契约""禁止 if market=="，但缺少让 AI/人**快速定位**的基础设施；这次诊断读 100+ 文件才定位一个 bug，就是"改 bug 烧 token"的根因 | 每次排障/改动都重复全库摸索 |
| 3 | **静默失效仍是头号威胁** | 12 个诊断 bug 中 8 个是静默类（全 HOLD 一个月、曲线读空账户、台账全空、死配置）；现有设计的告警是"点"，缺少系统性"体检" | 下一个"一个月没人发现"的事故 |

## 二、逐视角评审与改进

### 视角 1：消费者产品（新增维度，缺口最大）

| 问题 | 改进 | 落在哪 |
|---|---|---|
| 机构术语直暴露（rank/IC/滑点/回撤） | **呈现翻译层**：机构指标 → 消费者语言（rank→"当前热度"、IC→"历史胜率"、滑点→"实际成交与预期的差距"）；简单/专业双模式 | 产品化文档 |
| 每用户独立计算不可行 | **共享层/用户层分离**（架构级，见 §三） | 主文档铁律七 |
| 合规空缺 | 适当性 + 风险揭示 + 收益展示规范 + 模拟先行教育 + 全量留痕 | 产品化文档 §合规 |
| 消费者默认参数激进 | **默认安全**：默认保守（止损/分散/仓位上限），危险操作二次确认 | 产品化文档 |
| LLM 成本不可控（消费者规模） | 分层模型 + 缓存 + 用户级限流 + 每任务预算 | 产品化文档 + LLM 文档 |

### 视角 2：可维护性（AI 协作成本）

问题实测：这次诊断从"模拟盘不对劲"到定位根因，读了 100+ 文件。目标——**同类问题定位成本降一个数量级**。

| 改进 | 说明 |
|---|---|
| **代码地图**（`docs/CODEMAPS/`） | 每模块一页：职责/入口文件/契约/依赖/常见故障；AI 会话先读地图再定位 |
| **Runbook**（故障→命令手册） | "模拟盘不对"→ 一条命令出诊断报告；覆盖历史 top-20 故障 |
| **一键体检脚本** `scripts/diagnose/` | 把这次手工排查（信号分布/双账户键/台账空/曲线同源）全部脚本化 |
| **错误自定位** | 关键错误携带 契约ID/规则ID/run_id/文件位置——日志直接指路 |
| **回归资产化** | 12 个已知 bug 每个一个回归测试；每修一个新 bug 就沉淀一个测试 |
| **ADR 决策记录** | 本套设计的关键取舍落盘（AI 会话不用重新推导"为什么这样"） |
| **契约单测即护栏** | 四契约各有契约测试，改代码时测试替 AI"记住"行为 |

### 视角 3：机构专业度（对标补充）

Gap 表（机构级文档 §二）已覆盖 12 项，评审补充三个"机构有但我们漏了"：

| 补充项 | 说明 | 优先级 |
|---|---|---|
| **容量与拥挤度监控** | 不只估自己的容量，还监控"同策略资金拥挤度"（信号拥挤→收益衰减预警） | P4 |
| **通道单点与冗余** | QMT 桥是单点（宕机=无法交易）；设计降级路径（备用通道/纯手动预案）与心跳 | P2 |
| **压力测试/情景分析** | 组合在"大盘 -10% / 流动性枯竭 / 涨跌停潮"情景下的损失预估（月度跑） | P4 |

### 视角 4：事故反推——静默失效防治体系（专项）

12 个 bug 分类：静默失效 8 / 口径分裂 3 / 安全 2（有重叠）。防治体系四件套：

1. **fail-loud 清单**：关键路径（信号生成、下单、落账、快照、调度）异常必须告警，不许 debug/静默跳过（已有 signal_side WARNING 先例，推广成制度）
2. **每日系统体检断言集**（交易台"系统健康"卡片）：信号分布正常？账户/曲线同源一致？台账有写入？任务心跳齐？配置生效？——任一项不合格=红色告警
3. **一致性对账扩展**：Redis↔PG↔券商、模拟↔影子、曲线↔快照→订单，数字对不上自动报告
4. **配置生效检查**：任何参数保存后自动回读验证"真的生效了"（对治 min_score/execution_config 类死配置）

### 视角 5：成本与规模化

**计算分层（消费者规模的关键）**：

```
第 1 层 全市场批量（1 次/日，系统级）      —— 所有用户共享
第 2 层 盘中热集实时（1 份，系统级共享）    —— 所有用户共享
第 3 层 用户级（仅"参数应用 + 账户 + 通知"）—— 每用户轻量
```

原则：**越贵的计算越往上收（共享），越个性化的越往下放（轻量）**。用户策略 = 参数包（topk/universe/风控），不触发独立推理。
成本目标：共享层成本与用户数**脱钩**；单用户日边际成本 = 分摊(共享) + 通知/存储 ≈ 忽略级。

### 视角 6：合规（面向消费者的硬约束）

| 项 | 要求 |
|---|---|
| 资质边界 | 不构成投资顾问：展示"策略工具/研究结果"定位，不承诺收益、不代客理财 |
| 收益展示 | 历史收益展示规范（含"过往不代表未来"、样本区间/口径披露、禁止暗示确定性） |
| 适当性 | 风险等级问卷/风险揭示确认；高风险功能（实盘、杠杆类）门槛 |
| **数据合规** | **L2 数据的转售/二次分发授权必须在采购时确认**（消费者产品里 L2 不能外露原始数据） |
| 留痕 | 用户看到的每个信号/建议留痕（合规审计 + 纠纷举证） |

### 视角 7：演进性（未来 2-3 年变化点压力测试）

| 变化 | 被哪个设计吸收 | 结论 |
|---|---|---|
| tick/L2 接入 | 执行内核 SPI + L0.5 + 粒度对齐 | ✅ 已预留 |
| LLM/Agent 深化 | 六铁律 + 信号化评估 | ✅ 已预留 |
| 多券商/多市场 | Adapter SPI + Order 契约 | ✅ 已预留 |
| 用户量 10x | **共享/用户分层（本次新增）** | ️ 本次补上 |
| 监管变化 | 合规设计（本次新增） | ️ 本次补上 |

## 三、架构级改进（新增铁律七）

> **铁律七：共享计算、用户轻量**——面向消费者规模：全市场信号计算、盘中热集推理、行情扫描均为**系统级共享计算**（成本与用户数脱钩）；用户层只承载"策略参数应用 + 账户 + 通知"，禁止用户触发独立的全市场重算。

同时修订：**Signal 契约**明确"系统级共享信号 + 用户级策略参数"的双层模型；**评估体系**增加"系统共享层的容量/成本指标"。
