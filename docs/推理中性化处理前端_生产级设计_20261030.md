# 推理中性化处理前端（Neutralization Layer）· 生产级设计

- 文档版本：v1.0（2026-10-30）
- 状态：设计稿，待评审后进入实施
- 适用范围：A 股（CN）；架构预留 HK/US 扩展位
- 关联结论：CAT2016 T+3 在 434 天 test 上，原始多空日均 0.435%、Sharpe 2.82、最大回撤 -77.0%；分数级中性化（市值+beta）后 0.430%、Sharpe 4.94、回撤 -24.3%；再加 20 日动量后 Sharpe 5.66、回撤 -14.7%。

---

## 0. 决策摘要

1. 在推理链路新增一层**分数级中性化处理前端（NL）**：模型输出 → 截面回归取残差 → 中性化分数。**不改模型、不改特征、不重训**。
2. 覆盖**两处推理**：
   - **批量推理**（收盘后，全市场/指定池）：每次批量 run 完成后自动生成 NL 结果；
   - **推理中心/模型管理触发的一键推理**（含单日批量）：同一入口内可选择是否启用 NL。
3. 覆盖**两个前端入口**：
   - 推理中心：「模型治理」工作区新增中性化面板；「截面选股」工作区增加排序口径切换；
   - 模型管理：模型详情新增「中性化」Tab；「一键推理」对话框显示/选择 NL 模式。
4. 默认运行模式 **shadow（影子）**：中性化分数写入独立影子表，不改变现有排序、信号侧、下单链路；观察满 4 周、指标达标并经批准后才能切 enforce。
5. 控制变量提供**可选库**（默认仍只启用三项：log 流通市值、60 日 beta、20 日动量）。库内共 11 个：规模（流通市值/总市值）、风险（20/60 日 beta、20 日波动率、特质波动率）、动量（20/60 日）、流动性（20 日换手）、估值（PB/EP）。**行业中性化暂不上线**——当前行业映射是快照（`instrument_detail.rs_hyname`），没有 PIT 历史，用于历史回填会引入前视。同族变量高度共线，建议每族最多选 1 个。
6. 生产级硬约束：口径版本化、幂等重算、显式降级、失败不静默、全链审计、可一键回滚。

## 1. 背景与问题

### 1.1 现象

树模型分数带有明显的风格暴露（小市值、高 beta、短期反转）。以 CAT2016 为例：

| 口径 | rank IC | 多空日均 | Sharpe | 最大回撤 |
|---|---|---|---|---|
| 原始（434 天 test） | 0.0946 | 0.435% | 2.82 | -77.0% |
| 中性化（mv+beta） | 0.0887 | 0.430% | 4.94 | -24.3% |
| 中性化（mv+beta+mom20） | 0.0803 | 0.428% | 5.66 | -14.7% |

结论：被剥掉的 IC 主要是风格暴露，不是选股 alpha；剥掉后收益不变、回撤砍到 1/3。

### 1.2 现有组件为什么不能直接用

`backend/services/engine/inference/neutralizer.py` 已存在，但：

- 是**特征级**中性化（对模型输入做残差），要求训练时同口径，否则推理分布漂移；
- 依赖 `db/official_factors.duckdb`（CSMAR 口径），当前部署不存在，真触发直接抛错；
- 只覆盖 `InferenceService.predict` 单点，不覆盖批量推理、不落库、无诊断、无模式开关。

因此本设计另起一条**分数级**链路，既有组件保留不动，作为 Phase 3 的备选。

## 2. 目标 / 非目标

### 2.1 目标

- 对任意已注册模型的推理输出，生成可追溯、可复现的中性化分数。
- 保持原始分数完全不变（双写），消费方按需选择。
- 按模型、按市场、按日期精确控制：off / shadow / enforce。
- 每个结果带口径版本、控制变量快照、回归诊断，可审计、可重算。
- 批量推理与实时推理口径一致（同一套纯函数、同一配置版本）。

### 2.2 非目标

- 不替代模型训练；不做特征级中性化（Phase 3 另立项目）。
- 不直接修改下单、风控、决策轮逻辑；enforce 仅改变“信号读取层看到哪个分数”。
- 不做行业中性化（缺 PIT 行业数据，见 §13 未决项）。
- 不承诺收益；NL 只改变风险结构。

## 3. 口径定义（唯一真源）

### 3.1 术语

| 术语 | 定义 |
|---|---|
| 数据日 T | 生成信号所用特征的交易日（`qm_model_inference_runs.data_trade_date`） |
| 信号生效日 | `engine_signal_scores.trade_date`（现约定为 T+1，沿用现有语义） |
| 宇宙 U(T) | 该模型该日的可交易股票集合，与训练/回测宇宙一致（排除 ST、停牌、上市 <60 日；是否排除涨跌停由 universe_id 决定） |
| 控制变量 | 默认 log 流通市值、60 日 beta、20 日动量；可选库见下 |
| 中性化分数 | 分数对控制变量截面回归后的残差，再转百分位 |

#### 控制变量库（2026-10-30 扩展）

| 逻辑名 | 物理列 | 变换 | 分组 |
|---|---|---|---|
| `log_mv` | `fun_float_mv` | log | 规模（默认） |
| `log_total_mv` | `fun_total_mv` | log | 规模 |
| `beta20` | `style_beta_20` | raw | 风险 |
| `beta60` | `style_beta_60` | raw | 风险（默认） |
| `vol20` | `vol_std_20` | raw | 风险 |
| `idio_vol20` | `style_idio_vol_20` | raw | 风险 |
| `mom20` | `mom_ret_20d` | raw | 动量（默认） |
| `mom60` | `mom_ret_60d` | raw | 动量 |
| `turn20` | `turn_20` | raw | 流动性 |
| `pb` | `fun_pb` | raw | 估值 |
| `ep` | `fun_ep` | raw | 估值 |

- 默认配置仍为 `log_mv + beta60 + mom20`（已验证口径，历史影子结果不受影响）；
- 同族变量（流通市值×总市值、beta20×beta60）高度共线，同时勾选会推高设计矩阵条件数，服务层会判 `degraded`；
- 分区缺列时该变量填 NaN，按覆盖率降级，不会让整批计算失败。

### 3.2 时间口径（防前视）

- 批量（收盘后）：控制变量取 **T 日收盘**数据，来自 `6_ml_datasets/l1_factors/dt=YYYYMMDD/data.parquet`；
- 实时（盘中）：控制变量取 **T-1 日收盘**，结果行必须写 `control_lag=1`；
- 硬校验：`max(control_date) <= signal_data_date`，违反即拒绝写入并告警；
- 禁止用未来日期分区、禁止用当日尚未落盘的数据。

### 3.3 算法

对每个交易日 t、每个模型 m：

```
r_i      = rank_pct(score_i)            # 0~1，平均秩处理并列
X_i      = [1, rank_pct(log_mv_i), rank_pct(beta60_i), rank_pct(mom20_i)]
β        = lstsq(X, r)                   # 最小二乘，float64
resid_i  = r_i − X_i·β
neutral_i= rank_pct(resid_i)             # 输出百分位，便于跨模型组合
```

- 缺失控制变量的股票：从回归样本剔除，`neutral_score=NULL`，`flag=missing_controls`；**不得**用原始分数冒充中性化分数；
- 截面样本数 `< min_n`（默认 300）或设计矩阵条件数 `>1e6`：当日整体降级（见 §7）；
- 控制变量按分位截尾（1%/99%）后再取秩，防止极端值主导；
- 行业哑变量：Phase 2 才启用，启用时用 `drop_first`，并要求 PIT 行业源。

### 3.4 诊断量（每个 模型×日期 一条）

- `n_symbols`、`coverage`（有中性分数的比例）
- `r2`（对控制变量的解释度）
- `betas`（截距、mv、beta、mom）
- `condition_number`
- 事后暴露：`corr(neutral, control)`，每个控制变量必须 `|ρ| < 0.05`，否则标 `exposure_residual`
- `status`：`ok | degraded | failed`

### 3.5 版本号

`config_version = sha256(canonical_json({controls, universe_id, min_n, winsor, transform, timing}))[:16]`
每个结果行都带 `config_version`，保证“同输入 + 同版本 = 同输出”。

### 4.2 执行顺序（批量）

1. 推理 run 完成、原始分数与 `qm_model_inference_runs` 落库；
2. 触发 NL（同步在 run 收尾步骤内，失败不回滚推理 run）；
3. 载入该模型该日宇宙 + 控制变量；
4. 纯函数计算；
5. 写 `qm_neutral_runs` + `qm_neutral_scores`（幂等 upsert）；
6. 诊断入库；异常走 §7 降级。

### 4.3 执行顺序（实时）

- `signal-ready` 写入原始分数后，异步任务执行 NL；
- 若当日已有全市场批量 NL 结果，实时消费直接 join 当日批量结果（推荐）；
- 只有热集分数时可算，但写 `universe_scope=hot_set`，且 **enforce 模式拒绝使用 hot_set 结果**（横截面样本偏差），只能 shadow。

### 5.2 视图（消费方唯一读口）

```sql
CREATE VIEW v_engine_signal_neutral AS

  ON n.tenant_id=s.tenant_id AND n.user_id=s.user_id
```

## 6. 算法规格与实现细节

- **数值**：float64；`numpy.linalg.lstsq(rcond=None)`；不使用随机数。
- **并列秩**：平均秩（与 `batch_aggregator._rankdata` 同实现，避免两套口径）。
- **截尾**：控制变量 1%/99% winsorize 后再取秩；原始分数不截尾（只取秩）。
- **样本筛选**：只保留宇宙内、控制变量非空、原始分数非空的标的。
- **输出**：`neutral_score` 为残差的百分位（0~1）；同时保留残差原始值到 `betas` 诊断之外的列（可选 `neutral_raw`）。
- **幂等**：`INSERT ... ON CONFLICT (tenant,user,model,trade_date,symbol,config_version) DO UPDATE`。
- **重算**：同配置重复计算必须逐行一致（金样测试 ±1e-9）。
- **性能**：5000×4 设计矩阵，每日 <10ms；1200 个交易日全量回填 <1 分钟（不含 IO）。

## 7. 运行模式与降级策略

| 模式 | 写影子表 | 消费方可见 | 允许下单链路读取 |
|---|---|---|---|
| off | 否 | 否 | 否 |
| shadow | 是 | 是（带“影子”徽标） | 否 |
| enforce | 是 | 是 | 是（需显式接入） |

### 7.1 降级判定（任何一条触发即 `degraded`）

- 覆盖 `coverage < 0.95`
- `n_symbols < min_n`
- `condition_number > 1e6`
- 事后暴露 `|ρ| > 0.05`
- 控制变量快照日期 > 数据日（前视）
- 写入异常/事务失败

### 7.2 降级行为（不静默）

- `shadow`：保留 `degraded` 状态，消费方显示“降级：原因”，**不得**把原始分数当 `neutral_score`；
- `enforce`：该日不产出 `neutral_score`；若消费方是下单链路，**拒绝使用中性化分数**并以明确错误返回（fail-closed），原始分数链路不受影响；
- 连续 2 个交易日 `degraded` 触发告警（QQ/日志/看板）；连续 5 日自动降回 `shadow` 并留审计。

## 9. 前端设计

### 9.1 推理中心 —— 「模型治理」工作区

新增「中性化」面板（与「推理覆盖」「滚动训练」并列）：

- 模型列表：模式、覆盖率、最近一次状态（ok/degraded）、R²、事后暴露；
- 点开某模型：近 60 日诊断折线（R²、coverage）、原始 vs 中性化 IC 对照、降级原因列表；
- 顶部开关：off / shadow / enforce（enforce 需管理员确认）；
- 一键「重算当日」与「回填区间」（管理员）。

### 9.2 推理中心 —— 「截面选股」工作区

- 排序口径切换：`原始分数 | 中性化分数`（默认原始，影子期默认并列展示）；
- 表格新增列：中性化分位（带“影子”角标）、暴露标签；
- 导出名单时记录使用的口径与 `config_version`，保证可对账。

### 9.3 模型管理 —— 模型详情

新增「中性化」Tab（与元数据/指标/归因/漂移并列）：

- 当前配置（模式、控制变量、宇宙、control_lag、config_version）；
- 效果预览：区间 IC/多空曲线/回撤对照（原始 vs 中性化）；
- 历史记录：每次模式变更、重算、降级；
- 「一键推理」对话框内显示本模型 NL 模式，避免“以为跑了中性化实际没跑”。

### 9.4 批量推理面板

`BatchInferencePanel` 增加：

- 运行前：显示 NL 模式（只读，来自模型配置）；
- 运行后：每批显示 `neutral_status`（ok/degraded/skipped）与覆盖率；
- 失败的 NL 不阻断批量推理本身，但必须显式标红。

## 10. 可观测性与审计

### 10.1 指标

- `neutral_coverage`（每日/每模型）、`neutral_r2`、`exposure_residual_max`
- `neutral_latency_ms`（批量/实时）
- `neutral_degraded_days`（连续）
- 效果指标（按日/周）：原始 vs 中性化的 IC、多空日均、Sharpe、回撤

### 10.2 告警

- 覆盖率 <95% 或降级连续 2 日；
- 事后暴露 |ρ|>0.05；
- 中性化写库失败；
- enforce 模型当日出错（最高优先级）。

### 10.3 审计

- 每次配置变更、重算、回填、模式切换写 `qm_neutralization_audit`；
- 结果行带 `config_version` + `neutral_run_id`，可反查到原始分数与数据快照。

## 13. 测试与验收

### 13.1 测试

- **单元**：秩变换、回归残差、缺失处理、降级判定（≥80% 覆盖）；
- **属性**：尺度不变性（分数整体乘常数后中性化排序不变）、幂等性、可复现性；
- **金样**：固定输入（CAT2016 2026-01~09 全市场）→ 期望残差，误差 ±1e-9；两侧（服务与回填 CLI）共用同一金样；
- **集成**：批量 run → 影子表 → 视图 → 截面选股接口；
- **故障注入**：控制变量缺失、分区缺失、DB 写失败、条件数爆炸；
- **E2E**：模型管理开启 shadow → 一键推理 → 推理中心看到诊断与徽标。

### 13.2 预注册验收标准（enforce 前）

以 CAT2016 / 2016 起为基准，2025-2026 test：

- 最大回撤相对原始改善 ≥50%（-77% → ≤ -38%）；
- 多空日均收益不低于原始 −0.02pp/日；
- rank IC 不低于原始 −0.005；
- 覆盖率 ≥95%，降级日占比 <2%；
- 2026 干净窗口：Sharpe ≥4、回撤 ≤ -30%；
- shadow 观察 ≥20 个交易日，决策轮实际使用无异常。

### 13.3 Kill criteria

- enforce 后连续 10 个交易日净收益低于原始口径 0.05pp/日；
- 覆盖率连续 3 日 <90%；
- 任何前视/日期错配；
→ 立即回滚到 shadow/off，并留审计。

## 15. 风险与未决项

1. **行业中性化缺 PIT 数据**：`instrument_detail.rs_hyname` 是当前快照，历史回填会前视。Phase 2 前需确认行业历史源（申万历史成分/变更日期）；在此之前不上行业。
2. **宇宙一致性**：训练/回测/推理的宇宙定义必须一致（ST、停牌、新股、涨跌停）。首次上线前用同一 `universe_id` 做零差异核对。
3. **实时热集横截面偏差**：热集只有几百只，残差依赖样本；enforce 只允许全市场口径。
4. **多模型组合**：中性化分数是百分位，可直接加权；但不同模型的 `config_version` 必须记录，避免混口径。
5. **风格反转期**：中性化会放弃小市值/高 beta 的阶段性收益，需接受“某些月份跑输原始”。
6. **多重检验**：参数（控制变量、winsor、lag）只做一次预注册选择，不做网格挑最优，避免过拟合。
