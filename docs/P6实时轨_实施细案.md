## 一、目标与验收（P6 完成定义）

**一句话**：从「T+1 日频」升级到「盘中快照级闭环」——行情快照 3s 级进入系统，热集（持仓+候选+异动）
增量推理出信号，情报总线统一消费，哨兵把「值得注意的事」推给人，模拟撮合升级到 F2（盘口约束）。

| 验收项 | 判据（可测） | 度量方式 |
|---|---|---|
| 端到端延迟 | 行情到达 → 信号/告警可消费 < 2s（P95，含热集推理） | `intel:latency` 滚动统计 + 交易台面板（T-P6-05/16） |
| 情报告警闭环 | 新闻风险事件/市场 regime/异动 → 总线事件 → 风控 veto 或策略过滤 **真实生效** | 拦截计数（复用 mirror:skipped / risk_lock 审计先例）+ 事件回看（T-P6-12~14） |
| 哨兵误报率 | 告警留痕 → 事后标注（T+1 命中回填 + 人工标注）→ 误报率报表 | 报表页 + 周报口径（T-P6-15，口径见 §六.4） |
| F2 撮合 | 模拟成交价来自快照盘口（含涨跌停排队/深度约束/部分成交） | 成交价偏差分布/成交率/部分成交比例三指标上交易台（T-P6-17/18） |
| 可回放复现 | 实时信号可用留存快照回放复现（同数据/同特征/同模型 → 同信号 diff=0） | 验收器脚本 + 回归用例（T-P6-09） |

**明确不做（P6 边界，防范围蔓延）**：
- tick/逐笔级撮合与队列建模（F3 → P7，依赖 L2 数据落地）
- 执行算法 TWAP/POV（P7）
- 毫秒级策略（诚实边界：快照级策略 = 分钟级可靠、秒级边缘）
- 多市场实时轨（P6 先 A 股；HK/US 沿用日频；行情适配层预留市场参数）

## 二、总体架构（设计文档 §3.2 的落地形态）

```
盘中（快照 3s 级）
行情快照流 ──→ 实时特征（增量） ──→ 热集推理 ──→ 实时信号 ─┐
新闻/RSS 流 ─→ 情绪打分/实体链接 ─→ 事件分级 ──────────────┼→ 盘中情报总线 ─→ ①风控闸门（veto/降仓）
指数/涨跌停/成交额 ─→ 市场状态（regime） ──────────────────┤   （统一事件流）   ②策略（事件驱动/过滤）
量价异动/账户异常 ─→ 识别引擎 ─────────────────────────────┘                 ③哨兵推送 → 副驾驶建议
```

三条纪律（沿用主干设计）：
1. **同契约不同源**：实时信号仍写 Signal 契约（`source=realtime` + 快照精度时间戳），策略无感切换批量/实时。
2. **单实现**：特征定义、撮合规则、风控闸门全部复用既有唯一实现，实时只做「增量调度」不做第二套口径。
3. **可复现**：实时链路任何产出都必须能用留存快照回放复现。
