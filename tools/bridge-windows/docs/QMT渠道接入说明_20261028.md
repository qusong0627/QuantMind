# QMT 渠道接入说明（桥的上游第 4 源）

> 2026-10-28 ｜ 部署机：192.168.31.13 ｜ QMT 账户：<QMT_ACCOUNT>（券商模拟端）
> 原则：**外部所有取数都走 8550 这一座桥**，调用方不直连 QMT、也不直连伴生桥。

## 1. 拓扑

```
quantmind / 任何客户端
        │  HTTP（Bearer token）
        ▼
通达信桥 8550（本机中转站）
        │  source=qmt  →  http://127.0.0.1:17720/api/v1/qmt/call
        ▼
伴生桥 pipe_redis_bridge.py（只读 HTTP 面）
        │  命名管道 \\.\pipe\bigqmt_rpc_<QMT_ACCOUNT>
        ▼
QMT 策略（transport=pipe，零网络、零文件 IO）
        │
        ▼
大 QMT 客户端 XtItClient.exe（行情 / 账户 / 委托 / 成交）
```

- 伴生桥只监听 `127.0.0.1:17720`，**不对外**；对外只有 8550。
- QMT 的下单闸门在策略侧（`allow_order_methods=false`），桥这一层**不提供**任何下单/撤单方法。

## 2. 桥对外接口

所有接口都需要 `Authorization: Bearer <桥 token>`。

| 用途 | 请求 | 说明 |
|---|---|---|
| QMT 健康 | `GET /api/v1/qmt/health` | 伴生桥在线/离线 + 队列/延迟；5s 缓存 |
| 资产口径对账 | `GET /api/v1/qmt/reconcile` | 并列 QMT 总资产/现金/实时市值/占用，解释 `total ≠ cash+mv` 的差额 |
| 账户+持仓 | `POST /api/v1/account/query` `{"source":"qmt"}` | 优先读 3s 快照，附带最新价/市值/浮盈 |
| 当日委托 | `POST /api/v1/orders/query` `{"source":"qmt"}` | 只读 |
| 当日成交 | `POST /api/v1/orders/query` `{"source":"qmt","kind":"trades"}` | 只读 |
| 统一行情 | `GET /api/v1/market/quote?code=600519.SH&prefer=qmt` 或 `&qmt=1` | 与 TDX/THS 同一字段口径 |
| 通用透传 | `POST /api/v1/tdx/call` `{"source":"qmt","method":"...","params":{}}` | 方法白名单见 §3 |

`/api/v1/health` 里也带 `qmt.online`，页面顶栏的 QMT 状态灯读它。

### 账户返回示例

```json
{
  "account_id": "<QMT_ACCOUNT>",
  "asset": {"currency":"CNY","balance":23818980.55,"cash":21626929.45,
            "asset":23818980.55,"market_value":2201080.60,"frozen_cash":0.0},
  "positions": [
    {"stock_code":"600519.SH","stock_name":"贵州茅台","total_volume":100,
     "available_volume":100,"cost_price":1350.0,"last_price":1332.55,
     "market_value":133255.0,"pnl":-1745.0}
  ],
  "channel_used": "qmt", "account_source": "qmt",
  "snapshot_at": "2026-10-28 11:21:46", "age_sec": 2.4
}
```

- `asset` 字段名与 TDX 渠道一致（`balance`/`asset` 都是总资产别名）；
- 没有现价时 `last_price/market_value/pnl` 为 `null`，**不拿成本价冒充现价**；
- 快照未生成时才回落到实时 RPC（`get_asset`+`get_positions`），两者都失败就返回错误，不返回空账户。

## 3. 只读白名单

桥侧 `src/api/qmt_source.py:QMT_READONLY_METHODS`：

```
snapshot, get_market_snapshot, get_full_tick, get_market_data,
get_market_data_ex, get_trading_dates, quote_tap_status,
ping, get_asset, get_positions, account_snapshot,
query_orders, query_trades, get_instrument_detail
```

`order_stock` / `cancel_order_stock` / `passorder` 等一律 **403**（桥与伴生桥双层拒绝）。

## 4. 行情字段映射（QMT tick → 统一字段）

| 统一字段 | QMT 字段 | 备注 |
|---|---|---|
| last | lastPrice | |
| prev_close | lastClose | |
| open/high/low | open/high/low | |
| volume | volume | 手 |
| amount | amount | 元 |
| change_pct | 本地算 | (last-prev)/prev |
| bids/asks | bidPrice/bidVol, askPrice/askVol | 5 档 |
| inside/outside | — | QMT 不提供，保持 null |

默认优先序仍是 `ths > tdx`；QMT 只在 `prefer=qmt` 或 `qmt=1`（补缺）时参与。

## 6. 运维

```powershell
# 启动伴生桥（脱离 SSH，进程挂在 WMI 服务下）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\new_tdx_mock\PYPlugins\bridge-windows\qmt-tools\svc_start_pipe_bridge.ps1

# 看门狗（心跳 + 进程双检，10 分钟冷却）
powershell -NoProfile -ExecutionPolicy Bypass -File C:\new_tdx_mock\PYPlugins\bridge-windows\qmt-tools\pipe_watchdog.ps1

# 日志
C:\new_tdx_mock\PYPlugins\bridge-windows\qmt-tools\logs\pipe_bridge.log
```

排错顺序：
1. `GET /api/v1/qmt/health` 是否 online / degraded；
2. 伴生桥进程在不在（`pipe_redis_bridge`）；
3. `\\.\pipe\bigqmt_rpc_<QMT_ACCOUNT>` 存不存在（QMT 策略是否在跑）；
4. 管道 `ERROR_PIPE_BUSY` → 只能重启整个 QMT 进程（重启策略无效，2026-10-27 实测）。

体检脚本退出码（`bridge_health.py`）：0=正常，1=心跳缺失/过期，2=读不到心跳，
**3=心跳正常但账户快照停摆**（看门狗只记 `DATA_STALE`，不重启）。资产口径疑问看
`GET /api/v1/qmt/reconcile`。

## 7. QuantMind 消费侧（2026-10-28 起）

- 新增 `backend/services/live_trading/services/qmt_bridge_client.py`：
  只调桥 `POST /api/v1/account/query {"source":"qmt"}`，不直连 QMT/伴生桥/Redis RPC。
- `qmt_account_sync_task` 默认 `QMT_ACCOUNT_SOURCE=bridge`（代码默认值），
  启动日志应出现 `source=QmtBridgeClient`；落库 `real_account_snapshots` 的
  `source` 仍是 `qmt_exec`，前端 QMT 页签无需改动。
- 旧路径保留：设 `QMT_ACCOUNT_SOURCE=qmt_exec` 即回退 Redis RPC 直连。
- 守卫：桥若返回 `account_source != "qmt"`（旧桥把 TDX 账户当成功），客户端直接
  抛 `NOT_QMT_SOURCE`，不写库。午休/收盘 QMT 主线程不 tick 时桥返回
  `QMT_SOURCE_ERROR`（管道超时），同步任务只记 warning、不落 0 资产快照。
- **陈旧快照（休市或 RPC 停摆）**：桥在 `bigqmt:positions` 过期时回落到 `position_events` 最后一条，
  返回 `stale: true` + `snapshot_at`；客户端据此**跳过落库**（不把旧数据写成新快照），
  库里的最后一条真实快照保持不动。实时（快照 ≤ `source_http.stale_after_s`=30s）时
  `stale: false`，正常落库——**实时优先，休市才回落**。

## 8. 交易台 token（不用每次手填）

- 网页本身把 token 存在浏览器 `localStorage['tdx-token']`，**同一浏览器 + 同一地址**
  刷新/重开都在；换 `127.0.0.1` ↔ `192.168.31.13`、换浏览器/无痕模式/清站点数据时才丢。
- `启动交易台.cmd` 现已自动打开
  `http://127.0.0.1:8550/ui#token=<config.yaml 里的 token>`：
  fragment 不会发给服务器、不进访问日志，页面加载后立即存 localStorage 并从地址栏抹掉。
- 从别的机器访问（如 Linux 浏览器）：把
  `http://192.168.31.13:8550/ui#token=<token>` 存成书签一次即可；不想用就加
  `-NoUi` 启动参数。
