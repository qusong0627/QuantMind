QuantMind 便携包 - git 自动更新说明(用户版)
====================================================
你的包已经能启动。想以后维护者更新代码时,你自己一键拉取更新?
用本目录里的同步脚本即可,全程自动,不用懂 git。

----------------------------------------------------
一、你会用到什么
----------------------------------------------------
[Windows 用户]  sync_from_git.bat   (双击运行)
[Ubuntu/WSL2]   sync_from_git.sh    (终端执行 ./sync_from_git.sh)

把对应脚本放到便携包根目录 = start.bat / start.sh 所在的那一层。
(以后新版本包里会自带脚本,就不用再放)

※ 2026-09-05 重要:同步范围已升级为「代码 + 前端(web)」。
   **老包用户请用本目录的最新版 sync 脚本覆盖包根旧版一次**——
   旧版同步脚本不带前端,网页界面永远不会随代码更新。
   覆盖后用 Ctrl+Shift+R 强刷浏览器即可看到最新界面。

----------------------------------------------------
二、脚本会自动做的事(按顺序)
----------------------------------------------------
1. 检查 git 有没有装
   - 没装:Windows 自动下载便携版 git 到包内(一次性约45MB);
           Linux 自动尝试 sudo 安装(需免密 sudo)
2. 找代码仓库(克隆)在哪
   - 自动查找:环境变量 QM_REPO_ROOT / 用户主目录 / 包旁边的 quantmind-src
3. 如果还没克隆,会问你是否现在克隆
   - 输入 y 回车 = 自动克隆(推荐;完整克隆约 130MB,只需一次)
   - 输入 n = 跳过,之后可手动克隆(命令见屏幕提示)
4. 自动更新代码:git pull → 停服务 → 备份当前代码 → 同步新代码
   与前端(web)进包 → 清理缓存
5. 提示你重新启动:start.bat / start.sh
   (启动后浏览器 Ctrl+Shift+R 强刷一次,避免旧缓存)

之后维护者每次推送新代码,你重复运行脚本即可,永远自动。
(首次运行若提示重新克隆仓库,属正常——旧版按单分支克隆的
仓库需要换成完整克隆,以后才能自由切换分支。)

----------------------------------------------------
三、仓库放哪(两种都可以)
----------------------------------------------------
A. 让脚本自动克隆(最简单):按第3步输 y,它会克隆到包旁边:
    你的包目录的上一级/quantmind-src
B. 你自己已有克隆: 设环境变量指过去,或把克隆放包旁边同名目录

----------------------------------------------------
四、重要说明(别踩坑)
----------------------------------------------------
- 同步范围 = 代码 + 前端:
    backend(后端) / config / strategy_templates / web(前端产物)
  前端自 2026-09-05 起随 git 同步自动更新,不用再等维护者单独发文件
- 不走 git 的只有:runtime(Python 环境)、models(模型)、data(你的数据)
  这些更新仍需维护者发文件
- 分支默认 next = 维护者的开发主分支,自动跟随
- 如果 clone/pull 提示要账号密码:仓库是私有的,找维护者要访问权限
----------------------------------------------------
五、更新后启动失败?一键恢复(重要)
----------------------------------------------------
同步脚本在覆盖代码前,会自动把「当前能运行的代码」备份到
包内 backups\ 目录(Windows 滚动保留最近 2 份;Linux 保留最近 5 份,
约一两百 MB)。

如果更新后 start.bat / start.sh 启动超时或报错:
1. 双击包根的 restore_backup.bat
   (Linux/WSL 用户:终端执行 ./restore_backup.sh)
2. 等提示 DONE,代码就恢复成同步前能启动的版本
3. 重新运行 start.bat / start.sh

恢复后想再试更新:重新运行 sync 脚本即可,会再次自动备份。
(新版包里自带恢复脚本;老包请把本 updates 目录里的
restore_backup.bat / restore_backup.sh 拷到包根 = start.bat
所在那一层,和 sync 脚本放法一样。)

----------------------------------------------------
遇到任何红字报错:截图发给维护者即可。
